### 已确认的产品承诺

第一版不承诺还原完整思维链，也不宣称“读取用户思想”。产品只根据可回放的真实作答
证据提出一个待确认的策略/错因候选，给出一个下题可执行动作，并通过新题验证是否改善。

推荐对用户表达：

> 岸岸会根据你刚才的真实作答过程，找到本次最值得改的一个动作，并用下一道同类题帮你
> 验证。

### MVP 范围

1. 每次训练只选择一道高价值题或一个主要模式，不逐题调用模型。
2. 优先候选来自错题、蒙对、超时、低信心、频繁改答和主动跳题；这些只是筛选条件，
   不能自动等同于错因。
3. 先显示两至三条确定性动作事实，再显示一个带置信边界的候选判断。
4. 用户可以确认、否定或改写；只有用户明确确认的主要错因可以进入长期错误模式。
5. 输出一个可执行动作，而不是“粗心”“不会”等人格化标签。
6. 立即安排一题独立同类变式；后续继续使用现有首次复测和延时验证。
7. 验证同时观察答题结果与关键动作是否改善；仅再次答对不能单独证明思路已改变。
8. 首批聚焦资料分析、数量关系和判断推理；过程证据弱的题型保持显式证据不足。

### 成本与复杂度边界

- 确定性规则先完成高价值题筛选和事实摘要。
- 原则上按训练会话调用模型，而不是按题调用；每次只处理一个主要问题。
- 最多允许一次高信息量追问；不做持续多轮自由对话。
- 第一版只做答后纠偏，不做实时流式陪练。
- 模考交卷前只静默采集，不生成可能泄露答案的内容。
- 复用现有刷题、复盘、变式、掌握和岸岸入口，不新增 Tab 或新 Agent。
- 本次最小集成没有新增模型调用；可接受的单次成本、日/月预算和降级阈值当前仍为
  `unknown`。在扩题型、放量或发布前，必须用实际模型路由和内测数据标定，不使用行业
  平均值代填。

### 已确认的产品语义

- **标记具有双重作用：**
  1. 作为本次任务中的显式控制状态，表示“这题我不确定/值得稍后检查”，随 checkpoint
     恢复并出现在答题卡或复盘中；
  2. 作为用户主动留下的元认知动作证据，`marked/unmarked` 的时点和上下文进入真实作答
     轨迹，任务结束后仍应按学习证据生命周期保留，用于答后纠偏和理解解题过程。
- 因而“本次标记状态”可以在任务生命周期结束时终止，但“用户何时标记、是否取消、当时
  做过什么”的历史证据不能随界面状态一起丢失。
- **收藏：** 用户长期保存这道题，退出本次训练后仍应保留；它与标记具有独立状态、
  独立反馈和独立持久化语义。
- 两者不得共用一个布尔字段、同一个写接口或只靠同一书签图形让用户自行猜测。
- 跨设备同步已作为“用户长期收藏”的不变量完成合同冻结并实现服务端账号级权威；当前
  尚未执行两台真实设备之间的端到端验证，因此不能据此宣称跨设备体验已经发布验收。

标记是一条有价值的行为证据，但不是用户思维的直接答案。单次标记不能自动等同于“不会”
“粗心”或某个固定错因；只能与改答、排除、信心、用时、草稿/批注、跳题和最终结果共同
形成候选判断，再由用户确认或新题验证。

### 实施前代码事实（historical code_observed，非正式 finding）

- 行测顶栏的“打开当前工具”实际使用 `draft.svg`，入口含义与图形不一致。
- 当前共享材料标题行中的书签图形，ARIA 和事件都表示“标记本题”，并非长期收藏。
- `practice` 目前关闭了 `task-shell` 自带的草稿和标记入口，再由页面材料标题行及工具
  面板承载这些动作，导致全局动作、题目动作和低频工具混在两层。
- 当前运行时已经把 `marked/unmarked` 定义为带时间的作答动作事实；状态 reducer 在每次
  实际变化时写入事件，服务端 checkpoint schema 接受这些事件，Cause Agent 工具也会从
  冻结 checkpoint 读取 action trace。这证明“标记参与揣摩作答过程”已有代码基础，
  但不等于完整链路已经通过端到端验证。
- 实施前没有独立的“题目收藏”领域状态、接口或数据库持久化；后续实现因此先完成了
  独立收藏合同和持久化，再接入 UI，没有把收藏复用为 `marked`。

### 已确认的信息层级

1. **顶部任务栏（全局/会话级）：** 返回、答题卡/进度、计时、岸岸。
2. **共享材料栏（材料级，仅有材料时出现）：** 材料类型、覆盖题号、展开/收起；不承载
   当前题收藏或标记。
3. **题目栏（当前题级）：** 题号/模块、收藏、标记、更多。
4. **更多工具（低频）：** 草稿、题面批注、字号、护眼、题目争议、操作/故障帮助。
5. **无材料页面：** 保持同一顶部任务栏和题目栏，只省略材料栏，不另造一套动作结构。

岸岸从材料标题行移动到顶部任务栏，替代当前含义模糊的工具图标；它必须携带当前题上下文，
但继续遵守“提交前不泄露答案、解析或带答案暗示内容”的既有边界。

### 本轮最小合同冻结

以下选择是主审为避免 UI 先行和重复返工采用的最小风险实施默认，证据类别为
`audit_assumption`，不是对既有生产能力的声明：

1. 收藏只覆盖行测练习；模考和申论只做回归，不开放新的岸岸入口；
2. 收藏是账号级跨设备能力，以 `(user_id, canonical_question_id)` 为成员身份，并保存
   收藏时的 `content_version_id`；
3. 写接口使用 `desiredState`，禁止 toggle；同幂等键同请求精确重放，同键漂移返回
   `409`，重复设置同一状态不增加 revision；
4. MVP 不虚构会员额度或数量上限；
5. 收藏列表只预览和取消，不绕过任务计划直接重做题目；
6. 题目更新时保留收藏来源版本并提示更新；题目下架时保留 tombstone，不返回题干、
   选项或启动入口，但仍可取消；
7. 收藏及命令账本进入账号导出和删除；收藏不进入 Cause Agent；
8. 标记动作证据按账号生命周期保留、可导出，且只允许 Cause Agent 在既有防泄题边界内
   与其他真实作答证据组合使用，不能由单次标记直接生成长期错因。
9. 收藏列表使用账户隔离的实时 keyset 游标，不承诺分页期间并发取消/重新收藏下的跨请求
   强快照；条目可能移动到首屏，刷新必须读取当前服务端权威状态。MVP 不从命令账本重建
   历史分页快照。

后端实现必须先验证收藏来源确属该账号已获得的安全题目版本；前端不得先画一个实际仍写入
`marked` 或仅存本地的伪收藏按钮。

### 已冻结的原 unknowns

1. 找回入口复用“掌握/错题”页面容器的独立“收藏”视图，但不并入四类 mastery 队列；
2. 收藏身份绑定 canonical question，同时保存来源内容版本；
3. 更新、下架、权限变化使用上文的 updated/tombstone 安全语义；
4. MVP 无配额；
5. 服务端 revision 为跨设备权威，离线/未知结果复用原幂等键并重新读取权威状态；
6. 收藏事实和命令账本均纳入账号导出与删除；
7. 标记证据按账号生命周期保留、可导出，只供 Cause Agent 与其他动作证据组合使用。

### 最小验收场景

1. 标记后答题卡能识别“稍后检查”；结束本次训练不会被当成长期收藏，但
   `marked/unmarked` 历史及相对作答时点仍保留在该次真实作答证据中。
2. 收藏、取消收藏均幂等；退出训练、重新进入和重新登录后状态正确。
3. 若冻结为跨设备能力，同一账号在另一设备能得到一致结果，账号之间绝不串数据。
4. 收藏写入失败不得显示成功；响应丢失后重试不得反向切换或产生重复记录。
5. 收藏与标记同时开启、分别取消时互不影响，图标、文字及无障碍标签均可区分。
6. 岸岸入口能获得当前题上下文，但提交前不能返回答案、解析或答案暗示。
7. 有材料和无材料页面保持同一动作层级；共享材料跨多题时，当前题动作不会误附着到材料。
8. 草稿、批注、字号、护眼、争议和帮助仍可从“更多”到达，返回后不丢当前答案与滚动位置。
9. 至少验证 320×568、390×844、363×817、768×1024（平板竖屏）和
   1024×768（平板横屏）；检查微信胶囊、安全区、点击区域、键盘和横竖屏切换。
10. 答后纠偏只能把标记描述为可观察动作，并与其他证据组合形成候选；仅凭标记不得直接
    写入长期错因，用户取消标记也不得物理抹除已经发生过的动作事实。
