## 三、"15 个 degraded 是否正常降级"——分类结论

**共同点**：页面全部渲染出了错误态 UI，无白屏、无卡死、无运行时异常。
"降级渲染"这个行为本身是正常的。但触发原因分三类，性质不同：

### A 类：前后端 API 合同缺口（5 个 404）——**不是正常降级，是真问题**

前端调用了后端不存在的端点：

1. `GET /api/v2/mock-exams/weekly`
2. `GET /api/v2/onboarding/ability-baseline`
3. `GET /api/v2/onboarding/position-preference`
4. `GET /api/v2/onboarding/study-preference`
5. `GET /api/v2/reporting/reports/mock`

待办：逐个判定归属——是前端调错了路径（后端有等价端点），还是后端漏实现。
这些页面在生产上同样会 404（老后端更不可能有），属于发布前必须收敛的合同问题。

### B 类：环境依赖缺失（3 个 503）——**冒烟环境下预期，预发布需复验**

`community-method-cards`、`mock-exams/weekly(v1)` 返回 `service_unavailable`。
依赖冒烟环境未启用的服务。待办：在预发布环境确认这些依赖存在并复验；
若生产也缺，则升级为 A 类问题。

### C 类：账号缺业务数据（其余 ~7 个）——**正常降级**

essay 系列、ability、error-pattern 等页面因冒烟账号没有作文任务、能力评估等
业务数据而进入 error/empty 态。这是最小种子账号的预期行为，非缺陷。
可选优化：给冒烟账号补业务数据种子，把这些页面推进到 pass，提高信噪比。
