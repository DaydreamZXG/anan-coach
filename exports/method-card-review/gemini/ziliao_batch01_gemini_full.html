一般增长率：先定基期再算增幅

mc_ziliao_zengzhanglv_yiban_01 资料分析/增长率/一般增长率 限时 55 秒/题 抽样：exact_display_path 状态：draft

识别信号

题干问同比、环比、增长速度或增幅，材料能定位现期量和上一期量

精度规则

选项相差超过3个百分点时估算；相差小于3个百分点时保留一位小数

增长率分母永远是基期，不是现期

适用

  • 题干直接问增长率、增速、增幅
  • 材料同时给出现期量和基期量，或能由相邻时期定位

排除

  • 题干问增长量而不是增长率
  • 多个部分合并后才求整体增速

步骤

  1. 先标出现期和基期，判断答案应为正还是负
  2. 增长率 = 增长量 / 基期，增长量 = 现期 - 基期
  3. 选项差距大时只估首两位，优先排除符号和量级错误
  4. 基期接近整百整千时，把分母化整再估百分数

常见错因

  • growth_rate_denominator_wrong：把现期量当作增长率分母
  • growth_rate_sign_missed：现期小于基期时没有先判负增长

混合增长率：居中偏向基期大者

mc_ziliao_hunhe_zengzhanglv_01 资料分析/增长率/混合增长率 限时 65 秒/题 抽样：exact_display_path 状态：draft

识别信号

题干问两个或多个部分合计后的同比、环比增长率

精度规则

选项间距大时用居中偏向判断；选项贴近时估基期权重再算

混合增长率不是各增速的简单平均

适用

  • 已知各部分现期量和各自增长率
  • 题干要求整体、合计、总体的增长率

排除

  • 只问单个部分增长率
  • 各部分口径重叠，不能直接相加

步骤

  1. 先确定各部分增长率的最大值和最小值，整体增速必在两者之间
  2. 用现期量除以 1 + r 估出各部分基期量
  3. 基期量大的部分对整体增速拉力更大
  4. 选项在两端之外直接排除，居中选偏向基期大者的一侧

常见错因

  • mixed_growth_outside_range：选了不在各部分增长率区间内的整体增速
  • mixed_growth_weight_current：用现期量大小直接判断偏向，忽略应按基期量加权

识别信号

精度规则

选项差距大于5%时估算；差距小于5%时保留一位小数核算

看到负增长先提醒自己基期应大于现期

适用

  • 题干明确问上一年、上期、基期、2024年等过去口径
  • 材料给出现期量和同比、环比或增长率

排除

  • 问增长量而不是基期量
  • 需要先合并多个现期量再求基期

步骤

  1. 基期 = 现期 / (1 + 增长率)
  2. 增长率绝对值小于5%时，用现期乘以 (1 - r) 快速近似
  3. 增长率为负时分母是 1 - |r|，基期会大于现期
  4. 选项差距大于5%时估算，不做完整除法

常见错因

  • base_period_formula_flip：把基期公式记成现期乘以 (1 + r)
  • negative_growth_direction_wrong：负增长时仍把基期算得比现期小

识别信号

题干给出基期量和增长率，问后来某期、保持增速后的现期量

精度规则

单步顺推保留整数或一位小数；首次超过题先估年份再精算临界点

看清题干说的是保持增量还是保持增速

适用

  • 题干出现若保持、预计、将达到、某年为多少
  • 已知基期量和增长率或能先求出增长率

排除

  • 问过去基期量
  • 题干要求复杂递推且每期增速不同

步骤

  1. 现期 = 基期 x (1 + 增长率)
  2. 如果先给相邻两期量，先求增长率再顺推
  3. 连续多年同增速且选项粗时，用倍数感判断量级
  4. 问首次超过时，先算每年净增加量，再用差距除以增量

常见错因

  • current_period_direction_wrong：把顺推现期误做成反推基期
  • projection_increment_wrong：保持增量和保持增速没有区分

识别信号

题干问增加了多少、增长量、同比增量或环比增量

精度规则

r 可化成常见分数时用 n+1 公式；不能化分数时按选项差距估算

现期乘增长率算出来偏大，常是陷阱项

适用

  • 已知现期量和增长率
  • 或材料直接给出现期量和基期量

排除

  • 问增长率
  • 问多个对象增长量大小排序

步骤

  1. 有现期和基期时，增长量 = 现期 - 基期
  2. 有现期和增长率时，增长量 = 现期 x r / (1 + r)
  3. r 接近 1/n 时，用现期 / (n + 1) 速算增长量
  4. 负增长时增长量为负，问减少量时取绝对值

常见错因

  • growth_amount_use_current_times_rate：直接用现期乘增长率，少除以 (1 + r)
  • growth_amount_negative_misread：没区分增长量为负和减少量为正

增长量比较：大大则大，一大一小再算

mc_ziliao_zengzhangliang_bijiao_01 资料分析/增长量/增长量比较 限时 60 秒/题 抽样：exact_display_path 状态：draft

识别信号

题干问哪个增长量最大、最小，或要求比较多个对象同比增量

精度规则

先用大大则大排除；只在一大一小时估算增长量

增长率最高不等于增长量最大

适用

  • 多个对象均给出现期量和增长率
  • 题干目标是增长量大小而不是增长率大小

排除

  • 只比较增长率
  • 数据口径不同，不能直接横比

步骤

  1. 同时比较现期量和增长率，现期大且率大则增长量必大
  2. 现期小且率小的对象可先排除
  3. 一大一小时，用现期 x r / (1 + r) 估算关键候选
  4. 只精算最接近的两个候选

常见错因

  • growth_amount_compare_rate_only：只按增长率大小比较增长量
  • growth_amount_compare_all_calculated：每个选项都完整计算，耗时过长

识别信号

题干问某部分占总体的比重、占比或百分点差

精度规则

比重题先估首位；百分点差小于2时再保留一位小数

百分点是两个百分数直接相减，不再除以原比重

适用

  • 材料给出同一时期的部分量和总体量
  • 题干出现占、比重、占比、百分点

排除

  • 问上一期比重
  • 问两期比重变化

步骤

  1. 先圈部分量，再圈整体量，确认二者同一时期同一单位
  2. 比重 = 部分 / 整体
  3. 问百分点差时分别算两个比重再相减
  4. 选项粗时把整体化成便于除的整百、整千

常见错因

  • proportion_part_whole_reversed：把整体和部分放反
  • percentage_point_as_percent：把百分点差误当成百分比变化

精度规则

先判方向；选项接近时保留一位小数核算修正系数

基期平均数修正中，份数增速在分子，总量增速在分母

适用

  • 已知总量现期、份数现期及二者增长率
  • 题干明确问过去时期平均数

排除

  • 只问现期平均数
  • 材料直接给出基期总量和基期份数可直接相除

步骤

  1. 先算现期平均数 = 总量现期 / 份数现期
  2. 基期平均数 = 现期平均数 x (1 + 份数增速) / (1 + 总量增速)
  3. 总量增速大于份数增速时，基期平均数小于现期平均数
  4. 先用方向排除，再估修正系数

常见错因

  • base_average_growth_order_wrong：把总量和份数的增长率修正顺序写反
  • base_average_direction_wrong：没用总量增速和份数增速判断基期平均数方向

比值计算：先翻译除法关系

mc_ziliao_bizhi_jisuan_01 资料分析/倍数与比值相关/比值计算 限时 55 秒/题 抽样：exact_display_path 状态：draft

识别信号

题干问是几倍、比值、强度、密度、单位量或 A 约为 B 的多少

精度规则

范围选项只估到区间；精确倍数题保留两位有效数字

看到“增长速度的几倍”，先算两个增长率，不是两个原量相除

适用

  • 题干需要把两个同口径量做除法
  • 选项为倍数、范围或单位强度

排除

  • 问比重且有明确部分整体关系
  • 问增长率的倍数，需要先求两个增长率

步骤

  1. 把题干翻译成 A / B，先写清谁除以谁
  2. 单位不同先统一，尤其万、亿、日均、公里
  3. 选项为范围时估首两位即可
  4. 若问增长速度的倍数，先分别求两个增长率再相除

常见错因

  • ratio_direction_reversed：A 是 B 的几倍时把 B / A
  • ratio_nested_rate_skipped：问增长速度倍数时直接用原量相除

识别信号

题干问多个对象的强度、平均量、比值谁最高或最低

精度规则

比较题优先交叉相乘；除非选项要求具体数值，否则不做完整除法

分子大不一定比值大，还要看分母

适用

  • 多个对象都能写成 A / B
  • 题干目标是比较大小而非求具体数值

排除

  • 只要求单个比值落在哪个范围
  • 分子分母口径不同，不能横向比较

步骤

  1. 先写出每个候选的 A / B
  2. 分子大且分母小的候选必更大，优先保留
  3. 一大一小时用交叉相乘比较 A1 x B2 和 A2 x B1
  4. 只对最后两个候选估算具体比值

常见错因

  • ratio_compare_numerator_only：只看分子大小比较比值
  • ratio_compare_full_calculation：每个候选都完整除法，耗时过长
