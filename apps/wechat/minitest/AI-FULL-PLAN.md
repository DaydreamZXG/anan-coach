# 微信云测 AI 全量测试计划

AI 全量套件不是 5 条体验冒烟，而是 25 条真人旅程、3 类账号、3 种设备形态和 6 项微信原生能力人工补测。清单文件 `ai-full-suite.json` 会与 `app.json` 机械比对；当前覆盖 60/60 条注册业务路由。

**云端状态（2026-08-06）**：25 条 AI 用例和 3 组 AI 测试计划已通过微信云测官方 API 创建成功。

## 覆盖组成

| 计划                         | 用例 | 账号                                       | 设备                         |
| ---------------------------- | ---: | ------------------------------------------ | ---------------------------- |
| `岸岸0.1.10-AI全量-成熟账号` |   16 | 已完成新手引导、有历史数据                 | 手机竖屏、平板竖屏、平板横屏 |
| `岸岸0.1.10-AI全量-写入账号` |    8 | 昵称包含“测试”、`Test` 或 `E2E` 的专用账号 | 手机竖屏                     |
| `岸岸0.1.10-AI全量-全新账号` |    1 | 从未登录和建档的全新虚拟账号               | 手机竖屏                     |

成熟账号计划覆盖今日计划、计划依据与历史、岗位搜索与决策、能力报告、行测入口与掌握队列、申论证据链、报告中心、资料库、社区、我的、岸岸以及账号权益。

写入账号计划真实执行今日调整、提醒保存、岸岸提问、个人数据导出、行测交卷复盘、模考工具与恢复、外部成绩录入和申论阶段提交。每条写入用例开始前都会调用账号护栏，普通账号会立即失败。

全新账号计划从微信登录开始，依次完成备考经历、资格档案、岗位偏好、每周 8 小时学习时间、能力起点、建档结果和首次今日计划。

## 第一步：上传带 AI 函数的 Minium 包

在 `apps/wechat` 目录执行：

```bash
npm run minitest:package
```

重新上传：

```text
minitest/dist/anan-minium-full-suite.zip
```

包内的 `ai_cloud_support.py` 为 AI 用例提供稳定起点、视口读取和专用账号写入护栏。微信要求 `minium_func_call` 调用的函数必须已经随 Minium 用例上传。

## 第二步：本地检查全量清单

```bash
npm run aitest:check
```

成功输出应为：

```text
AI full suite: 25 cases / 3 plans / 60 registered routes / 6 manual platform cases
```

新增或迁移页面后，如果没有任何 AI 旅程声明覆盖它，检查会直接失败并列出路由。

## 第三步：批量创建 AI 用例与计划

微信官方 API 需要两个值：

- `token`：云测页面右上角头像菜单中的“我的 Token”或“我的信息”；
- `group_en_id`：项目管理/产品管理页面中的项目英文 ID。

不要把 Token 写进仓库或聊天记录。在 `apps/wechat` 目录直接运行：

```bash
npm run aitest:sync
```

脚本会隐藏询问 Token，再询问项目英文 ID。CI 等非交互环境也可以使用 `WECHAT_CLOUDTEST_TOKEN` 和 `WECHAT_CLOUDTEST_GROUP_ID` 环境变量。

同步脚本会：

1. 查询云端现有 AI 用例；
2. 按唯一名称创建缺失用例；
3. 内容变化时更新已有用例；
4. 创建或更新三组 AI 测试计划；
5. 保持清单里的 DDT 执行顺序；
6. 不打印或保存 Token。

## 第四步：提交三组云测任务

在“测试任务”中新建任务：

1. 测试类型选择 `Minium`；
2. 选择右侧带 `AI` 标签的计划；
3. 为成熟计划分别提交手机竖屏、平板竖屏和平板横屏；
4. 写入计划只绑定专用可抛弃账号；
5. 全新计划只绑定一个未使用过的虚拟账号。

AI 用例采用 DDT 顺序执行。写入账号的顺序已经安排为申论、行测、模考、外部成绩、岸岸、计划调整、提醒和数据导出，避免前面的计划变更过早影响任务数据。

## 报告判读

微信官方明确说明，AI 显示“测试成功”代表大模型认为自己执行成功。每条用例仍需检查：

- 执行步骤截图；
- `llm_assert` 是否验证了真正的业务结果；
- 自动生成的 Minium 代码；
- 是否出现 OCR 误认、误点或探索超时；
- 写入后是否形成真实的新版本或记录。

稳定通过的 AI 生成脚本应下载并收编进确定性 Minium 套件，形成“AI 探索发现 → 人工核对证据 → 固定回归”的闭环。

## AI 当前不能替代的真机检查

官方当前主要支持点击、简单输入、滑动、函数调用和大模型断言。下面 6 项仍需人工真机保留截图或录屏：

1. 相机拍题、相册选图与权限拒绝后恢复；
2. 系统文件选择器导入资料和更新私人资料版本；
3. 麦克风授权、录音、试听、上传和语音转文字；
4. 微信订阅消息授权弹窗与设置页同步；
5. 客服二维码预览、保存和识别；
6. 个人数据导出文件保存与转发。
