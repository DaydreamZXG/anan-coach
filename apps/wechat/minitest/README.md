# 微信云测 Minium 全量测试

这套用例用于微信开发者工具的“云测 → 自定义测试 → Minium”。它连接真实上传版本、真实后端和测试账号，不把“页面能打开”冒充“业务已跑通”。

当前套件经微信官方 `debug_analyse.py` 解析为 **109 条独立用例**：

- 60 条注册业务路由逐页渲染冒烟；
- 9 条核心工作区真实数据就绪检查；
- 21 条跨页只读主链路与内容切换；
- 6 条手机、竖屏平板、横屏平板横向溢出检查；
- 6 条今日页布局与分包回归；
- 6 条专用账号真实写入与训练闭环；
- 1 条全新账号登录到完成新手引导的完整链路。

项目的静态交互合同还会校验 60/60 页面各自的主操作是否绑定到真实控制器。相机、录音、系统文件选择器、订阅消息授权等微信原生能力另列真机人工清单，不能用 DOM 点击假装已经验证。

在确定性 Minium 套件之外，项目还提供 **25 条 AI 真人旅程、3 组 AI 测试计划**，同样覆盖 60/60 条注册路由。批量创建方式和报告判读见 [AI-FULL-PLAN.md](./AI-FULL-PLAN.md)。AI 探索用于发现真人操作中的意外问题，不能替代本页的确定性断言。

## 生成上传包

在 `apps/wechat` 目录执行：

```bash
npm run minitest:package
```

产物为：

```text
minitest/dist/anan-minium-full-suite.zip
```

ZIP 根目录直接包含测试文件和 `minium_support.py`，没有多套一层目录。打包脚本还会核对测试路由清单与 `app.json` 完全一致，避免新增页面后测试悄悄漏掉。

## 必须拆成三组测试计划

同一个账号无法同时处于“全新”“成熟”和“允许反复写脏数据”三种状态。上传一个 ZIP 后，在云测里建立下面三组计划；微信官方支持按勾选顺序执行用例。

### 计划一：成熟账号全量只读

账号要求：已经登录、完成新手引导、有今日计划、有岗位与能力数据。勾选除 `YFreshAccountOnboardingJourneyTest` 和 `ZDisposableAccountMutationTest` 以外的全部用例，共 **102 条**。

至少运行三组设备：

1. 主流手机竖屏；
2. 平板竖屏；
3. 宽度不低于 1024px 的平板横屏。

这一组会验证 60 条路由、核心数据、今日/能力/岸岸/我的、岗位、报告、资料、社区入口和本轮布局回归。

### 计划二：专用账号真实写入

账号要求：昵称必须包含“测试”、`Test` 或 `E2E`，已经完成新手引导，今天同时有可执行的行测和申论任务。只勾选 `ZDisposableAccountMutationTest` 的 **6 条**，先用一台手机运行。

这组会真实产生或修改：

- 今日计划调整；
- AI 督学提醒偏好；
- 一次岸岸提问及额度；
- 个人数据导出请求；
- 一次行测交卷与复盘记录；
- 一份申论本地结构化草稿。

用例在每次写入前都会检查昵称；普通账号会直接失败，不会被静默修改。

### 计划三：全新账号新手引导

账号要求：单独分配一个从未登录、从未完成新手引导的虚拟账号。只勾选 `YFreshAccountOnboardingJourneyTest.test_fresh_account_completes_login_and_onboarding`。

该用例只有一条，是因为它执行后账号不再是“全新账号”。它覆盖登录授权、备考经历、资格档案、岗位偏好、每周 8 小时学习时间、能力起点、建档结果以及首次今日计划加载。

## 结果怎么判读

报告中四种证据不能混用：

| 证据     | 说明                                            | 能证明什么                   |
| -------- | ----------------------------------------------- | ---------------------------- |
| 路由渲染 | 页面稳定、出现 DOM 或发生产品允许的注册路由跳转 | 包加载、路由与基础渲染没有崩 |
| 核心就绪 | 页面进入 `ready/empty` 且关键数据存在           | 真实后端读取和页面投影可用   |
| 用户旅程 | 从真实入口点击并到达下一业务页面                | 导航与主要只读交互连通       |
| 真实写入 | 后端版本变化、返回保存结果或形成训练记录        | 关键写操作闭环成立           |

路由冒烟允许缺少业务参数的详情页进入产品自己的空态/错误态；详情页的有效数据路径由用户旅程另测。不要只看“通过数量”，应先看失败属于账号前置不足、测试数据不足，还是产品缺陷。

## 微信原生能力真机清单

下面场景需要在云测真机上单独人工确认并保留截图或录屏：

- 拍题、相册选择和资料文件导入；
- 行测/申论复盘的麦克风授权、录音、试听、上传；
- 订阅消息授权弹窗与微信设置页同步；
- 客服群二维码预览、保存或识别；
- 个人数据导出文件的保存与转发；
- iOS 与 Android 的返回、键盘顶起、权限拒绝后恢复。

## 建议的执行顺序

1. 先跑成熟账号的手机竖屏；
2. 修复产品缺陷或补齐测试账号数据；
3. 重跑失败用例；
4. 再跑平板竖屏和横屏；
5. 跑专用账号真实写入；
6. 最后跑一次性全新账号新手引导和微信原生能力人工清单。

微信官方说明：用例上传后会执行每个 Python 文件，并通过 `inspect` 识别 `test` 开头的方法；云测也支持一键重跑失败用例。参考[自定义测试](https://developers.weixin.qq.com/miniprogram/dev/devtools/minitest/minium.html)和[上传自定义用例指引](https://developers.weixin.qq.com/miniprogram/dev/devtools/minitest/upload_case.html)。
