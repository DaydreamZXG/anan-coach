# 岸岸微信小程序 · 前端设计与实现规范

> 四个主 Tab 的视觉唯一依据是 Figma Design File
> `pU5sxRfG4UFeCCrnSPoaAX`（今日 `3:2`、能力 `4:2`、岸岸 `6:2`、我的 `7:2`）。
> Figma Make / Antigravity 只提供交互意图，不能覆盖真实 controller、接口、路由与数据状态。
> 产品边界以 `docs/product/2026-07-18-canonical-product-boundaries.md` 为准。

## 1. 产品界面原则

1. 岸岸是“以国考目标岗位为终点的 AI 学习教练”，主链必须能从建档、定岗一路走到任务、复盘、能力更新和计划调整。
2. 没有数据就说明还缺什么，并给出真实下一步；禁止演示数据、假成功、内存成功和“稍后开放”死入口。
3. 写给考生看，不把接口名、枚举、规则版本、指纹、事务、回执、投影等工程概念直接放到界面。
4. 重要结论要同时说清依据和边界：岗位分差不是录取概率，AI 判断可以被用户确认或否定，私人资料不跨用户复用。
5. 一个能力只有一个正式页面和一条正式数据链路。不能为了换皮复制出第二套岗位、通知、复盘或资料页面。

## 2. 视觉方向

- 页面使用石墨黑文字、极浅冷灰背景和大面积白色卡片，保留充足留白。
- 普通主操作使用石墨黑；**主交互强调色为青色系**（2026-07-26 产品拍板：选中态、进度、
  轻量按钮、链接走 `--color-primary*` 青色档）。靛蓝、紫色与玫红渐变只保留在 AI
  洞察、岸岸能力和智能状态的渐变身份里。
- 不再使用暖橙陪伴色。成功、提醒、危险各自使用独立语义色。
- 注意：Figma 源文件主色仍是靛蓝，运行时经语义层映射为青色；下轮设计稿更新时同步。
- 卡片使用 24–32px 圆角与极轻阴影；层级来自间距、字号和明度，不堆叠描边与发光。
- 页面不得自行创造第二套颜色、圆角或阴影；先映射全局 token，再实现局部节点。

### 2.1 锁定的视觉阶梯（2026-07-26 定档）

字号、圆角、阴影三个维度全部锁档，运行时 WXSS 一律写 `var()`，`validate-tokens.mjs`
门禁强制执行；确需例外时在该行末尾写 `/* token-exempt: 具体理由 */`。
Figma 稿是视觉方向权威，但**不是字面值权威**：设计稿里出现的 16–21rpx 文字、
一次性圆角和一次性阴影，落码时必须吸附到最近的档位。

**字号（`--text-*`，13 档）**

| token             |    值 | 用途                                       |
| ----------------- | ----: | ------------------------------------------ |
| `--text-tab`      | 20rpx | 仅自定义 tab bar 标签                      |
| `--text-micro`    | 22rpx | 时间戳、chip、标注（可读性底线，禁止更小） |
| `--text-caption`  | 24rpx | 说明文字、次要信息                         |
| `--text-body`     | 26rpx | 正文最小档                                 |
| `--text-body-lg`  | 28rpx | 正文、列表标题                             |
| `--text-section`  | 32rpx | 区块标题、强调正文                         |
| `--text-title-sm` | 36rpx | 卡片大标题                                 |
| `--text-title`    | 40rpx | 页面小标题                                 |
| `--text-title-lg` | 48rpx | 大标题                                     |
| `--text-hero`     | 56rpx | 页面主标题                                 |
| `--text-stat`     | 64rpx | 数据大数字                                 |
| `--text-display`  | 72rpx | 特大展示                                   |
| `--text-stat-lg`  | 80rpx | 结算大数字                                 |

字号只允许引用 `--text-*` 这一个家族（2026-07-26 起）：`--figma-font-*`
（`--figma-font-family` 除外）与旧 `--font-body/caption/section/title` 别名已退役，
`validate-tokens.mjs` 会拦截。

**文字灰 4 档锁定（2026-07-26）**：`--color-ink`(#101828 主文字) →
`--color-ink-secondary`(#364153 次要) → `--color-muted`(#6a7282 辅助) →
`--color-faint`(#99a1af 最弱)。`--figma-color-ink-strong` 与
`--figma-color-ink-tertiary` 不再作为文字色（前者仅限暗色面板的结构背景/描边）。

**选中态一律主交互色（青）家族**：紧凑 chip/选项选中用 `--color-primary` 实底 + 白字，
大卡片选中用 `--color-primary-soft` 底 + `--color-primary-deep` 字；不再使用深墨选中。

**彩色文字白名单（2026-07-26）**：文字只有三种理由可以带彩色——
① 语义状态（`--color-danger`/`--color-warning`/`--color-success`）；
② 可点击或选中（链接、文字按钮、选中态用 `--color-primary*`）；
③ AI 身份（AI 渐变仅限岸岸/AI 元素）。
装饰性眉题、kicker、星标、步骤号、非交互标签、数据值一律用灰阶或 `--color-ink`，
不得用主色点缀。

**圆角（`--radius-*`）**：8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 + `--radius-capsule`(9999rpx)。
`≤4rpx` 发丝圆角、`0`、`50%`、`inherit` 允许保留字面值。

**阴影（`--shadow-*`）**：`soft`（卡片微投影）、`crisp`（小控件）、`card` /
`card-strong`（标准卡）、`elevated`（浮起）、`primary`（深色主按钮）、
`primary-soft`（靛蓝浅光）、`ai`（AI 元素紫光）、`cyan`（陪伴青光）、
`dock`（底部工具坞）、`overlay`（上滑浮层）、`well`（内凹）、
`spotlight-mask`（引导镂空遮罩）。除 AI/陪伴语义外不允许彩色发光。

**间距节奏**：padding / margin / gap 的 rpx 分量必须落在
2 / 4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 40 / 48 / 56 / 64 / 80 / 96 阶梯上；
`≤4rpx` 发丝值与 `>96rpx` 布局让位保留字面，含 `calc()`/`env()`/`max()` 的复合值不受约束。

**字重 5 档**：400 / 500 / 600 / 700 / 800，禁止 650、750、760 之类的中间值。

行高不锁档：定高控件的垂直居中契约（`line-height` = 高度）由
`validate-control-alignment.mjs` 单独校验，不得为凑节奏破坏。

平板层（`@media` 内的 px 值）不受 rpx 阶梯约束，但同样优先复用 token。

### 2.2 适配规则（设计稿抄不到的部分）

Figma 是 375 宽静态图；以下情况设计稿没有答案，按本节执行，不得硬抄：

1. **文案变长**：单行标签一律 `ellipsis` 截断或按语义换行，禁止把数值和单位拆行
   （如天气「降水概率 45%」必须整体换行，不许「45%」孤行悬挂）。
2. **数据缺失/变短**：区块按真实数据收缩，不留设计稿里的固定空高。
3. **胶囊与灵动岛**：自定义导航必须经 `components/safe-top`（实测
   `getMenuButtonBoundingClientRect` + 状态栏，灵动岛机型自动被计入）；标题与操作
   只允许使用胶囊**左侧**空间，任何控件不得进入胶囊所在行的右侧区域。
4. **触控底线**：可点击控件视觉高度 ≥88rpx（44px），小图标用透明外扩热区补足。
5. **底部安全区**：吸底元素一律 `env(safe-area-inset-bottom)` 起算，浮动 tab 胶囊
   之上的内容留 ≥180rpx 底部空间。
6. **组件优先**：先用 `s9-*` 骨架与 `design-system/primitives` 组件拼页面；缺组件
   先补组件，不许在页面里手写第二份卡片/按钮/列表样式。

### 2.3 页面骨架（2026-07-26 起）

- 原生导航页用 `s9-page`；workbench-nav 自定义导航页用 `s9-screen` + `s9-body`
  （带底部操作坞时加 `--with-dock` 变体）。
- 页头用 `s9-hero`（`s9-chip-row` / `s9-title` / `s9-subtitle`），区块用
  `s9-section` + `s9-section-head`，卡片一律 `s9-card`（页面类只加特有节点），
  底部固定操作用 `s9-action-dock` + `s9-primary-button` / `s9-secondary-button`。
- 各 feature 的 `page-shell.wxss`（positions / onboarding / essay / reporting 等）
  视为该流程的骨架方言，允许存在，但值必须走锁定阶梯，且不得再新增方言。
- 有意的骨架例外（不套 s9 骨架）：四个主 Tab（Figma 专属节点）、login（光晕开屏）、
  capture-import（暗色相机面）、essay-material（纯白阅读面）。新页面不加入例外，
  除非产品负责人确认。

核心 token：

| 名称             | 默认值    | 用途             |
| ---------------- | --------- | ---------------- |
| `--bg`           | `#f7f9fc` | 页面背景         |
| `--surface`      | `#ffffff` | 主卡片           |
| `--ink`          | `#101828` | 主文字与主操作   |
| `--ink-2`        | `#6a7282` | 次文字           |
| `--line`         | `#f3f4f6` | 分隔             |
| `--primary`      | `#00b8db` | 主交互强调（青） |
| `--primary-soft` | `#ecfeff` | 交互浅底（青）   |
| `--ai-violet`    | `#ad46ff` | AI 渐变          |
| `--ai-pink`      | `#f6339a` | AI 渐变          |
| `--good`         | `#00a63e` | 成功             |
| `--danger`       | `#fb2c36` | 危险操作         |

页面背景锁定（2026-07-26）：

- 页面根背景一律纯平 `--color-canvas`（`#f7f9fc`），不加任何极光/径向渐变晕；
  页面 JSON `backgroundColor` 统一 `#F7F9FC`。
- 例外仅限 Figma 批准的：login 光晕开屏、capture-import 暗色相机面、
  essay-material 纯白阅读面。
- AI 语义卡片允许 ≤0.03 透明度的 AI 三色微渐变叠在 `--surface` 上；
  这是卡片装饰，不得上升为页面背景。

按钮五档锁定（2026-07-26）：

| 档位    | 样式                                                                  | 场景                                  |
| ------- | --------------------------------------------------------------------- | ------------------------------------- |
| 主操作  | `--color-ink` 实底 + 白字                                             | 页面/卡片唯一主动作，每屏最多一个层级 |
| AI 动作 | `--gradient-ai` + 白字                                                | 岸岸/AI 发起的动作                    |
| 次级    | `--surface` 白底 + `--color-line-strong` 描边                         | 与主操作并列的备选动作                |
| 轻量    | `--color-primary-soft` 底 + `--color-primary-deep` 字，或青色文字按钮 | 行内/列表内动作、加载更多             |
| 语义    | `--danger` 红、`--color-wechat` 绿                                    | 危险操作、微信授权                    |

- 主交互色实底（`--color-primary`）保留给**选中态、进度、圆点、开关**等交互指示，
  不再用作按钮底色；暗色面（相机流）上的动作按钮用 `--color-primary-bright`（亮青）。

## 3. 导航与页面

- 固定四个 Tab：今日、能力、岸岸、我的。
- 岗位属于阶段性决策工具，从“我的”和建档结果进入，不占常驻 Tab。
- 路由唯一权威是 `miniprogram/app/navigation/routes.ts`，注册唯一权威是
  `miniprogram/app.json`；两者必须一致。
- 登录、建档和任务深链必须恢复原目的页，不能静默改跳到“差不多”的页面。
- 全局使用微信原生导航栏；确有自定义顶部导航的页面必须读取胶囊和安全区数据，不能只靠 CSS 猜高度。

## 4. 真实状态

页面按业务实际支持以下状态，而不是机械凑“四态”：

- 首次加载；
- 有数据；
- 无数据，并给出可执行下一步；
- 请求失败，展示安全的人话提示和 Request ID；
- 写入处理中；
- 版本冲突；
- 网络结果不确定时恢复原操作；
- 数据过期或部分可用。

读取失败不能改用演示数据；写入失败不能提示成功。短暂断网只保留已经真实取得的题面、答案和草稿。

## 5. API 与状态所有权

- 所有业务请求经 `miniprogram/api/client.ts` 和对应领域 API 类发出。
- OpenAPI 生成类型来自 `miniprogram/api/generated/types.gen.ts`，页面不得手写另一套服务端响应结构。
- 写操作使用稳定的幂等键；结果不确定时重放同一命令，不能新建第二次写入。
- 登录状态唯一由 `miniprogram/auth/session.ts` 持有；用户数据必须按 learner ID 隔离。
- 页面只负责展示与交互，版本冲突、恢复、校验和业务转换放在对应 controller / feature 中。

## 6. 文案

- 遵守 `docs/design/2026-07-22-ui-copy-style-guide.md`。
- 标题先说用户要完成什么；说明文优先控制在 30 字以内。
- 空状态必须回答“现在为什么没有”和“接下来点哪里”。
- Request ID 可以展示；错误码、数据库字段、模型内部过程不展示。
- 不出现“服务端、断点、证据链、门禁、投影、原命令、输入指纹”等工程词。

## 7. 手机与平板

- `app.json` 保持 `resizable: true` 和自动方向。
- 手机完成完整功能；平板不是简单放大，长材料题、申论和整卷模考使用材料/题目/作答双栏。
- 表单、对话和普通详情页保持可读限宽；主内容与次内容在宽屏可并排。
- 横竖屏切换不能丢失题号、答案、草稿、计时和编辑权。

## 8. 交付要求

- 改造阶段允许批量完成页面后统一验收，不要求每改一页都跑完整套件。
- 合入前必须一次性完成类型检查、路由/交互覆盖、关键真实链路、运行时警告、视觉对照、手机和平板真机验收。
- 正式版本不得带 401/404、属性类型警告、废弃 API 警告、静态演示数据或未解释的审核警告。
- 上述 Design File 节点是主 Tab 的像素与布局依据；视觉同步不能覆盖 controller、接口、恢复逻辑和真实状态。
- Figma Make 中的 mock、`setTimeout`、空按钮和 placeholder 路由不得进入正式代码。

## 9. 当前延期入口

以下能力保留实现或配置，但在条件成熟前关闭用户入口：

- 收费商品、退款和微信虚拟支付；
- 用户可见的手动云备份；
- 正式客服工单；
- 事业单位独立产品；
- 岸岸宠物形象替换。
