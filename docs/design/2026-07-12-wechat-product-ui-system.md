# AI 国考上岸教练小程序产品 UI 系统

> 状态：全局设计基线  
> 日期：2026-07-12  
> 取代：逐页堆叠白卡、通用 SaaS 仪表盘、无主次的低保真页面

## 1. 设计命题

**一个真正懂你的 AI 备考搭子。**

视觉不模仿传统题库，也不做聊天机器人壳。产品必须同时表达三件事：

1. **目标很具体**：岗位、分差、日期是持续可见的坐标。
2. **判断有依据**：结论与证据在同一视觉层次，不用魔法文案包装。
3. **行动很克制**：每页只有一个当前主行动，AI 不用功能数量制造聪明感。
4. **陪伴可感知**：岸岸记得用户的状态和变化，但不靠撒娇、打卡或游戏化制造黏性。

## 2. 品牌与视觉方向

### 2.1 个性

- 聪明，但不炫技。
- 温和，但不幼稚。
- 直接，但不羞辱。
- 有未来感，但不做赛博霓虹。
- 像一位记性很好、懂得适时收手的备考搭子，不像客服或官场 NPC。

### 2.2 色彩令牌

| 角色 | 令牌 | 值 | 用法 |
|---|---|---:|---|
| 主墨色 | `ink-950` | `#111426` | 大标题、正文和关键数字 |
| 智能蓝 | `signal-600` | `#5268FF` | 主行动、当前进度、AI 判断 |
| 深空蓝 | `space-800` | `#252C72` | 品牌层、目标分和强指标 |
| 陪伴紫 | `companion-500` | `#8B5CF6` | 岸岸、AI 生成态和连续关系 |
| 呼吸青 | `cyan-400` | `#4DE2D0` | 掌握、在线感、证据通过 |
| 战略橙 | `amber-400` | `#FFAC66` | 分差、降权、待确认 |
| 雾面底色 | `surface-50` | `#F3F5FB` | 长时学习场景背景 |
| 玻璃线 | `line-glass` | `rgba(52,61,102,.11)` | 容器、表格与证据链 |

禁止每个模块任意生成独立颜色。行测模块只在图表中使用限制色，不把界面变成彩色标签墙。

### 2.3 字体与数字

- 全产品统一使用 `Maple Mono CN`，包括中文标题、正文、题干、材料、解析和数据。
- 正式字重只保留 Regular 400 与 Bold 700；500 就近使用 400，600/800 就近使用 700，禁止浏览器合成伪粗体。
- 不引入 Nerd Font、斜体、Thin、Light、Medium、ExtraBold 或完整字体压缩包。
- 字体由自有 HTTPS origin 提供，Regular 与 Bold 分别加载并记录真实状态；两者都成功才算产品字体可用。
- 字体版本和内容校验值必须与 OFL 许可证一并维护。
- 大数字必须配对象和口径，不单独陈列“78%”。

### 2.4 岸岸

岸岸使用固定的“蓝紫生命体 + 青色轨道”识别。形态轻微呼吸，不在每页放大头照，也不做幼态卡通表情。

- 今日判断：小型头像 + 一句话。
- 解题追问：作为方法和证据的讲解者。
- 聊天页：才出现完整形象。
- 不使用岸岸取代错误、风险或支付等语义图标。

## 3. 导航与页面家族

正式底部导航为四项：

1. **今日**：规划 Agent 的唯一主入口。
2. **训练**：智能练习、错题、复测、模考、申论。
3. **岗位**：资格、搜索、冲稳保、岗位详情和对比。
4. **我的**：学习档案、岸岸、会员、隐私与设置。

“岸岸”是全局悬浮入口和任务内上下文入口，不独占底部导航。

## 5. 全局布局规范

### 5.1 页面节奏

- 顶部不统一放“小蓝字 + 大标题 + 灰副标题”。只有一级工作区使用品牌页头。
- 二级任务页使用紧凑导航 + 内容进度，不重复宣传文案。
- 页面主区域不超过三个：当前事实、当前判断、当前行动。
- 连续卡片超过三张时，必须改用表格、时间线、分组列表或全宽区带。

### 5.2 圆角与阴影

- 一级强区域：22 px 圆角，允许蓝紫极光渐变和柔和外发光。
- 普通容器：15–17 px 圆角，使用半透明浅表面。
- 输入/按钮：13–16 px 圆角。
- 一个页面不同时出现四种圆角。
- 常规容器使用低对比玻璃线；只有浮层、强指标和悬浮操作使用有色柔光阴影。
- 品牌页、AI 对话页可使用深色空间层；长时阅读和做题页必须保持浅色、低干扰。

### 5.3 行动

- 每页一个填充式主按钮。
- 危险操作不与主按钮并排。
- 做题页在选择答案前不展示解析。
- 复盘页的主行动是“提交我的思路”，不是“看 AI 答案”。

## 6. 做题闭环专项规范

```text
任务说明
  -> 作答（记用时/信心/修改/跳题）
  -> 最小即时反馈
  -> 若高价值错误：用户先表达
  -> AI 候选错因
  -> 用户确认/否定/补充
  -> 即时变式验证
  -> 整组结果
  -> 下次间隔复测
```

作答页将题目阅读空间置于一切之上：

- 顶栏只放进度、用时、答题卡。
- 题干与材料使用阅读排版，不装进双层卡片。
- 选项用整行可点区域，标签、正文和选中态在同一网格。
- “不会/跳过”是一等作答轨迹，不藏在菜单。
- 信心度在提交时采集，不每题再开一页。

## 7. 状态规范

每个服务端页面必须设计：

- `loading`：保留页面结构的骨架，不使用全屏转圈。
- `empty`：说明为什么空和如何建立第一条证据。
- `partial`：展示已知结论和未知项，不用“待校准”一句掩盖。
- `error`：展示 request ID 与可执行重试，不暴露原始服务端错误。
- `stale`：明确显示数据时间和刷新影响，不把旧计划伪装成今日计划。
- `processing`：异步 AI 任务展示当前阶段和可离开性，不伪造百分比。

## 8. 视觉验收

- 从 5 米外看页面，仍能识别当前页的一个主任务。
- 隐藏所有颜色后，信息层级仍靠字号、布局和留白成立。
- 任一工作区连续三张白卡均不能看起来像管理后台。
- 做题页首屏不显示分差、岗位和商业信息，只服务阅读与作答。
- 所有 AI 结论有“依据”入口，所有用户确认有反向修改入口。
- 390 px 宽度无水平滚动、主要按钮无文字截断、长题干无卡片套嵌。
