# AI 国考上岸教练：产品体验总架构

> 状态：商业化产品体验基线  
> 日期：2026-07-12  
> 作用：约束页面、题目渲染、材料阅读、申论、报告、AI 陪伴和后端 ViewModel，禁止逐页临时发挥

## 1. 总体定义

产品不是“题库 + AI 对话”，而是一套围绕目标岗位持续运行的备考操作系统。

```text
用户与目标
  ↓
共享学习大脑（资格、成绩、错因、时间、情绪、证据）
  ↓
岗位 Agent ── 规划 Agent ── 解题 Agent
  ↓              ↓              ↓
岗位决策        今日任务       作答/复盘/验证
  └────────── 统一写入证据与掌握状态 ──────────┘
                         ↓
                   报告与下一步行动
```

任何页面必须回答以下至少一个问题：

1. 我现在在哪里？
2. 为什么系统这样判断？
3. 我现在最该做什么？
4. 做完后，系统对我的理解发生了什么变化？

## 2. 六层体验架构

### L1. 产品外壳

- 四个底部域：今日、训练、岗位、我的。
- 全局解释入口不占用第五个 Tab；当前使用中性入口，岸岸形象在最后阶段接管表现。
- 页面级导航统一处理返回、标题、进度、同步状态、关闭任务。
- 模考和长时申论进入专注外壳，隐藏日常导航。

### L2. 工作区

| 工作区 | 核心对象 | 首要行动 |
|---|---|---|
| 今日 | 当日计划 | 开始下一项任务 |
| 训练 | 题组、错题、复测、模考、申论 | 进入训练闭环 |
| 岗位 | 资格、岗位、目标分、风险 | 确认目标组合 |
| 我的 | 学习档案、岸岸、权益、隐私 | 查看和修正系统理解 |

### L3. 任务容器

统一承载专项练习、复测、模考、申论、复盘，不让每种任务自建一套框架。

任务容器必须提供：

- `taskId`、任务类型、目标、验收条件、预计时长。
- 当前题/材料/作答进度。
- 暂停与退出策略。
- 草稿、标记、信心度、跳过轨迹。
- 自动保存与恢复位置。
- 提交后的复盘、AI 候选结论和验证任务。

### L4. 内容渲染器

内容渲染器只负责忠实呈现题目、材料和作答控件，不直接做规划判断。

- 客观题渲染器。
- 复合材料渲染器。
- 图片/图形渲染器。
- 申论材料渲染器。
- 申论作答编辑器。
- 解析与证据渲染器。

### L5. 智能层

- 全局解释路由：根据页面对象、任务阶段和问题意图选择领域 Agent，本身不生产领域事实。
- 岗位 Agent：资格、冲稳保、目标分区间、岗位变更影响。
- 规划 Agent：收益/时间/掌握窗口/情绪负荷，生成每日任务。
- 解题 Agent：方法讲解、复盘追问、候选错因、变式验证。
- 三个 Agent 只通过共享学习大脑交换结论，不直接互相覆盖数据。
- AI 推断先写入候选结论；需要用户确认或新作答验证后，才能升级为稳定画像。

### L6. 证据与审计

每个结论必须能回到：

- 原始题目版本。
- 用户原始答案与修改轨迹。
- 用时、信心、跳过、标记。
- 用户自己的复盘表达。
- AI 候选错因与用户确认。
- 即时变式、首次复测、延时验证。
- 算法/提示词/规则版本。

## 3. 页面与状态总图

### 3.1 页面家族

```text
A 身份与建档
B 今日与规划
C 客观题训练与掌握
D 岗位决策
E 学习档案与岸岸
F 模考、申论与商业
```

页面不是唯一设计单位。正式设计单位是：

```text
Page = Shell × Mode × ContentType × TaskState × DataState × AIState
```

例如“材料题作答页”至少有：专项训练/复测/模考 × 文字/表格/图形 × 未作答/已选择/标记/跳过 × 在线/离线同步中。

### 3.2 全局状态维度

| 维度 | 状态 |
|---|---|
| 任务模式 | 针对训练、首次复测、延时验证、标准模考、外部模考复盘 |
| 作答状态 | 未作答、已选择、修改过、不会、跳过、标记争议、已提交 |
| 时间状态 | 正常、接近建议时长、超时、暂停、后台恢复 |
| 内容状态 | 单题、共享材料题、长材料、表格、图片、材料缺失、版本更新 |
| 同步状态 | 已保存、保存中、待同步、冲突、恢复成功 |
| AI 状态 | 不介入、等待用户复盘、生成候选、待确认、证据不足、已验证 |
| 掌握状态 | 未知、暴露问题、初步理解、首次复测通过、延时稳定、再次回退 |

### 3.3 全局提问的页面策略

| 页面场景 | 可问范围 | 回答 owner | 限制 |
|---|---|---|---|
| 今日任务 | 为什么安排、如何完成、与目标的关系 | 规划 Agent | 调整计划需预览并确认 |
| 岗位与资格 | 条件原文、待确认项、目标分证据 | 岗位 Agent | 不通过对话直接改资格或主目标 |
| 专项/复测作答前 | 题意澄清、界面和作答规则 | 解题 Agent | 不泄露答案、排除结论或针对性方法 |
| 专项/复测提交后 | 方法、选项依据、错因、变式 | 解题 Agent | 错因仍需用户确认 |
| 模考交卷前 | 界面、计时、交卷和故障帮助 | 确定性帮助系统 | 不调用解题模型，不检索当前题解析 |
| 申论提交前 | 题目要求、材料操作和形式规则 | 解题 Agent | 不显示参考要点、范文或定向改写 |
| 报告/学习档案 | 指标口径、证据、变化原因和下一步 | 相应领域 Agent | 不把解释本身写成新能力证据 |
| 账户/支付/隐私 | 功能解释和当前状态 | 确定性帮助系统 | 不通过自由对话发起支付、退款或删除 |

入口在每个普通页面可见；专注作答页使用顶部小工具入口，不悬浮遮挡题干。被策略限制时仍允许用户提问，但返回可提供的帮助范围和解锁条件，不伪装成网络错误。

## 4. 岸岸角色系统

### 4.1 角色原型

当前岸岸以“来自数据河流的水獭伙伴”作为**概念候选**，用于验证陪伴场景，不是已冻结的最终形象。最终角色在所有核心页面、异常状态和付费边界完成后统一设计。水獭候选成立的原因：

- 名字与“上岸”天然相关。
- 水獭会整理和收藏物品，对应整理错因与证据。
- 既能陪伴，也不天然幼稚或权威。
- 身体轮廓适合缩成头像、做半身提示，也适合后续轻动画。

### 4.2 固定识别

- 深空蓝紫毛色，不采用真实棕色写实动物。
- 胸前是青色“上岸坐标”光点。
- 尾巴形成轻微的轨道弧线，继承现有品牌轨道语义。
- 眼睛不使用夸张星星眼；表情依靠眉眼、耳朵、身体姿态表达。
- 小尺寸只保留头、耳、眼、胸前光点四个特征。

### 4.3 六个标准状态

| 状态 | 姿态 | 使用场景 | 禁止文案 |
|---|---|---|---|
| 陪伴 | 正视、轻呼吸 | 今日首页、空状态 | “主人”“打卡赢奖励” |
| 思考 | 托住资料片、尾部轨道转动 | AI 分析、生成计划 | 假进度百分比 |
| 提醒 | 一只手抬起、目光明确 | 超时、资格待确认 | 恐吓和羞辱 |
| 鼓励 | 身体前倾、胸前光点变亮 | 完成闭环、验证通过 | 夸大“你已掌握” |
| 休息 | 抱住漂浮垫、闭眼 | 恢复日、疲劳降负 | 制造连续打卡焦虑 |
| 劝退 | 收起笑容、摊开收益对比 | 建议放弃低收益题 | “你不行”“别学了” |

### 4.4 尺寸与出现规则

| 尺寸 | 用途 | 信息量 |
|---|---|---|
| 28–36 px | 列表、消息来源 | 头像轮廓 |
| 48–72 px | AI 判断、反馈卡 | 半身 + 单一姿态 |
| 120–180 px | 首页/空状态/休息日 | 全身 + 环境光 |
| 220 px 以上 | 仅品牌启动或角色故事 | 完整场景 |

做题读题首屏不出现大形象；岸岸只在提交后、暂停、超时或需要复盘时进入。

在最终定稿前，业务页面只依赖 `CompanionIntent` 和尺寸占位契约，不依赖水獭轮廓、固定动作、颜色或台词。

## 5. 客观题内容模型

### 5.1 统一题目 Schema

```ts
type QuestionViewModel = {
  questionId: string;
  version: string;
  module: "verbal" | "judgment" | "data" | "quantity" | "knowledge";
  mode: "practice" | "retest" | "mock";
  stem: RichContentBlock[];
  sharedMaterial?: MaterialViewModel;
  inlineAssets?: AssetViewModel[];
  options: OptionViewModel[];
  answerMode: "single" | "multiple" | "numeric" | "ordering";
  suggestedSeconds?: number;
  tools: ToolPermission[];
  source: SourceViewModel;
};
```

富内容块必须支持：段落、加粗、下划线、公式、行号、表格、图片、图例、脚注和无障碍替代文本。

### 5.2 题型矩阵

| 题型 | 材料形态 | 阅读行为 | 特有工具 |
|---|---|---|---|
| 言语单题 | 单段/多段文本 | 选中文句、标记转折 | 关键词标记、字号 |
| 篇章阅读 | 一份材料对应多题 | 保留阅读位置、题间切换 | 材料题号导航 |
| 判断图形 | 单图/宫格/分类图 | 点击放大、黑白高对比 | 画线、旋转仅训练可用 |
| 定义/逻辑判断 | 长文本 + 条件 | 标记条件、排除选项 | 条件清单、排除线 |
| 资料分析 | 文字 + 表格/图表 | 材料与题目反复对照 | 表格放大、行列聚焦、草稿 |
| 数量关系 | 文本 + 公式 | 记录中间过程 | 草稿、公式输入；不提供计算器 |
| 常识判断 | 文本/图片 | 快速作答 | 无辅助推导工具 |
| 复合材料题 | 共享材料 + 5 题 | 题间共享材料状态 | 材料抽屉、题号导航、定位锚点 |

## 6. 材料阅读器

### 6.1 手机布局

小程序不使用桌面式左右固定分栏。采用三种状态：

1. **题目优先**：题目占主屏，顶部材料条显示标题、已读位置和“查看材料”。
2. **材料抽屉**：从底部升起至 72% 高度，题目仍保留在背景，支持半屏对照。
3. **材料全屏**：长文、复杂表格、图表进入全屏阅读；关闭后回到原滚动位置。

平板或横屏可以启用 44/56 双栏，但不是手机默认形态。

### 6.2 材料导航

- 材料段落有稳定锚点：材料 1、材料 2、表 1、图 1。
- 共享材料题切题后保留材料滚动位置和缩放比例。
- 点击解析引用时返回对应材料锚点，而不是只显示一段复制文本。
- OCR 材料必须保留原图入口；识别置信度低的区域标记出来。

### 6.3 表格与图表

- 首屏显示等比预览和关键列，不把 8 列表格压成不可读小字。
- 点击进入可缩放视图，首列/表头可冻结。
- 行列聚焦仅改变视觉高亮，不改原始数据。
- 单位、时间口径、注释始终与图表同屏。
- 训练模式可长按复制数值到草稿；模考模式禁用。

### 6.4 阅读标注

- 训练模式：高亮、下划线、圈条件、写短注。
- 模考模式：仅提供接近纸笔的高亮和排除，不显示 AI 提示。
- 所有标注自动保存到当前作答证据，不写回题库原文。

## 7. 做题页工具系统

### 7.1 常驻工具

- 题号/进度。
- 已用时间与建议时长提示。
- 答题卡。
- 材料入口（有材料时）。
- 标记本题。
- 不会/跳过。

### 7.2 工具抽屉

| 工具 | 训练 | 复测 | 模考 | 规则 |
|---|---:|---:|---:|---|
| 草稿板 | ✓ | ✓ | ✓ | 本地自动保存，支持清空确认 |
| 排除选项 | ✓ | ✓ | ✓ | 再点恢复，记录排除轨迹 |
| 关键词标记 | ✓ | ✓ | ✓ | 不提供 AI 自动标注 |
| 字号/行距 | ✓ | ✓ | ✓ | 记住用户偏好 |
| 深色/护眼 | ✓ | ✓ | ✓ | 图表保持原始配色可辨识 |
| 公式卡 | 提交后 | 提交后 | × | 不能在作答前泄露方法 |
| 计算器 | × | × | × | 对齐真实国考条件 |
| 问岸岸 | 提交后 | 提交后 | × | 模考交卷前不介入 |

### 7.3 退出与恢复

- 专项训练退出：自动保存当前题、材料位置和草稿。
- 模考退出：明确提示计时是否继续，二次确认。
- 意外后台：恢复后显示离开时长，不能静默篡改作答用时。
- 多端冲突：保留最新完整作答并展示冲突详情，不自动拼接答案。

## 8. 客观题反馈与复盘

### 8.1 即时反馈层级

1. 对错、正确答案、是否超时。
2. 一句核心方法，不直接铺满完整解析。
3. 选项级排除依据。
4. 材料引用锚点。
5. 用户复盘。
6. AI 候选错因。
7. 变式验证。

### 8.2 必须区分的结果

- 真会且正确。
- 蒙对。
- 方法正确但计算错。
- 方法错误但碰巧得到正确答案。
- 超时后做对。
- 主动放弃且策略正确。
- 题目/答案/材料存在争议。

“正确”不能直接等于“掌握”，“放弃”也不能直接等于“错误”。

## 9. 申论工作台

### 9.1 申论任务结构

```text
任务说明
  → 材料阅读与标注
  → 题目要求拆解
  → 提纲/找点
  → 正文作答或手写 OCR
  → 用户自检
  → AI 评阅
  → 重写
  → 新材料迁移验证
```

### 9.2 材料工作台

- 材料目录：材料 1–N、每则字数、已读状态。
- 标签体系：问题、原因、影响、对策、案例、观点；用户可自定义短标签。
- 高亮必须能反向定位到材料原句。
- 题目要求常驻顶部：身份、任务、范围、字数、文体。
- “我的找点”与“AI 参考要点”严格分层；提交前不显示 AI 参考。

### 9.3 作答编辑器

- 字数实时统计，临近上限提醒，不强制截断。
- 支持段落、序号和纯文本，不做富文本排版游戏。
- 自动保存版本，展示最后保存时间。
- 手写 OCR 保存原图、识别文本和用户修订记录。
- 可将材料标注拖入提纲，但正文必须由用户组织。

### 9.4 评阅结构

- 分数只给区间和置信度，不伪装精确人工评分。
- 四类图表：要点覆盖、结构、表达、要求遵守。
- 每条评价引用用户原句和材料证据。
- 区分“本篇修改成功”和“能力已经迁移”。
- 重写页提供原稿/新稿差异，但不替用户整篇代写。

## 10. 报告与图表系统

### 10.1 图表选择规则

| 用户问题 | 图表 | 不使用 |
|---|---|---|
| 分数是否提高 | 带置信区间的趋势线 | 单个大数字 |
| 模块差距多大 | 横向子弹图/目标线 | 雷达图 |
| 时间花在哪里 | 堆叠条形图 | 饼图堆叠过多分类 |
| 哪类错误重复 | 错因热力矩阵 | 标签云 |
| 速度与正确率关系 | 四象限散点图 | 双轴混合图 |
| 掌握是否稳定 | 三阶段验证阶梯图 | 简单完成率圆环 |
| 岗位分差如何构成 | 分差瀑布图 | 只显示“差 11 分” |
| 一周任务是否可执行 | 日历热力 + 完成轨迹 | 连续打卡火焰 |

### 10.2 报告层级

1. **结论层**：本次发生了什么，下一步是什么。
2. **图表层**：趋势、分布、差距、置信范围。
3. **证据层**：具体题目、材料、复盘、时间轨迹。
4. **行动层**：加入计划、开始复测、调整岗位或确认信息。

### 10.3 报告类型

- 单次题组报告。
- 错因专项报告。
- 周报告。
- 自有标准模考报告。
- 外部模考趋势报告。
- 申论单题评阅报告。
- 岗位分差报告。
- 学习大脑全局报告。

## 13. 前后端 ViewModel 边界

- 后端返回语义状态和内容，不返回颜色、圆角、像素坐标。
- 前端不根据文案猜状态；必须有显式枚举。
- 每份题目和材料必须有版本号、来源、更新时间和校验状态。
- 图表接口返回原始序列、口径、置信度和推荐图表语义，前端统一渲染。
- 岸岸状态由 `companionIntent` 控制，文案与姿态分离。
- 自动保存返回 `revision`，解决多端和后台恢复冲突。

## 14. 开发验收门槛

### 内容

- 文字、表格、图形、共享材料、长申论材料均有真实长度样例。
- 题干 1 行、8 行、20 行都不破坏主要操作。
- 表格 3 列、8 列和带合并表头均可阅读。
- 图片加载失败不丢失题号、来源和异常上报入口。

### 交互

- 材料抽屉开合后保持阅读位置。
- 切题后保留共享材料缩放和锚点。
- 草稿、标记、排除、答案修改全部可恢复。
- 模考模式不会暴露解析、公式卡或岸岸提示。

### 报告

- 所有图表带标题、口径、时间范围、单位和无障碍摘要。
- 图表即使不看颜色也能区分序列。
- 结论可回到具体证据，证据可回到原题和材料位置。

### 岸岸

- 六种标准状态均有 28、56、144 px 适配版本。
- 动画可关闭，低性能设备使用静态关键帧，不改变语义。
- 做题读题首屏不遮挡内容，不以情绪动画打断用户。
