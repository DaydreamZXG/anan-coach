# UI 文案规范（考公搭子）

> 2026-07-22 制定。起因：本轮 UI 文案审计发现不少界面把系统机制直接写给用户。本文档是防回归标准。

## 一句话原则

**写给考生看，不写给系统看。** 用户关心的是题、分、计划、进步；系统怎么实现，与用户无关。

## 五条红线

1. **禁止机制暴露**：不出现服务端、数据库、事务、任务队列（job）、断点、投影、回执等实现概念；需要表达版本时说"这次记录""上一版""已确认的内容"。
2. **不删产品边界**：隐私、退款、录取概率、成绩用途、AI 不保证结果、过期数据、用户确认这些边界必须保留，只换成人话表达。
3. **禁止生造名词**：投影、证据语义、门禁、指数、策略组合等自造概念不上界面。度量指标用大白话（"综合表现分"而非"平衡表现指数"）。
4. **禁止术语直出**：错误码、枚举值（legacy_result_unavailable）、技术缩写（LaTeX、OCR）不出现在用户界面。OCR→"拍照识别"，LaTeX→"公式"，错误码只进日志。
5. **说明文 ≤ 30 字**：超过就砍。先说"对你意味着什么"，不说"系统会做什么"。

## 不能为了好听而删掉的边界

- 分数线、目标分、岗位分差只能表达为备考参考，不得写成录取概率。
- 往年成绩只用于定位，不直接跨年计算提分，也不参与退款或现金奖励。
- 资料、讲义、笔记只用于本人学习分析；不用于训练基础模型，不跨用户复用。
- AI 结论必须允许用户确认、修改或拒绝；不要写成系统已经替用户做出事实判断。
- 支付、退款、删除、授权和数据导出必须说清楚会发生什么，不能用温柔文案糊过去。

## 术语替换表

| 工程师腔 | 用户语言 |
|---------|---------|
| 学习证据 / 能力证据 / 证据链 | 学习记录 / 进步记录（或直接删） |
| 服务端权威版本 | 最新记录 / 最新数据 |
| （内容/题面）版本 | 这份 / 本次（"原来的答案还留着"） |
| 断点 | 上次的进度 / 做到这里 |
| 冻结 / 固定题面 | 定好的卷子 / 题目已定 |
| 门禁 | 还没解锁 / 先完成前置 |
| 写入（证据/画像） | 保存 / 计入 |
| 会话 | 这场 / 本次 |
| 不可变 / 权威 / 幂等 / 事务 / 回执 | 已保存 / 已确认 / 这次记录 |
| 生成新版本 | 单独保存一份 |
| 确认版本 / 已确认 | 你确认过的 |
| 能力画像 | 能力分析 / 你的水平 |
| 错因 | 错因（可用，已是业务词）但"错因归类"→"帮你归类" |
| 曝光控制策略 | （删） |
| 平衡表现指数 | 综合表现分 |

## 语气（沿用 PRD §4.8）

- 温和但明确：不羞辱、不鸡血、不无原则安慰。
- 岸岸口吻像师哥师姐：说"帮你""陪你"，不说"系统将""平台有权"。
- 空状态 = 引导下一步，不堆机制（"做几次题就有了" > "暂无数据"）。
- 错误状态 = 说怎么办，不说哪里坏了（"没连上，点重试" > "服务端返回冲突版本"）。

## 示例对照

| 原文（已废弃） | 改后 |
|---------------|------|
| 一次提交会在同一事务中写入作答、结构化复盘，并完成对应的今日申论任务 | 提交后保存答案和复盘，今天的申论任务就完成了 |
| 页面重载后会从已确认的作答、答案或评阅 job 继续，不会重新造一条证据链 | 中途退出也不怕，回来接着写 |
| 绑定本场会话、题目与固定内容版本，不上传你的答案或草稿 | 报错只带题目信息，不带你的答案 |
| 该报告存在证据缺口，已有结论按部分状态展示，不会填充假数据 | 这份报告数据不全，只展示已有的部分 |
| 服务端已按冻结事实合同评分 | 这次练习已出分 |

## 执行方式

- 新增/修改 UI 文案时对照本规范自查；code review 拦截工程师腔。
- 关键词黑名单（CI 可加 grep）：`服务端|断点|证据链|门禁|同一事务|写入器|权威版本|原命令|谱系|不可变回执|投影` 出现在 wxml 属性文案或文本节点时应告警；内部错误、测试和开发文档不按 UI 文案处理。
