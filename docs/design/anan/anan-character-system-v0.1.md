# 岸岸角色系统 v0.1

> 状态：方向已批准，角色母版制作中
> 日期：2026-07-14
> 适用：微信小程序岸岸角色系统；未来 Codex v2 桌宠派生

## 1. 决策分层

### 1.1 已确认

- 名字：岸岸。
- 角色类型：成长型伴宠，不是官场 NPC，也不是独立业务 Agent。
- 物种：奶牛猫；水獭方向退役。
- 核心轮廓：成年健康比例的小肥猫，圆润但能跑、跳、扑和抬爪。
- 识别花纹：深海军蓝与暖白的不对称奶牛花纹；脸部深色块必须跨尺寸稳定。
- 眼睛：暖金色，负责大部分注意力和情绪方向表达。
- 品牌识别：软灰项圈 + 青色坐标灯；不是奖章、等级条或付费饰品。
- 视觉媒介：现代 2.5D；柔和哑光、轮廓干净、毛发成块，不做写实宠物摄影或毛绒玩具。
- 性格：主动、好奇、有点憨、偶尔管人；不能高贵疏离，也不能只有克制待机。
- 招牌微表情：自然的小吐舌 `blep`，只在合适动作中偶发，不是永久脸。
- 成长：四阶段、不可倒退；不使用喂食、XP、连续打卡惩罚、掉级、疾病或付费解锁。

### 1.2 待母版确认

- 最终阶段的精确头身比、腹部宽度与爪子尺寸。
- 正面与背面的稳定花纹地图。
- 项圈坐标灯的四阶段图形与亮度范围。
- 小吐舌的最大尺寸和出现频率。
- 28 px 头像是否保留项圈灯，或只保留脸部花纹与金色眼睛。

### 1.3 后续建议，尚未批准

- 招牌动作候选：歪头抬爪、小吐舌招呼、低身找线索、原地小跳、伸爪轻拍、翻肚皮休息。
- 声音只使用轻量非语言反馈；不为岸岸设计持续叫声或拟人配音。
- 四阶段成长同时表现身体成熟、关系熟悉和动作开放度，不通过换装表达。

## 2. 角色使命与边界

岸岸将岗位、解题和规划 Agent 的结论转成用户能理解、能执行、愿意继续面对的解释。岸岸可以有鲜明反应，但不能制造结论、替代证据或把不确定性包装成安慰。

### 必须做到

- 让用户感到它记得目标、错因、时间和当前压力。
- 在关键节点主动靠近：计划解释、提交后复盘、长期卡点、恢复日与空状态。
- 通过身体语言区分“正在想”“需要你确认”“这次值得开心”“今天应该休息”。

### 禁止

- 用可爱遮盖资格风险、题目争议、付费边界或证据不足。
- 在做题阅读首屏展示大形象或持续高频动画。
- 用生病、失望、饥饿、离家出走等负罪感机制推动学习。
- 建立喂食、忠诚、稀有度、抽取、服装收集或功能解锁经济。

## 3. 四阶段成长

| 阶段 | 角色变化 | 关系变化 | 触发原则 |
|---|---|---|---|
| 初遇 | 偏年轻、体型较小、姿态收拢；项圈单点 | 观察用户，不假装理解 | 完成基础建档并认识岸岸 |
| 熟悉 | 脸颊与身体更圆，开始主动抬爪与吐舌 | 记住已确认偏好和第一批证据 | 完成真实学习闭环并形成可引用记忆 |
| 默契 | 达到小肥猫主比例，动作更大胆 | 能预判常见卡点，但仍说明依据 | 多次稳定复盘、复测与计划回流 |
| 并肩 | 身体不再放大，姿态与坐标灯更完整 | 在冲刺与低谷中保持稳定表达 | 达到版本化、可解释的长期关系条件 |

成长条件必须由独立、可审计的关系状态契约定义；不能从连续打卡天数、付费金额或刷题数量直接推导。任何阶段都不降低既有专业功能，也不因断更而倒退。

## 4. 表情与动作语言

岸岸的情绪优先级为：眼睛与眼睑 → 耳朵方向 → 头部角度 → 尾巴 → 爪子 → 身体压缩或伸展 → 嘴部。吐舌和张嘴只作为低频强调，不能代替完整身体语言。

| 语义 | 核心动作 | 强度边界 |
|---|---|---|
| 陪伴 | 歪头、抬爪、尾尖轻摆 | 可以主动招呼，不持续跳动 |
| 思考 | 低身、耳朵分向、眼睛追踪、尾巴问号 | 不显示假进度或漂浮问号 |
| 提醒 | 坐直、直视、伸爪轻拍 | 可以有点“管人”，不恐吓 |
| 鼓励 | 小跳、双爪抬起、尾巴高举 | 不用礼花、奖杯或夸大掌握 |
| 休息 | 猫饼、翻肚皮、慢眨眼、舌尖露出 | 不制造断更焦虑 |
| 降权建议 | 收起笑容、身体靠近、目光明确 | 不使用失败、嫌弃或离开动作 |

## 5. 与 UI 的关系

- 28–36 px：来源头像和消息标识，优先保留脸部不对称花纹、耳朵和金色眼睛。
- 48–72 px：AI 判断、反馈与复盘卡，可显示半身和单一动作。
- 120–180 px：首页、空状态、恢复日与阶段成长，可显示全身动作。
- 220 px 以上：仅角色介绍、成长回顾或品牌内容。
- 做题首屏不出现大形象；提交后、暂停、超时或复盘阶段才进入。
- 岸岸不替代错误、风险、支付、隐私或网络状态图标。

## 6. 无障碍与性能

- 动画关闭时使用每个语义动作的专门静态关键帧；这属于完整无障碍规格，不是质量降级。
- 语义不能只靠颜色；耳朵、眼睛、姿态和轮廓必须共同表达。
- 所有资源提供明确可访问性标签，描述角色状态而不是泛称“可爱猫咪”。
- 小程序资产独立制定帧数、图集、按需加载与包体预算，不套用 Codex `192×208` 单元格。
- Codex 桌宠在角色母版和动作矩阵批准后，使用 `hatch-pet` v2 完整流程单独制作与 QA。

## 7. 社区边界

岸岸若出现在方法卡社区，只能引导“对我有用”投票和固定结构化反馈；不得引导或承载用户自由文字评价。
