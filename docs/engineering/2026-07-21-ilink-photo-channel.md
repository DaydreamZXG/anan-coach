# 岸岸官方 iLink 拍题通道

## 结论

本发布单元实现的是“小程序账户绑定后的第二入口”：用户在微信中给岸岸发送一张已经裁剪好的单题图片，服务端识别题面、只在当前授权范围内匹配题库，并返回带来源标签的答案或明确拒答。

工程实现不等于线上已激活。轮询工作进程默认关闭；官方机器人凭证、HTTPS 识图发布版本、一套受审主答案模型和生产数据库迁移全部满足后才允许开启。

## 用户边界

- 只有已经登录小程序并用一次性连接码绑定的微信发送者可以查询。
- 一名发送者同一时间只能绑定一个岸岸账户；服务端只用 HMAC 指纹查询，原始发送者 ID 加密保存，不返回小程序。
- 查询只形成弱兴趣和查询历史，不写入正确率、掌握度、错因或能力画像。
- 回复“收录”后，题目进入本人私有收录，状态明确显示“已收录 · 暂不计入能力”。
- 回复“重做”后，状态明确显示“待重做 · 暂不计入能力”。这个发布单元只拥有持久化待重做队列，不伪造独立作答证据；将它编入今日计划并完成真实作答属于后续独立发布单元，在该消费者上线前不得宣传“已自动安排训练”。
- 回复“删除”会清除最近一次查询和收录里的题面、解析、模型来源和直接引用。
- 回复“存资料”后，最近一张已答复图片转入本人私有阅读室摄取（复用 private_knowledge
  的上传产物与待核对识别修订），状态为“待核对”。小程序内核对确认前不生成检索片段；
  该指令按查询幂等（重复回复返回同一回执），并写入命令回执与无内容事件审计。
- 发送“今天练什么”（等价词：今天学什么/今日安排）只返回当日计划的只读投影摘要
  （标题、任务数、总分钟）与小程序入口文案；无计划时按“先定目标/先确认时长/未就绪”
  三分支回复。该查询不产生任何写操作，也不展示分差等能力数据。
- 图片、识别文字和答案禁止进入公共题库，也禁止用于模型训练。

## 回答来源

每条成功回复固定包含“答案、解析、来源、状态”：

| 来源 | 行为 |
| --- | --- |
| 题库授权原题 | 展示当前用户有权读取的版本和授权快照对应解析 |
| 相似题参考 | 明确标成相似参考，不冒充原题 |
| AI 候选 | 题库未命中时由受审主模型生成，并明确不是官方答案 |
| 匹配存在歧义 | 不选择其中一个，提示补拍题号、材料标题或完整选项 |
| 缺少共享材料 | 对申论、资料分析等依赖共享材料的题目拒绝猜测 |

任何未授权题库内容都不会因为“命中了”就返回；未命中时只把主模型输出标为 AI 候选，不包装成题库或官方答案。

## 官方协议基线

实现按腾讯官方 `@tencent-weixin/openclaw-weixin` 2.4.6 的公开行为固定：

- 上行长轮询：`ilink/bot/getupdates`，游标使用 `get_updates_buf`。
- 下行回复：`ilink/bot/sendmessage`，原样回传本次消息的 `context_token`。
- API 固定为 `https://ilinkai.weixin.qq.com`；媒体固定为 `https://novac2c.cdn.weixin.qq.com/c2c`，禁止重定向和非白名单来源。
- 图片使用官方媒体字段，支持官方出现的两种 AES key 编码，按 AES-128-ECB + PKCS7 解密。
- 请求头固定使用 `AuthorizationType: ilink_bot_token`、`Authorization: Bearer ...`、`X-WECHAT-UIN`、`iLink-App-Id` 和 `iLink-App-ClientVersion`。
- `errcode=-14` 视为凭证失效，清除本地轮询游标并停止工作进程，必须重新扫码；不会带着旧游标继续请求。
- 发送超时属于结果不确定，记录为 `uncertain`，不自动重发，避免用户收到两份答案。

## 官方扫码取凭证

岸岸不安装、启动或依赖 OpenClaw 主程序。运行时只复用腾讯官方 `@tencent-weixin/openclaw-weixin` 2.4.6 公开的 iLink 协议行为，并用机器可读锁定文件校验 npm integrity、tarball SHA-256、关键源文件哈希、包身份和协议常量。

每次升级或取证前，先在隔离的运维终端验证锁定上游：

```bash
backend/.venv/bin/python ops/verify_ilink_upstream.py
```

校验通过后，用岸岸的独立取证命令申请一次性二维码：

```bash
backend/.venv/bin/python ops/ilink_login.py --output ~/.anan/credentials/ilink.json
```

命令会在本机默认浏览器打开腾讯签发的 HTTPS 扫码页，不在终端输出二维码 token、bot token 或原始凭据。用准备作为岸岸入口的微信扫码并在手机确认；若微信要求数字验证，终端以不回显方式读取。

凭据只能原子写入仓库外、无符号链接、权限为 `0600` 的新文件；已有目标绝不覆盖。通过生产密钥管理流程把文件中的 `account_id`、`bot_token` 分别注入 `ILINK_BOT_ACCOUNT_ID`、`ILINK_BOT_TOKEN`，然后安全销毁本地文件。不得把凭据复制进仓库、命令历史、部署包或工单正文。

一个 bot 账户只能有一个长轮询消费者：凭据转入岸岸工作进程后，不得再让其他程序消费同一账户。

微信开放文档中的 `WeKnoraGateway` ClawBot 接口位于知识库/AI 网关产品下，使用 WeKnora AppID 与 Secret-Key。它能把 WeKnora 知识问答接到微信通道，但不是独立、通用的原生 iLink 协议合同；岸岸不以它作为当前 iLink 运行时或凭据签发依赖。

## 数据生命周期

- 收到图片后只在内存解密，并以私有 ACL、服务端加密写入 TOS 的 `private/ilink/` 前缀。
- 答复完成后，私有图片只在 `ILINK_TRANSIENT_RETENTION_SECONDS` 的转存窗口内保留，供用户回复“存资料”转入私有阅读室；窗口到期由维护任务把对象加入可靠删除队列，回复“删除”也会立即入队。处理超过同一窗口的中断任务会失败关闭并把对象加入可靠删除队列。
- 回复“存资料”把对象所有权转移给私有阅读室工件（`learning.source_artifact_versions`），此后随私有资料删除流程管辖，不再由通道删除队列处理。
- `context_token` 只加密保留到终态回复，发送成功或结果不确定后立即清除。
- 未收录查询超过 `ILINK_QUERY_RETENTION_DAYS` 后清除识别文字、答案、来源引用、图片指纹和回复 ID，只留防重放所需的无内容墓碑。
- 已收录内容保留到用户明确删除或账户删除；账户禁用触发数据库级清理，并把仍存在的私有对象加入删除队列。
- 导出不包含发送者 ID、bot token、连接码、HMAC、加密材料或 `context_token`。

## 生产激活清单

1. 部署代码并把 PostgreSQL 升级到 Alembic `20260721_49`。
2. 从 `ops/ilink-channel.env.example` 逐项注入生产密钥；AES-256 密钥和 HMAC 密钥必须来自密钥管理器。
3. 先校验腾讯上游锁，再用岸岸独立命令扫码取得专用 bot 账户 ID 和 token；通过密钥管理器注入，并确认没有第二个轮询消费者。
4. 发布并批准支持 JPEG、PNG 的 HTTPS 识图 processor route。候选地址已改为 `https://cpa.ergou.pro/v1`；TLS 与鉴权边界可达不等于处理器已经获批，仍要冻结实际模型、发布版本、零留存/训练禁用声明和场景审批。
5. 为主答案模型配置 HTTPS 白名单、发布版本、DPA/零留存、训练禁用、请求 ID 与幂等审计；题库命中路径不调用模型。
6. 跑协议、工作流、小程序和全仓回归；再把 `ILINK_CHANNEL_ENABLED` 从 `false` 改为 `true`。
7. 安装并启动 `ops/systemd/gongkao-dazi-ilink-worker.service`，观察无内容日志中的轮询、过期、删除队列和凭证失效指标。
8. 用两个真实测试账户验收：未绑定拒绝、绑定唯一性、跨账户隔离、精确/相似/歧义/缺材料、收录/重做/删除、存资料转存与幂等、转存窗口到期删除、今天练什么三分支、重复消息和发送超时。

## 当前线上阻断项

- 腾讯官方 2.4.6 上游锁、独立扫码流程和安全凭据文件已实现；尚未扫码并把 iLink bot 账户 ID/token 注入密钥管理器。
- Grok 地址的明文 HTTP 阻断已经消除；`https://cpa.ergou.pro/v1` 的实际模型、处理器发布版本和数据处理审批尚未冻结，所以识图仍保持关闭。
- 待重做队列还没有今日计划/独立作答消费者，不能宣传自动排进学习计划。

因此当前结论是：账户绑定、官方协议、拍题解析、来源标注、收录状态和删除生命周期已经具备工程实现；生产轮询仍必须保持关闭。
