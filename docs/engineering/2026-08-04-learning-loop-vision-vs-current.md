## 三、核心结论:你的"中控大脑"确实缺失(你的怀疑成立)

四个 agent 独立得出一致结论:**不存在一个同时掌握【目标+能力+错因+知识树】并主动推断"下一步怎么学"的中枢。**

现在是"伪中枢三件套",各管各的:

```
planning(排题)  ── 规则权重,读原始掌握度,不吃大脑
cause_agent(归因) ── 解释为什么错,喂进大脑
learning_brain(记账) ── 只读汇总 + 展示,不产出决策
companion(岸岸) ── 只读它们,转译成对话 + 预览动作
```

**最有力的证据**:
- `learning_brain` 唯一的"推断产物" `_knowledge_point_weaknesses` 注释自证"只读投影,不影响选题"(learning_brain/service.py:453-457)
- planning 域 **grep 不到任何 `LearningBrainService` 引用** —— 排题根本不读大脑
- `strategy_candidate` 表的 `producer_type=rule|agent` 字段**从无生产者** —— 唯一的策略候选是用户手填的(ability-module 页)

## 四、对照你的原图,断点在哪

对照你画的 mermaid,真正的"断"有 4 处:

1. **`X4 错因诊断 → X8 针对性训练` 断** — 错因码没喂回选题,针对性训练只是"模块级弱点"而非"错因级"
2. **`D 确定备考差距` 的"待验证弱项"缺** — 有目标分、有能力证据,但没有"弱项假设→验证→收口"
3. **`L 共享学习状态 → P 计划` 弱** — 共享状态是展示物,不驱动计划(planning 绕开它直接读原始数据)
4. **`岸岸 ↔ 中控大脑` 断** — 岸岸能读大脑、能预览改计划,但**没有大脑可对话**

## 五、中控大脑该放哪(建议)

不是新建一个域,而是**给现有三件套加一个"决策层"**:

```
                ┌──────────────────────────────┐
  目标分 ───────→│                              │
  能力估计 ─────→│   中控大脑(新增决策层)          │──→ 决定"下一步学什么"
  错因 ─────────→│   = 读 learning_brain 状态      │──→ 驱动 planning 排题
  知识树薄弱 ────→│   + 主动推断策略                │──→ 反馈岸岸解释
  模考/内场 ─────→│                              │
                └──────────────────────────────┘
                       ↑ 岸岸对话(用户反馈改计划)
```

**关键设计原则**(前面讨论定的):
- 大脑**推断策略**(用 agent),但**执行仍是确定性**的(planning 排题)——既灵活又可复现
- 大脑是"读"learning_brain 状态 + "驱动"planning,而不是替代它们
- 岸岸是大脑的"嘴",用户是最终裁决者(先预览再确认)

## 六、建议的落地顺序

1. **先补 3 个数据断点**(不需要架构决策,纯补齐):
   - 内场模考出分 → 更新能力估计(现在只出报告)
   - "待验证弱项"概念(错因 + 能力证据 → 生成弱项假设)
   - 错因码 → 喂回针对性训练选题
2. **再建中控大脑的决策层**(架构决策,需先设计):
   - 定"大脑读什么状态、产什么策略、怎么驱动 planning"
   - 岸岸接入:能对话"为什么这么排""我想改"
3. **最后把知识树接成"薄弱→选题"**(让树从"频次树"变"能力树")
