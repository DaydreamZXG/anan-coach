## 1. 冻结目标

按照已确认的产品体验总架构，交付一套可商业化、可测试、可观测、可持续演进的 AI 国考上岸教练：

- 知道用户是谁、能报什么岗位和目标分差。
- 记录行测、申论、模考和外部成绩的可信证据。
- 允许任务导出到纸笔/笔记 App，并将答案、答题卡、外部错题和申论手写稿可审计地接回学习大脑。
- 理解错因，但不把未经确认的 AI 推断写成用户事实。
- 根据时间、情绪、收益和掌握窗口生成每日计划。
- 用岗位、解题、规划三个 Agent 共享同一个学习大脑。
- 支持微信身份、权益、支付、隐私导出与完整删除。
- 所有高影响结论可追溯、可重算、可审计。

设计小问题进入设计债务清单，不随意改变页面结构、领域边界和核心状态机。只有影响可用性、正确性、合规或商业闭环的问题才能中断当前阶段。

### 1.1 行测—申论跨阶段并行不变式

“双轨”不是阶段 4 的规划功能，也不是阶段 5 再补一套申论页面，而是整个产品架构的强制维度：

- 证据、作答、复盘、掌握、能力估计、计划任务、报告和全局提问上下文都必须显式携带 `xingce` / `essay` 轨道；共享外壳不能抹平两科不同的证据链。
- 行测与申论分别拥有 canonical writer、版本历史、有效期和验证阶梯；任何一轨尚未发布 writer 时返回类型化 capability gap，禁止用 `0`、空数组或另一轨数据伪装可用。
- 岗位 Agent 只消费同一考试年度、当前有效且两科完整的正式能力区间；部分能力可以展示和引导补证据，但不能生成总分差、冲稳保或录取概率。
- 规划 Agent 独立生成两轨候选，再在同一容量预算中选择；申论不得是行测安排后的剩余时长，行测也不得因申论已有纵向切片而被视为已完成。
- 每一阶段都要列出双轨覆盖矩阵并分别验收 producer、consumer、状态、迁移和测试。某阶段只深化一轨时，必须建立在此前已发布的双轨公共合同上，且不得将“专项深化”描述成另一轨首次进入系统。

因此，阶段 5 是申论在既有双轨学习闭环上的专项深化，不是申论轨道的起点；当前已前置的申论纵向切片也不代表中间阶段或行测同层能力已经完成。

## 2. 交付定义

完成一个能力必须同时满足：

1. 产品页面完成默认、加载、空、部分数据、失败、过期和处理中状态。
2. 前后端契约版本化，客户端不根据文案猜业务状态。
3. 领域规则有单元测试，事务与用户隔离有 PostgreSQL 集成测试。
4. 主链有自动化端到端测试和关键页面视觉验收。
5. AI 场景有结构化输出、评测集、提示版本、成本记录和失败审计。
6. 日志、指标、request ID 和业务事件能定位线上问题。
7. 数据迁移、发布顺序、回滚方式和运维说明完整。
8. 文档与代码同一提交更新，不留下只存在于聊天中的决定。

## 5. 实施顺序

### 阶段 0：工程基座与架构护栏

目标：让后续每个功能进入同一工程体系。

交付：

- 调整小程序目录为目标分层，迁移现有 7 个页面，不复制旧实现。
- 建立正式设计 token、基础组件、岸岸组件和组件预览页。
- 建立 OpenAPI v2 生成链路、类型化 API 客户端和统一错误模型。
- 建立路由门禁、会话刷新、request ID、埋点和错误追踪。
- 建立小程序单元、组件、契约、端到端和视觉测试。
- 建立后端 v2 路由骨架、领域命令、outbox 和 job 基础设施。
- CI 执行小程序、后端、迁移、契约和静态检查。

门禁：

- 页面层没有直接网络请求。
- 手改生成代码会被 CI 拒绝。
- 任一请求能从小程序日志追踪到后端 request ID。
- 设计组件在 390 px、大字号和关键状态下通过视觉验收。

### 阶段 1：微信身份、资格与岗位目标

目标：系统先真正知道用户是谁、能报什么、目标在哪里。

交付：

- 微信登录、可撤销会话、账户恢复和登录拒绝处理。
- 资格事实模型、来源、确认、冲突和缺失项。
- 岗位查询、可报/待确认/不可报的确定性规则。
- 岗位详情、冲稳保组合、主目标版本和目标分区间。
- 岗位变更事件与对学习计划的影响预览。
- 建档 A01–A06、岗位 D01–D06 正式页面；D06 只在首次主目标确认后询问用户是否需要小白考情说明，不按账号新旧推断备考经验。

门禁：

- 客户端无法伪造 learner ID。
- 任一可报结论能回放所有硬条件。
- 硬条件缺失时不能展示已确认可报。
- 目标分展示样本、范围、证据等级和有效时间。

### 阶段 1.5：学习输入输出与外部摄入基座

目标：在做题运行时定型前，先建立纸笔、笔记 App、拍题和外部错题共用的数据边界。

交付：

- `source_artifact`、`recognition_revision`、`content_match`、`offline_packet` 和 `answer_ingestion` 版本化契约。
- 拍摄/PDF 上传、对象存储、去重、分题、OCR 和用户修订任务。
- 文本 + 视觉混合召回，精确命中/相似候选/AI 解题分层结果。
- 图形推理视觉指纹和申论完整性门禁。
- 基础 PDF 渲染、学习包码、答案串/答题卡回流和外部证据权重。
- 微信小程序“拍题/导入”、“我的学习包”和“录入答案”正式页面。

门禁：

- 未经用户确认的 OCR、原题匹配和外部答案不影响能力、错因或计划。
- 纸上作答与程序内作答使用不同证据等级，但回到同一复盘和验证状态机。
- 外部版权内容不进入跨用户题库或训练数据。
- 重试不重复计费，失败/不可用结果自动返还预留额度。
- 导出件的题目版本、顺序和答题卡能与回流结果完整校验。

### 阶段 2：统一任务运行时与内容渲染器

目标：完成所有训练、复测、模考和申论都能复用的稳定底座。

交付：

- TaskShell、任务恢复、自动保存和退出策略。
- 客观题富内容渲染器：文本、公式、图片、图形、表格。
- 共享材料阅读器：题目优先、72% 抽屉、全屏。
- 材料锚点、表格缩放/冻结、图片放大和 OCR 原图入口。
- 作答控件、草稿、排除、标注、字号、护眼、答题卡和争议上报。
- 全局提问容器、页面对象引用、会话恢复和专注作答小工具入口。
- 专项、复测、模考的工具权限矩阵。
- C02、C09–C14 和 F02 正式页面状态。

门禁：

- 真实长材料、8 列表格、合并表头和高分辨率图形均可用。
- 切题保留材料位置、缩放、草稿和排除轨迹。
- 模考交卷前不存在解析、公式卡或解题 AI 能力。
- 模考交卷前的全局提问只返回操作/故障帮助，服务端不检索当前题解析。
- 后台恢复不篡改用户用时。

### 阶段 3：双轨作答、复盘与掌握基础闭环

目标：让行测与申论都拥有可被学习大脑消费的 canonical 学习闭环；两轨共享状态语义和审计要求，但保留各自证据图。

交付：

- append-only 作答事件、题目版本和内容质量事件。
- 行测区分真会、蒙对、方法对计算错、超时和主动放弃。
- 申论固定完整材料、找点、提纲、原稿、结构化复盘、证据化评阅及用户确认版本。
- 用户原始复盘文字/语音和结构化标签。
- 解题 Agent 分轨产生候选错因/改进点、追问及用户确认或否定。
- 行测使用即时变式、1–3 天首次复测和 7–14 天延时验证；申论使用重写与新材料迁移验证，均进入版本化掌握阶梯。
- 轨道化掌握状态机与到期调度。
- C01–C08 行测闭环正式页面，以及申论基础执行链的正式状态与 writer。

门禁：

- 未确认 AI 归因不进入长期错误模式。
- 单次正确不标记稳定掌握。
- 题目争议确认后不污染能力和错因。
- 每个掌握状态能回放到具体轨道、作答/原稿、复盘和验证证据。
- 行测和申论任一轨缺少 canonical writer 时，规划与报告必须返回该轨 capability gap，不得宣称阶段完成。
- 单篇申论 AI 训练估分不能直接成为正式申论能力或岗位总分差。

### 阶段 3.5：社区方法卡共创与效果验证

目标：让用户沉淀真实解题思路，并用新题迁移证据而不是流量选出有用方法。

交付：

- 正式方法库与社区方法库的独立 owner、版本和派生发布关系。
- 方法卡显式标记行测/申论轨道、适用题型和验证合同；两轨分别统计效果，不共享裸分。
- 文字、语音、手写照片和错题复盘生成私有草稿，AI 结构后由作者逐项确认。
- 去重、版权来源、内容安全、知识节点和题库答案一致性的自动检查。
- 曝光、新题试用、延时复测、“对我有用”票、固定反馈信号和证据举报。
- 个性化效果排序、异常互投检测和自动限制状态机。
- 以 AI 场景额度/会员时长为首批载体的幂等奖励账本、封顶和撤回规则。
- C21 私有方法草稿、C22 AI 结构确认、C23 社区试用、C24 贡献与奖励页面。

门禁：

- 修改社区卡必须生成新版本，不继承旧版本的效果分。
- 未完成新题试用不能投有用票，作者和关联账户不计入独立样本。
- API、数据库和页面不存在用户评价文字、公开评论、回复、私信和外链字段。
- `trial` 卡不是解题 Agent 默认证据，也不是规划 Agent 的必做任务。
- 奖励不按上传数、流量或裸票数发放，支付不能影响排名或验证。

### 阶段 4：共享学习大脑、能力估计与规划 Agent

目标：让系统基于证据每天决定最值得做什么。

交付：

- 不可变证据、候选结论、派生画像和决策版本四层模型。
- 行测/申论区间估计、置信度、证据新鲜度和冲突处理。
- 时间预算、精力、压力和常规休息日。
- 规划优先级：岗位收益、能力收益、遗忘紧迫度、时间适配、负荷惩罚。
- 每日计划版本、依据、失效条件和重排原因。
- 5+1+1 周节奏、恢复日、任务不积债。
- B01–B05、E01–E05 正式页面。

门禁：

- 相同输入版本生成可重放的相同计划。
- 计划变化有事件原因和证据引用。
- 情绪只调整负荷，不覆盖能力证据。
- 战略放弃有范围、收益证据、有效期和复评日期。

### 阶段 5：申论深度训练与迁移工作台

目标：在阶段 2 的统一运行时和阶段 3 的双轨 canonical 闭环上，深化申论长材料交互、评阅质量、重写与跨材料迁移；不在本阶段才创建申论轨道。

交付：

- 材料目录、锚点、问题/原因/影响/对策标注。
- 找点、提纲、正文和字数控制。
- 手写图片、OCR 文本、原图与用户修订版本。
- AI 区间评分、置信度、评分维度和原句/材料证据。
- 原稿/重写差异与新材料迁移验证。
- F05–F07、F10–F12 正式页面。

门禁：

- 提交前不显示 AI 参考要点。
- 每条评语能定位用户原句和材料原文。
- 单篇修改成功不直接提高长期能力。
- OCR 低置信区域必须由用户确认。

### 阶段 6：模考、外部报告与图表报告系统

目标：建立稳定标尺和直观报告。

交付：

- 版本化标准卷、题目曝光控制和完整考试轨迹。
- 外部模考 OCR、字段确认、重复识别和证据等级。
- 置信区间趋势、模块子弹图、速度×正确率象限、错因热力、分差瀑布。
- 单次题组、周报、模考、岗位分差和全局学习报告。
- F01–F04、F13 正式页面。

门禁：

- 外部报告未经用户确认不进入能力估计。
- 图表都有口径、时间、单位、置信度和文字摘要。
- 自有标准卷评分版本可追溯。
- 报告结论能进入下一次计划，而不只用于展示。

### 阶段 7：AI 治理与成本系统

目标：先确保三个 Agent 的输出可评测、可校验、可计费，不让角色表现遮盖系统不确定性。

交付：

- CompanionIntent 与业务状态、自由文案和客户端资源解耦。
- 小/高能力模型路由、schema 校验、提示版本和评测集。

## 7. 维护策略

### 7.1 决策记录

以下改变必须增加 ADR：

- 领域 owner 或数据真相边界变化。
- 新增客户端、AI 供应商、支付渠道或对象存储。
- 掌握、计划、订单、异步任务状态机变化。
- API 不兼容变更。
- 引入新的跨域基础设施。

### 7.2 版本策略

- API：URL 主版本和 schema 向后兼容。
- 题目、材料、试卷、评分、提示词、规则和图表口径独立版本化。
- 数据库：Alembic expand/migrate/contract。
- 小程序：版本绑定 API 最低兼容版本和设计系统版本。

### 7.3 代码所有权

- 一个领域只有一个事实 owner。
- 跨域读取使用查询接口或事件投影，不直接更新其他领域的表。
- 公共组件进入设计系统前必须有两个以上真实使用场景。
- 页面私有样式不得覆盖全局 token。

### 7.4 债务管理

- design-debt：不影响主流程的视觉与动效问题。
- content-quality：题目、答案、材料、解析和 OCR 质量问题。
- architecture-debt：违反 owner、契约、测试或可观测性约束的问题，进入下一阶段前清零。
- operations-debt：迁移、告警、备份、成本和发布流程缺口，商业上线前清零。
