## 1. 结论先行

当前项目不是空壳：小程序、后端、数据库迁移、题库、岗位规则、AI 调用、报告、外部资料和数据权利已经有大量真实实现，生产服务也在运行。

但当前不能把“阶段 0–9 已完成”理解为产品已经交付。基线代码与刚确认的产品边界原有四个最高优先级冲突：

1. **行测仍以五模块为核心口径**，与产品负责人确认的六大模块冲突；现已在本地完成修正。
2. **用户仍能看到会员、购买与退款页面文案**，与公开免费冷启动冲突；现已在本地完成修正。
3. **申论多模型评分尚未接入正式批改链**；混元当前只允许合成连通探针。
4. **真实用户内容的外部处理边界未闭合**；当前 Grok 地址为明文 HTTP，Gemini/Grok 代理的训练、留存和删除规则尚无可核验处理方证据。

此外，AI 督学消息、MyScript、私人资料检索库、Obsidian 回流、跨设备编辑接管、学习分享卡和生产备份恢复仍缺少完整实现。

截至本文件最后更新，前两项已在本地闭合：服务端发布 `free_cold_start + unlimited`，公开商品与下单关闭；行测发布唯一六模块目录、六模块诊断与 135 题新模考口径，历史五模块证据保留原版本。生产仍停留在数据库修订 `20260718_37`，因此两项只有部署当前迁移头 `20260718_39` 后才在线上生效。

## 5. 开发顺序

每一步必须在自己的验收通过后再进入下一步，不把多个高风险领域一起改到无法定位。

### 步骤 1：让线上产品口径与最新决策一致（本地完成，待发布）

目标：先消除用户现在就能看到的错误承诺。

1. 建立服务端权威 `free_cold_start` 商业状态。
2. 个人页移除会员购买入口；会员页改为免费阶段说明或取消公开路由。
3. 支付与退款 API 保留代码但关闭公开商品和创建订单能力。
4. 点击审计移除虚拟支付旅程，增加“免费状态无购买入口”旅程。
5. 更新测试，确保任何客户端构造都不能在免费状态创建订单。

验收：

```bash
cd apps/wechat && npm run structure:check && npm run typecheck && npm run lint && npm run test
cd backend && .venv/bin/python -m pytest tests/test_stage8_commerce_privacy.py tests/test_stage8_virtual_payment.py
```

完成证据：

- 小程序 `npm run check` 全链通过：47 页、3 个 Tab、15 个共享组件、52 个视觉场景、74 个测试文件和 413 个测试。
- 后端 commerce 13 项、Stage 8 相关 19 项、申论/陪练/奖励跨模块 50 项通过。
- 免费模式继续记录调用次数与成本证据，但不以会员额度阻断；付费模式的正式额度状态仍可独立工作。
- 申论评阅意图持久化 `quota_access_mode`，不会把“无限制”伪装成一个虚构额度。
- 免费冷启动迁移为 `20260718_38`；叠加六模块发布后，当前迁移链唯一 head 为 `20260718_39`。

### 步骤 2：把行测五模块迁移为六模块权威契约（本地完成，待发布）

目标：诊断、题库、模考、能力、计划和报告不再各写一套模块列表。

1. 先盘点题库中第六模块“政治理论”的现有标签、题量、年份和旧常识归类。
2. 建立唯一 `GuokaoXingceModuleCatalog`，固定代码、显示名、适用年份和版本。
3. 新迁移只追加六模块发布版本，不直接篡改旧模考和历史能力证据。
4. 快速诊断、任务轮转、模考蓝图、报告和能力读取同一目录。
5. 旧五模块结果保留旧版本；需要比较时明确口径，不伪造第六模块历史分。

验收重点：六模块覆盖、旧结果可读、新结果不写五模块、报告不把缺失模块填零。

完成证据：

- 本地 36 份国考卷源文件已核对；2025 与 2026 标题的国考卷均明确分为政治理论、常识判断、言语理解与表达、数量关系、判断推理、资料分析六章。
- 源题库共有 878 道 `政治理论`；2025 与 2026 国考副省卷各有 20 道选项和答案完整的政治理论题。
- 核对发现导入库的 `question_type` 实际是“新思想/马克思主义/知识点”等知识分类，不是 `single_choice`；模考抽题现以客观题域、选项完整性和答案标签一致性判定可作答，不再错用知识分类字段。
- 新发布 `guokao-xingce-modules-2025-v1` 与 `mock-question-weighted-performance-index-v2`；旧会话继续使用其冻结蓝图和五模块 v1 策略，不填造政治理论历史分。
- 六模块回归 33 项、历史基线迁移 1 项、小程序 74 文件 413 项全部通过；数据库唯一 head 为 `20260718_39`。

### 步骤 3：补齐新用户与二战入口

目标：让小白、外部学习用户和二战用户进入不同的首日路径。

1. 增加备考经历事实与版本迁移。
2. 增加可跳过考情分析页。
3. 外部学习用户直接进入成绩/报告导入。
4. 把已有二战后端从 commerce 领域迁回学习/建档的正确 owner，再接前端入口。
5. 二战成绩只用于失分结构和训练，不参与退款、奖励或跨年直接提分。

### 步骤 4：关闭真实用户 AI 数据的处理风险

目标：只有处理方、传输、训练和删除边界可核验的场景才能接收用户内容。

1. 为每个外部处理方建立可发布的处理方记录与证据。
2. Grok 图像链改为 HTTPS 或可信服务端安全转发；未完成前只允许合成测试。
3. 对外请求最小化，移除账户与无关上下文。
4. 删除、留存和训练用途与数据导出/删除任务打通。
5. 做真实对象存储与外部调用审计演练。

### 步骤 5：实现正式申论多模型评分

目标：两个或三个独立候选、确定性比较、明确裁决，不做随意平均。

1. 冻结候选评分结构和证据锚点。
2. Gemini、Grok/其他评分模型和混元按独立候选调用；混元云函数扩展到正式评分契约。
3. 设定可解释的一致、轻微分歧、重大分歧和无法评分状态。
4. 裁决模型不得看到模型品牌偏置，且必须引用材料和评分规程。
5. 记录每个候选、裁决、成本、版本和最终区间。

### 步骤 6：补齐输入与私人知识能力

目标：完成 MyScript、讲义/笔记私人检索、删除传播和 Obsidian 回流。

1. MyScript 密钥只在后端，增加签名、请求账本、公式候选与用户确认。
2. 为私人资料建立 source → page/chunk → index → citation 的版本链。
3. 岸岸回答只检索当前用户获授权资料。
4. 删除文件同步清理切片、索引、摘要和记忆。
5. 导出/导回标准 Markdown，修改生成新版本。
