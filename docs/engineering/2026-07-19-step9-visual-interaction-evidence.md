## 2. 视觉基线合同

旧基线只有 43 张，混有 390×671、390×753 和 390×844 三种历史设备高度，且缺少 13 个已注册场景，不能作为可重复验收证据。本轮重建为 56 张完整基线，并由 `tests/visual/baseline-profile.json` 固定：

- iPhone 12/13 mini；
- 窗口 375×812，像素比 3；
- 中文、系统字号 16、竖屏；
- 微信基础库 3.17.0。

视觉命令会在截图前读取开发者工具系统信息。任何字段不一致都会提前失败，禁止把换机型后的全量差异误认为 UI 回归。

## 3. 本轮发现并修正的问题

1. 当前开发者工具仍响应 `MiniProgram.evaluate`，但旧 DOM/Page 数据命令会超时；兼容桥改为通过运行时函数访问当前页。
2. 自动化 RPC 会把嵌套数组转换成数字键对象；桥现在只跨边界传 JSON 字符串，读、写和事件 dataset 均保持原始形状。
3. 报告图表增加明确的 `ChartSpec.data` 数组运行时契约；非法形状直接报出图表 ID 和实际值，不做对象兼容或空图降级。
4. 旧视觉夹具把“计划解释”的岸岸动作伪造成“查看依据”；已按后端合同改为“预览今日计划调整”，并验证再次确认后的导航。
5. 社区试用和战略取舍原先选择的就是默认值，无法证明交互有效；现改为会产生真实状态变化的目的动作。
6. 运行时警告门禁统一捕获组件属性类型、废弃文件 API、组件 WXSS 选择器、TypeScript 全局类型和 `/api/v2` 401/404。

## 4. 证据边界

以下事项没有被本地结果冒充为完成：

- **真实后端**：`npm run journey:real` 缺少专用 access token、用户、base URL 或账号确认时拒绝启动；写入测试另需显式写入确认。当前未提供专用验收账号。
- **字面 DOM 点击**：仓库锁定的 `miniprogram-automator` 与当前开发者工具 DOM 查询协议不兼容。目的级处理器已经执行，但真实触点、焦点、键盘、相机和系统弹窗必须由可用的官方自动化环境或真机验证。
- **Figma**：当前身份对目标文件没有可读取的编辑权限，无法取得节点 `41:7` 的设计上下文；本地像素基线不是 Figma 对照结论。
- **设备**：平板已有布局契约测试，但没有 Android、iOS 和平板微信真机的横竖屏、切后台和双设备证据。
- **备份/发布**：制品切换回退已演练；按产品决定生产备份仍关闭，因此没有真实跨故障域备份、隔离恢复或生产流量回退证据。

## 5. 外部验收顺序

1. 给 Figma 当前身份授予目标文件读取权限，生成逐屏差异清单并只修改经确认的偏差。

4. 用两台设备执行任务接管、断网分叉选择和模考绝对截止时间复验。
