# 岸岸小程序 Figma 交付接入与生产功能审计

日期：2026-07-24  
审计范围：`apps/wechat` 小程序、相关后端关键合同、Figma 本地交付包  
审计性质：只读审计；本轮未修改产品 UI、路由、接口或业务逻辑

## 1. 结论

当前版本**不能认定为“Figma 已完整接入”或“可直接发布”**。

成立的部分：

- Figma 本地交付包完整：8 个页面、45 个顶层屏幕、45 个路由/状态映射、184 个素材。
- 小程序 58 个注册页面、4 个 Tab、21 个组件的结构校验通过。
- TypeScript 编译通过。
- 大部分核心模块已经接入真实 API、登录态、幂等命令和用户隔离。
- 后端关键链路 157 个测试全部通过。

不成立的部分：

- 多个路由只是“有页面、有接口”，但 Design File 规定的关键状态和动作没有实现。
- 拍照搜题有两处必须先扩展 API 合同，单改 WXML/WXSS 无法完成。
- 申论长答案没有草稿持久化，存在真实数据丢失风险。
- 每日结算、错题复盘完成态、申论材料阅读与批改结果仍缺少核心闭环。
- 前端测试 446 个中通过 444 个，2 个平板适配合同失败。

因此，当前更准确的状态是：

> **设计交付资产完整；后端主体扎实；小程序前端完成了大量真实接线，但仍存在生产阻断和一批“旧工作台替代 Design File”的页面。**

## 4. P0：发布前必须解决

### P0-01 建档完成后的“开始双科起点诊断”跳错页面

- 展示文案：`features/onboarding/result-presentation.ts:150-161`
- 实际路由：`app/navigation/routes.ts:132-141`

`record_baseline` 的按钮文案是“开始双科起点诊断”，实际却与 `enter_workspace` 一样直接进入“今日”。用户会认为按钮失效，且起点诊断闭环无法开始。

正确处理：为 `record_baseline` 指向正式诊断入口；如果诊断尚无生产路由，应先补齐产品路由与任务合同，不能继续用“今日”代替。

### P0-02 每日结算只有报告，没有结算动作

- Figma：`contexts/02-today-plan/04__node-12-2.tsx:289-401`
- 实现：`pages/daily-settlement/index.wxml:19-73`
- API：`api/planning.ts:27-28`

Design File 包含：

- 未完成任务的去向选择；
- 明天第一项任务选择；
- “岸岸推荐”；
- “确认结算，结束今天”。

当前页面只 GET 结算报告，然后返回首页、问岸岸或打开周计划，没有任何结算命令。它不是设计中的每日结算流程，只是只读日报。

正确处理：建立正式 `DailySettlementCommand`、幂等写接口、冲突恢复和提交后回执，再接 Design File 状态。

### P0-03 拍照搜题“多题命中”无法辨认候选题

- Figma：`contexts/05-photo-search/06__node-44-2.tsx:44-112`
- 页面：`pages/capture-import/index.wxml:220-231`
- 合同：`api/external-learning-contracts.ts:123-140`

Figma 候选卡显示题库来源、模块、题干摘要和匹配度。当前候选卡只有：

- 精确/相似；
- 匹配分；
- “点击选择并核对这条题库记录”。

合同 `MatchCandidate` 也只有 `contentVersionId / matchKind / score / evidenceRefs`，前端根本拿不到可辨识内容。多候选时用户无法知道选哪一道。

正确处理：扩展正式候选展示合同，至少提供授权后的题干摘要、来源标签、模块与版本信息；不能在前端伪造。

### P0-04 拍照搜题“题库解析”没有解析数据

- Figma：`contexts/05-photo-search/09__node-47-2.tsx`
- 页面：`pages/capture-import/index.wxml:283-286`
- 合同：`features/external-learning/contracts.ts:50-57`

`ImportReferenceAnswer` 只有答案文本和内容版本 ID，没有解析、步骤、考点或来源展示信息。当前页面只能写死“详细精讲会保存在学习包”，不能呈现 Design File 中的题库解析。

正确处理：扩展授权参考答案合同，返回可展示的 AI/题库解析、来源和结构化步骤；继续遵守“查看不自动写入能力画像”的边界。

### P0-05 申论长答案没有自动保存，页面回收会丢失

- 输入：`pages/essay-task/index.ts:916-949`
- 生命周期：`pages/essay-task/index.ts:475-492`
- 空函数：`pages/essay-task/index.ts:2470-2472`
- Figma 保存状态：`contexts/06-essay/01__node-17-2.tsx:205`

所有输入调用的 `markDraftChanged()` 是空函数；`onHide/onUnload` 只停计时与轮询，不保存草稿。只有最终提交时才持久化命令。用户写几百到上千字后切走、系统回收页面或小程序重启，内容可能全部丢失。

正确处理：建立按用户、题目版本、任务版本隔离的本地草稿存储与服务端草稿版本；节流保存、恢复、版本冲突和提交后清理必须是同一套正式机制。

### P0-06 申论材料阅读不是 Design File 的阅读工作流

- Figma：`contexts/06-essay/02__node-29-2.tsx`
- 实现：`pages/essay-material/index.wxml:1-12`

Design File 是沉浸式材料阅读，支持选中文本后的高亮、加入提纲和复制。当前页面是材料目录、材料卡片和既有标注的只读地图，不提供选择工具条，也不能把材料片段带入作答提纲。

正确处理：保留现有真实材料 API，但重做页面交互层和标注/提纲写入合同；不能把“材料地图”当成交付屏幕。

### P0-07 申论批改结果仍是旧工作台摘要

- Figma：`contexts/06-essay/03__node-30-2.tsx`
- 实现：`pages/essay-review/index.wxml:1-10`

Design File 包含得分维度、命中/遗漏要点、材料定位、表达升格、建议改写，以及“再写一次 / 加入明日专项 / 带着本题问岸岸”。当前独立页面只展示分数、维度和 findings，且把原始 `severity` 直接显示，没有底部动作闭环。

正确处理：复用已通过测试的 grounded review 数据，补齐正式 presentation contract、材料定位、改写和计划动作；不能继续用 10 行旧工作台替代。

### P0-08 错题复盘完成态缺少三个关键后续动作

- Figma：`contexts/03-practice-review/04__node-15-2.tsx:67-148`
- 实现：`pages/reflection/index.wxml:240-254`

Figma 完成态包含：

- 查看知识卡；
- 现在加练 2 题，且明确不计入复测证据；
- 调整复测时间。

当前只有“完成复盘”返回今日。结构化解析也只展示一段通用 explanation，没有最短路径、其他选项错误原因、一句话记忆和草稿轨迹。

正确处理：补齐知识卡、即时加练、复测计划三个真实动作合同，并把结构化解析字段正式纳入 presentation。

### P0-09 私人资料导入面板会覆盖处理/核对流程

- 面板：`pages/private-knowledge/index.wxml:199-209`
- 关闭限制：`pages/private-knowledge/index.ts:460-462`
- 处理态：`pages/private-knowledge/index.wxml:1-33`

从导入 sheet 选择文件后，`busy=true`，但 `importPanelOpen` 仍为 true；sheet 位于页面分支外，继续覆盖处理页面。此时 `closeImportPanel()` 因 busy 直接返回，用户不能关闭它。

正确处理：开始正式处理前原子关闭选择面板，再进入处理状态；核对、取消与后台运行应由同一状态机管理。

### P0-10 今日可用时间冲突/保存结果对用户不可见

- 状态计算：`features/planning/today-controller.ts:112-225`
- 页面数据：`pages/today/index.ts:269-311,489-514`
- 模板：`pages/today/index.wxml`

`capacityMessage` 已覆盖冲突、重排、保存失败和成功，但模板没有渲染它。发生版本冲突或保存失败时，业务状态改变了，用户看不到原因和恢复动作。

正确处理：把消息和可执行恢复动作放回 Design File 对应位置；不能静默吞掉写入结果。

## 5. P1：核心体验与设计一致性

### 登录与建档

- 登录页把 Figma 原始 SVG `112de17e...svg` 转成 88×88 raster，再放大显示，属于不必要的素材劣化。
- “用户协议与隐私政策”只是文本，不可点击。
- 备考经历领域支持 `externalLearning` 和 `priorGuokaoExam`，页面只暴露“首次备考 / 二战多战”，无法表达“已在外部学习但未参加国考”等真实状态。
- 用户要求的微信头像未实现；当前只是昵称首字和六种渐变风格。
- 能力基础页缺少 Design File 的“暂存并退出”。

### 今日、能力、岸岸、我的

- “开始学习”在 startUrl 为今日页时滚动到不存在的 `.focus-dashboard`。
- 能力雷达文案称综合正确率、用时、掌握与复测，实际点值只使用 `correctRate`。
- “查看怎么算的”只打开岗位工作区，没有直接打开分数依据。
- 岸岸只在 `onLoad` 加载学习上下文，Tab 再次显示时不刷新，跨页面动作后的岗位、任务、能力摘要可能陈旧。
- “我的”使用 `Promise.allSettled` 后不显示资格、学习偏好或目标的局部加载失败，容易把服务错误伪装成“尚未填写”。
- “授权管理”实际打开通知设置；“申论记录”和“模考成绩”实际进入同一报告中心。
- 账号退出/全部设备退出逻辑存在，但当前 Design File 页面没有入口。

### 周计划与岗位

- 周计划标题写“只追三个变化”，Figma 也有“本周三个目标”，但页面和 `WeeklyPlanVersion` 没有目标卡与目标合同。
- 岗位发现缺少“专业优势 / 分数友好 / 周边弹性备选”的分组。
- 全部岗位缺少 Design File 的单位层级、招录人数和专业限制筛选，当前地区也是自由输入而非结构化选择。
- 岗位对比允许 3 项，Design File 是两列布局；手机横向滚动可用，但视觉合同不一致。

### 拍照搜题

- “拍摄”页面没有 `<camera>` 实时预览，快门实际调用 `wx.chooseMedia`。
- 裁剪框只是展示，真正裁剪依赖系统 `wx.editImage`，没有 Design File 的页内拖拽裁剪。
- OCR 核对按通用片段显示，没有题干/选项语义结构和缺项校验。
- “收录成功”设计要求真实收录位置与撤销；当前回执是“仅本次查看”，没有撤销动作。边界表达诚实，但不能占用 `recorded` 设计状态。

### 私人资料库

- 处理步骤是固定三行视觉文案，不映射真实后端处理阶段。
- 搜索结果为 0 时没有明确“未找到”状态。
- 岸岸回答中的私人引用与资料库的原文快照还没有形成统一可跳转的引用合同。

### 设备与动效

- `task-runtime/task-shell` 只使用 CSS safe-area，不使用微信胶囊实际几何；做题、模考和申论自定义导航存在真机碰撞风险。
- 58 个页面中只有 17 个页面使用了 `hover-class`；全局 `.tap-tactile` 已定义但未被页面使用。
- 关键 sheet、展开、Tab 激活和进度变化缺少统一动效合同。
- 平板适配测试当前失败；手机发布不应声称已完成平板适配。

## 6. 已确认完成或做得扎实的部分

- 报考资格已正确区分普通工作经历与服务基层项目。
- 学习时间已改成小时表达，并支持 0.5 小时步进与高强度学习场景。
- 行测做题主流程包含共享材料、题目切换、计时暂停、草稿、排除、信心与检查点恢复。
- 题目作答、用时、信心、改答、排除与草稿事实均进入真实控制器。
- 岗位资格核验、分数证据、目标预览与确认使用真实 API，并有幂等与版本约束。
- 拍照搜题已实现真实上传、OCR 核对、匹配确认、AI 独立答案、结果确认和画像边界。
- 私人资料库已经有真实上传、OCR 核对、索引、检索、导出和删除接口。
- 申论后端的 grounded review、改写、材料、评分和多模型相关测试整体扎实；问题主要在独立小程序页面没有按 Design File 交付。
- 用户隔离和授权边界在关键 API 中存在，不是单用户 demo 架构。

## 7. 用户已明确允许延期，不列为本轮发布阻断

- 微信虚拟支付：等待商户与密钥条件。
- 备份功能：暂不开启。
- 客服：暂时占位，后续放群二维码。
- 天气：今日卡片只展示，不再进入“天气来源”详情页。
- iOS App Store：当前不在小程序发布范围。
- 咖啡下单：在获得每用户独立授权与确认链路前保持关闭，不得使用共享 Bearer Token 代下单。

## 8. 推荐修复顺序

### 第一批：数据安全与合同

1. 申论草稿正式持久化。
2. 拍照搜题候选展示合同。
3. 拍照搜题题库解析合同。
4. 每日结算写命令与回执。
5. 复盘完成后的知识卡、加练和复测计划合同。

### 第二批：按 Design File 重接核心页面

1. 申论作答、材料阅读、批改结果。
2. 每日结算与周计划三个目标。
3. 拍照搜题 11 个状态。
4. 私人资料库 4 个状态。

### 第三批：核心路由与状态刷新

1. 建档结果的起点诊断路由。
2. 今日冲突消息与正确滚动目标。
3. 岸岸 `onShow` 上下文刷新。
4. 我的页面入口拆分与局部错误呈现。

### 第四批：视觉与设备一致性

1. 严格使用 Design File 原始素材与交付 tokens。
2. 修复自定义导航胶囊安全区。
3. 统一按压、sheet、展开和状态切换动效。
4. 完成平板合同后再声明平板适配。

完成以上四批后，再进行一轮真机端到端验收；在此之前不建议继续用零散页面微调掩盖合同缺口。
