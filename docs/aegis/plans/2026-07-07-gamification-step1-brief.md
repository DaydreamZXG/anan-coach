# 治国 App 游戏化 — 第一步：定位与依赖 brief

> 阶段：策略验证期（非机制设计期）
> 依据：用户确认「痛点=枯燥·坚持难」「核心=雏形待打磨」
> 作者：GameDesigner ｜ 日期：2026-07-07 ｜ 版本：v0.1

## 1. 我们赌的痛点（已确认）
用户流失主因 = **枯燥·坚持难**（机械重复、孤独、看不到头、缺动力）。
→ 游戏化对此对症。其他痛点（不知练啥 / 太难挫败 / 没时间）游戏化治不了，需先解决内容路径与难度。

## 2. 我们的胜负手定位
核心刷题体验目前「雏形待打磨」→ **尚未与头部平手**，游戏化暂不能单独当护城河。
**并行策略**：
- 核心团队：把刷题 / 解析 / 个性化打磨到与头部平手（这是入场券）。
- 游戏化：设计成「头部抄不走的情感叙事层」，而非通用勋章 / 排行皮。

## 3. 核心 fun hypothesis（一句话）
> 用户每天愿意回来，不是因为"好玩"，而是因为**"看得见自己在靠近上岸，且回来这件事不沉重"**。

游戏化要撬动的不是"把题变好玩"，而是**进度可见性 + 情感叙事 + 低负担的回归**。

## 4. 游戏化三层（由轻到重，先验证最轻的）

| 层 | 内容 | 作用 | 成本 |
|----|------|------|------|
| **L1 进度可见** | 分差进度条 + 今日/明日政务预告 + 归来提醒（含考试倒计时+剩余分差） | 验证"可见进度是否提升坚持" | 最低，先做 |
| **L2 治国叙事** | 把 L1 反馈用"批阅奏折/治绩"包装 + 幕僚点评 | 给进度一个情感外壳，难抄 | 中 |
| **L3 成长可视化** | 辖区/封地作为 6 模块 mastery 的仪表 | 让"变强"可见 | 高，最后做 |

**原则**：L3 只反映「弱项练习」真实行为，不发放独立游戏奖励（避免抢学习注意力）。

## 5. 游戏化对核心的「数据契约」（核心团队现在就留接口）

| 信号 | 用途 | 来源 |
|------|------|------|
| 分差 = 目标分 − 预估分 | L1 主指标（英雄指标） | 选岗进面分 + 摸底/模考 |
| 各模块滚动胜率（6 板块） | L3 辖区等级、弱项推荐 | 练习记录 |
| 连续学习天数 / 最近活跃 | L1 归来提醒、坚持感 | 活跃日志 |
| 单次练习质量（正确率、难题占比） | L2 幕僚点评、攻坚连击 | 答题记录 |

没有这些信号，L2/L3 都建不起来——核心打磨时必须顺手产出。

## 6. 第一步原型（最便宜的假设验证）
- **只做 L1，不做 L3。**
- 两周小样本（30–50 人）A/B：有「分差进度 + 明日预告 + 归来提醒」组 vs 无此层对照组。
- 观测：7 日 / 30 日留存、周练习天数。
- **成了** → 叠加 L2 治国皮肤，再测。
- **没成** → 痛点判断有误，回看是否其实是「不知练啥 / 太难」，游戏化退为辅助。

## 7. 红线（贯穿全程）
- 游戏化只服务「坚持」，不抢学习注意力（铁律）。
- 不做抽卡式变量奖励、不做付费避罚。
- 主 KPI = 分差缩小速率 / 模考提升 / 上岸率，不是 DAU / 时长。
