# 接手评估：治国 Gamification Master Plan

> 评审人：GameDesigner（接手视角）
> 评审对象：docs/aegis/plans/2026-07-06-governance-gamification-master-plan.md
> 日期：2026-07-07
> 结论等级：方案可接手，但开工前必须解决 1 个 P0 矛盾 + 3 个 P1 风险

## TL;DR（一句话）

骨架清醒、壁垒复用到位、世界观包装克制；但**进度系统存在"双引擎"定义冲突**（品级到底由刷题量还是由分差决定），这是开工前必须拍板的头号问题；同时精力值机制与"刷题工具"目标相悖、民心值构成双重惩罚、锦囊"保命"是付费避罚设计——这四项是必须在阶段1之前解决的设计债务。

## 一、方案里"对"的地方（先肯定，再挑刺）

1. 壁垒不动、只做包装层 —— 这是风险最低也最正确的决策，符合"最小可行改造"。
2. 6 大板块硬约束写死（不可更改） —— 用文档纪律防止范围蔓延。
3. 三条"不做"很清醒：不做真实地区映射、不做实时 AI 生成卡片、不做像素风。
4. **熔断（智能熔断 / 恩准休沐）是真懂学习机制的设计** —— 把"你已经够好了，去学别的"用游戏语言讲清楚，比粉笔的"哪里弱补哪里"更有差异化。
5. 品级方向正确（九品最低、一品最高），rank_level 9→1 自洽。
6. 阶段化路线图 + 验证标准具体，可执行。

## 二、P0：开工前必须解决的核心矛盾

### 2.1 品级的"双引擎"冲突

文档同时定义了两种品级驱动方式，且互不锚定：

- **引擎A（刷题量）**：`答对1题行测 +10 XP`、连击、每日政务、模考等累加 XP → 达阈值升品。
- **引擎B（能力/分差）**：`目标分 - 预估分 = 分差`；`分差缩小 = 品级经验增长`；`分差100%消除 = 一品首辅（上岸）`。

**冲突后果**：

- 玩家可刷 4000 道简单题攒满 XP 却没缩小分差（品级虚高，与"上岸"脱节）；
- 或缩小了分差但 XP 不足，卡在八品却已"上岸"——进度与叙事断裂。

**我的判断（需你拍板）**：以**引擎B（分差驱动）作为品级主引擎**，更贴合"上岸"终极目标、更抗题库耗尽、也更能解释"为什么练这个模块"。引擎A 的 `+10 XP` 降级为**即时反馈与小奖励**（驱动手感，不直接决定品级）。两者解耦后，叙事才自洽。

### 2.2 精力值 vs "鼓励多刷"的目标相悖

- 排序工具的核心商业目标是**让用户多刷题**；而 `精力值：做题消耗，每日恢复` 本质是限制每日刷题量——与目标反向。
- 风险注里说"只限制单次时长，不限制每日总量"，但机制本身做不到：精力耗尽即当日无法继续，等于隐性日上限。
- 建议三选一：① 直接砍掉精力值；② 改为正向 buff（精力满时答题有加成，而非耗尽惩罚）；③ 用"备考阶段"完全替代精力概念。

## 三、P1：平衡与伦理风险（需在阶段1前建模/重做）

### 3.1 品级阈值全是 magic number，无推导

阈值 0/500/1500/3000/6000/10000/16000/25000/40000 没有来源说明。按 `约40题/日正确、约500 XP/日（含连击+每日政务）`估算：到一品约 **80 天（≈11–12 周）**，恰好贴合国考备考周期（7月启动→11月考试）——这很可能是有意校准，但文档没说。要求补一张"目标时长→阈值"反推表，并把所有数值标 `[PLACEHOLDER]` 待 playtest。

| 品级 | 阈值XP | 估算到达天数(≈500XP/日) | 备注 |
|------|--------|------------------------|------|
| 九品县令 | 0 | 0 | 起点 |
| 八品县丞 | 500 | ~1 | 过快，几乎无感 |
| 七品知县 | 1,500 | ~3 | |
| 六品知州 | 3,000 | ~6 | |
| 五品知府 | 6,000 | ~12 | UI进化节点 |
| 四品道员 | 10,000 | ~20 | |
| 三品布政使 | 16,000 | ~32 | |
| 二品巡抚 | 25,000 | ~50 | 黑金UI |
| 一品首辅 | 40,000 | ~80 | =上岸 |

> 八品→七品仅 3 天，早期晋升过于廉价，缺乏"里程碑感"；建议早期阈值拉开间距或加解锁仪式。

### 3.2 民心值：双重惩罚 + 羞辱式反馈

- 答错本身已带来挫败（题错了），再 `-1 民心` 是 double jeopardy，会放大挫败而非引导。
- `民心<30 → UI背景变暗红` 是**持续性负面视觉压力**，对学习者可能反向推动流失——而文档未将其列为风险（只列了御史台惩罚）。
- `民心<0 → 触发降级判定` 但**降到哪、是否跳级、与御史台降级是否叠加**均未定义（见 3.3）。
- 建议：答错不扣民心（或仅"连续错 N 题"才扣）；把"暗红羞辱"改为中性/鼓励提示。

### 3.3 降级判定未定义（两条降级路径混淆）

- 路径A：民心<0 → 降级判定
- 路径B：御史台 48h 未答 → 降级

两路并存，玩家会困惑"我为什么被贬"，且可能叠加惩罚。需明确定义：降级幅度（−1 品？回退到某阈值？）、冷却、与熔断/御史台互斥规则。

### 3.4 锦囊"保命"= 付费避罚（伦理 P1）

- `御史台降级时可花2元买锦囊保命` = pay-to-avoid-punishment，利用损失厌恶变现，对**教育产品**是危险模式，且有品牌/合规风险。
- 建议改为**正向增益型消费品**：揭示提示、跳过怪题、额外幕僚解析、临时解锁某特权——让付费带来"爽"，而非"别罚我"。

## 四、P2：验证标准偏差与文档纪律

- 现有验证标准全是"功能是否就位"（盖了准字印、燃起火焰），不是"玩家是否感受到 X"。按我的规则，每个阶段应补**玩家体验验证标准**（如：首次答对后 3 秒内，玩家能说出"我在批阅奏折"）。
- 缺"broken 定义"：XP 曲线多快算崩？民心地板值多少触发流失？需先定义失败样貌再 playtest。
- 缺 onboarding 关键项：核心动词（批阅奏折）是否在 30 秒内出现？首答是否"必定成功"？文档沿用旧流程但未映射新包装下的首次必成。
- `同榜进士排行榜`按 XP 排序——若 P0 改为分差驱动，排行榜指标需同步改为分差/治绩。

## 五、其他小问题

- 术语映射"前后端各维护一份" → 双源头漂移风险，应后端单一来源下发前端。
- "不做打卡天数系统（用官场品级替代）" 但 `御史台 = 换皮打卡`（consecutive_days + last_active_date），措辞需统一，避免接手者误判。
- 政治理论仅 860 题，存在内容耗尽风险；需建模重复率/错题回收，否则高频练习会撞题。
- 熔断 3 天硬锁无退出机制，建议允许锦囊跳过或降级为"软推荐"（高亮建议换模块，不强制锁）。
- AI幕僚"预制50+模板"策略正确（控成本），但需保证模板随机组合不出现语义矛盾（如连胜时刷出"你退步了"）。

## 六、接手优先级建议

1. **拍板品级主引擎**（分差 vs 刷题量）—— 决定大半后端结构与排行榜指标。← 卡点
2. 砍/改精力值（反向目标）。
3. 重做民心为非负向 + 定义降级规则。
4. 锦囊改正向增益。
5. 补数值推导表 + broken 定义 + 玩家体验验证标准。
6. 再进入阶段1 开发。
