## 真实缺口（按杠杆排序）

### 缺口 1（最高杠杆）：StatusBar 没有分差，反而凸显民心 + 精力
**现状** `StatusBarView.swift` 显示：品级 + 距下品 XP + **民心** + **精力** + 今日政务。
**问题**：
- 分差（英雄指标）完全没显示 —— 后端 `calibration/ability` + `positions/{id}/target-score` 都在算，**iOS 没调**。
- 民心（fame -1 on wrong）和精力是我建议休眠的惩罚 / 反目标机制，却占着顶栏 C 位。

**改法**：
- StatusBar 重排为：品级徽章 + **【分差：距上岸 X 分（主视觉进度条）】** + 今日政务 + 连续天数。
- 接 `/api/v1/calibration/ability`（预估分）+ `/api/v1/positions/{id}/target-score`（目标分），算 `分差 = 目标 − 预估`。
- 民心 / 精力 保留数据但 MVP **不在顶栏展示**。

### 缺口 2：明日政务预告（会话钩子）
**现状**：`StudyDeskView` 只有静态文案"明天的计划会参考今天的表现"。
**改法**：会话结束展示"明日政务预览"（具体到模块 + 题量，如"明日：数量关系 5 题 + 言语 3 题"）。复用 taskstream 逻辑，后端加 `/taskstream/tomorrow` 或前端据今日推断。

### 缺口 3：归来推送
**现状**：未实现（`UserNotifications` 框架已链接但未调度）。
**改法**：本地推送，断更 1 天后触发，文案含考试倒计时 + 剩余分差（如"距考试 86 天，还差 12 分，今日政务已备好"）。无惩罚，纯召回。

### 缺口 4：确认惩罚机制休眠
`censor_events` / `module_locks` / fame 衰减 已建表 + 逻辑。MVP 须确保：
- 不触发 censor 巡视定时任务（或关闭）。
- `module_locks` 不自动锁库。
- fame 衰减 / 降级 不在前端体现。
→ 需后端确认这些是否已有定时任务在跑（待 SSH 查 cron / systemd timer）。

## "玩几天"的支撑
`calibration` 已支持"练习 ≥ 30 题 → 中置信预估分"，即**每日练习能让预估分变动 → 分差每日可见地变化**。无需等模考即可推进，满足"玩几天"的进度感。
