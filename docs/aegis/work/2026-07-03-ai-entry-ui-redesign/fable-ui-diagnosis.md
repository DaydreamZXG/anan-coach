## 7.1 UI 诊断

### 1. 当前 UI 为什么仍像刷题软件

核心问题：**所有信息都用同一种"白色圆角卡片"以同等权重堆叠，AI 的判断没有视觉主权。**

具体表现：

- **`panelStyle()` 统治了一切。** TodayHero、TrackMixPanel、TaskRow、做题面板、申论面板全都是 `padding(16) + 白底 + cornerRadius(8)` 的同构卡片，从上往下垂直堆叠。用户视网膜里得到的是"一列设置项/题目列表"，这正是每一个刷题 App 的视觉语法。
- **"今日配比"和"执行顺序"是标题 + 列表的普通清单。** TrackMixPanel 是 `Text 标题 + ForEach 行`，TaskRow 是图标 + 标题 + 副标题 + 小字——和网易云课堂/粉笔的任务列表没有区别。它表达的是"这里有 4 个条目"，而不是"AI 排了一条 42 分钟的提分路径，按顺序走"。
- **做题和申论面板直接内联在今日首页里。** `PracticeExecutionPanel` 和 `EssayExecutionPanel` 平铺在 TodayView 的 ScrollView 中，任务执行没有自己的"场"。首页更像一个"什么都往里塞的题库页"，"开始第 1 项"这个 CTA 失去仪式感——点了之后只是页面下方多出一块卡片。
- **AI 的话语被降级成 secondary 灰色小字。** `plan.rationale`、`task.reason`、`item.reason` 全是 `.secondary` 的 subheadline/caption。AI 的判断（产品的灵魂）在视觉上是"辅助说明文字"，而题目选项、按钮这些执行元素反而更醒目。用户感受不到"有人在带我"。
- **iPad 右栏是占位文案，不是真判断。** DeskInsightPanel 显示的是"这类对象会进入今日计划……"这种自我描述性文字，DeskSourcePanel 只有一个来源计数。右栏没有承载错因、依据、下一步，工作台感是空的。
- **分数差距被埋没。** "预计差距 14 分"只是 hero 副标题里的一个 subheadline，而它应该是驱动一切的第一视觉。

一句话病因：**信息架构已经是 AI-first 的（三 tab、taskstream、双轨），但视觉层级仍是 feature-first 的——卡片平权、AI 降级、执行内联。**

### 2. 应保留的元素

| 元素 | 理由 |
|---|---|
| `今日 / 工作台 / 我的` 三 tab 结构（AppShellView） | 符合 IA 规格，不动 |
| iPad 独立 StudyDeskView + 宽度自适应两/三栏骨架 | 骨架方向对，只需重排内容归属 |
| TodayHero 的信息内容（headline / 目标 / 差距 / rationale / 总分钟 / CTA） | 内容契约正确，问题在排版权重 |
| TrackBadge 行测蓝 / 申论橙的双轨色语义 | 已建立的轨道识别系统，应升级为全局设计 token |
| 行测答题 → 提交 → `PracticeFeedbackView`（正误 + 解析 + 来源 + nextAction）闭环 | 后端契约已通，是"AI 带练"的原材料 |
| 申论 材料 → 初稿 → 五维点评 → 重写 → 对比 的完整链路（EssayReviewView 等） | 首版申论闭环齐全，只需换容器 |
| 每个任务/反馈上的 `sourceGrounding` 来源标注 | 产品原则 4 的落点，必须保留并加强 |
| LoadingPanel / ErrorBanner / 无假数据的加载态 | 商业化诚实原则 |
| `floatingTabClearance()` 底部避让 | 验证要求第 5 条 |

### 3. 应删除或重排的结构

| 结构 | 处置 |
|---|---|
| `PracticeExecutionPanel` / `EssayExecutionPanel` 内联在 TodayView | **移出首页**。任务执行改为全屏推入的执行页（iPhone）/中栏画布（iPad），首页只负责"看清今天 + 开始" |
| `TrackMixPanel` 普通列表 | **删除列表形态**，重做为"双轨时间条"：一条按分钟比例分色的横向轨道条（行测蓝段 + 申论橙段），点按段落展开 reason |
| `TodayTaskList` 卡片堆叠 | **重排为纵向步骤流（stepper/timeline）**：左侧竖线串联序号节点，明确"这是一条路径不是一个清单"；当前项放大，已完成项收起打勾，未到项弱化 |
| 所有卡片共用 `panelStyle()` 的平权体系 | **建立三级容器层级**：主任务面板（强，一屏只有一个）> 路径/轨道（中）> 元信息（弱，可无底色）。多数二级内容去卡片化，用留白和分隔线组织 |
| iPad `DeskTaskContent` 直接复用 iPhone 的 TodayHero+列表整段塞进中栏 | **中栏改为纯执行画布**：只放当前任务/对象；今日路径归左栏，判断/来源/错因/下一步归右栏 |
| iPad `DeskInsightPanel` / `DeskSourcePanel` 的占位描述文案 | **删除**，右栏改为真实数据驱动：搭子判断（rationale/错因）、来源列表（可点）、掌握度变化、下一步动作按钮、点评质量反馈 |
| `SourceBasePanel` 三个大数字指标砖（55,214 题库等） | **从工作台首屏降级**。对用户这是厂商自夸，不是学习对象；移到来源库详情或"我的"，工作台首屏留给生成的学习对象 |
| 首页 `navigationTitle("今日")` 大标题 | **删除**。第一行视觉应该是目标条和搭子的话，不是栏目名 |

### 4. 新首页的一句话产品主张

> **"搭子已经排好了你今天的提分路径——离目标还差 14 分，今天先补最拖分的地方。"**

压缩成 UI 上的一行主张即：**"今天 42 分钟，补掉 14 分差距里最值钱的一块。"**

首屏必须让用户在 2 秒内读到三件事：我离目标多远 → 搭子已经排好了 → 现在开始第一项。

## 7.2 设计方案

总方向按 brief 第 6 节：**iPhone 用方向 A（AI 教练驾驶舱），iPad 用方向 B（NotebookLM 垂直工作台）**，保留方向 C 的短句语气。

### 全局设计语言

**颜色（共 5 色，克制、专业、提分导向）**

| Token | 值方向 | 用途 |
|---|---|---|
| `brand` | 深蓝墨色（近 navy/indigo 但去紫感，如 #1B3A6B 系） | 主 CTA、当前步骤、搭子判断强调 |
| `trackXingce` | 现有蓝（保留） | 行测轨道 |
| `trackShenlun` | 现有橙（保留） | 申论轨道 |
| `surface` / `surfaceElevated` | 系统 groupedBackground / systemBackground | 背景与一级容器 |
| `positive` / `alert` | 绿 / 橙红各一 | 答对/掌握上升、错因/风险 |

不用渐变，不用营销 hero 图。装饰性元素为零，"决策密度"就是视觉风格。

**字体**：全系统 SF Pro。等级差要拉开——搭子主判断用 `.title2/.title.weight(.bold)`，数字（差距分、分钟）用 `.monospacedDigit` 加大加粗成为视觉锚点；辅助说明维持 secondary，但 **AI 判断永远不用 secondary**，它是 primary 内容。

**文案基调**（方向 C 的语气注入 A/B 的结构）：短句、有主见、给理由、落动作。模板：`判断一句 + 证据一句 + 动作一句`。例："先补资料分析比重变化。昨天 3 题里错 2 题，都错在基期选择。现在做 4 题同类。"禁止"您可以尝试……"式客服语。

**间距**：区块间 24–32pt 拉开呼吸感，区块内 8–12pt 收紧；卡片圆角统一 12–16pt，但只有一级容器有底色投影感，二级内容靠留白组织。

### 方案一：iPhone「今日」首页（AI 教练驾驶舱）

#### 信息层级（自上而下，一屏内完成决策）

```
① 目标条（固定顶栏，非卡片）
   广东省考 · 珠三角综合管理岗        差距 -14分
   —— 差距数字用 alert 色 + 大号等宽字，是首屏第一视觉锚

② 搭子主判断（首屏主体，占据视觉中心）
   「搭子给你排好了今天 42 分钟」        ← title 级粗体
   「先补省联考判断推理，再做申论概括重写。
     原因：联考题重复率高，你昨天错在论证关系。」 ← primary 正文，带来源角标
   —— 这是唯一的"强卡片"，深色/brand 底 + 反白文字，
      和页面其余部分形成一眼可辨的主从关系

③ 双轨时间条（一条，非列表）
   [■■■■■■ 行测 26分 ■■■■■■|■■■ 申论 16分 ■■■]
   点按任一段 → 底部浮出该轨道的 reason 一句话

④ 今日路径（垂直步骤流，非卡片堆叠）
   ●— 1. 判断推理 · 论证 3题        12分  ← 当前项：放大、brand 描边
   ○— 2. 资料分析 · 比重 4题        14分  ← 未到项：缩小、灰化
   ○— 3. 申论 · 概括题重写          16分
   每步保留 reason 一行 + 来源角标（link 图标 + 简称）

⑤ 底部固定 CTA（safe-area 上方悬浮）
   [ ▶ 开始第 1 项 · 判断推理 3 题 ]   ← 全宽 brand 按钮，随进度变
                                        「继续第 2 项」
```

#### 组件列表

- `GoalStripView`：目标条（考试/岗位组/差距分/距考试天数）
- `CoachBriefCard`：搭子主判断强卡片（headline + rationale + 来源角标）
- `TrackTimelineBar`：双轨比例时间条（替代 TrackMixPanel）
- `TaskPathView` + `TaskStepNode`：竖向步骤流（替代 TodayTaskList/TaskRow）
- `PrimaryCTABar`：底部悬浮开始/继续按钮（吸收 floatingTabClearance）
- `PostTaskDeltaSheet`：任务完成后弹出"发生了什么变化"（正确率、错因、明日计划将如何调整）

#### 交互流

1. 打开 App → ①②③④ 一屏呈现，②在视觉中心；
2. 点底部 CTA 或步骤节点 → **全屏推入任务执行页**（NavigationStack push，不再内联展开）；
3. 任务完成 → 返回今日页时 `PostTaskDeltaSheet` 呈现反馈 + 步骤流自动打勾并聚焦下一项，CTA 变"继续第 2 项"；
4. 全部完成 → 主判断卡变为"今日复盘 + 明天预告"，CTA 变"看今天带来的变化"。

### 方案二：iPhone 任务执行页（AI 带练）

任务执行是独立全屏页，题目是画布，AI 是随行教练。

#### 行测执行页

```
顶部：细进度条（第 2/6 题）+ 轨道徽章 + 剩余预估分钟
中部：题干 + 选项（保留现有交互，容器放大留白）
底部：提交按钮
提交后（就地展开，不跳页）：
  ┌ 错因判断（不是长解析）─────────────┐
  │ ✕ 错在"论证关系"——你把削弱当成了无关  │  ← 一句话错因，alert 色
  │ 同类题识别：题干出现"由此可以推出"时…   │  ← 一句话识别法
  │ 来源：省联考 2024 · 判断推理 · #4821   │  ← 可点来源
  │ [ 下一题 → ]   [ 展开完整解析 ˅ ]      │  ← 长解析默认折叠
  └───────────────────────────────────┘
```

关键改动：`PracticeFeedbackView` 的解析长文降级为折叠项，**错因一句话 + 同类识别一句话 + 下一步**成为默认呈现——这就是"AI 带练"和"刷题软件出解析"的分水岭。

#### 申论执行页

保留现有 材料→初稿→五维→重写→对比 链路，改为**分步呈现而非一页堆叠**：

1. 步骤 1「读材料 + 作答」：材料可折叠，编辑器全高，字数实时计数/限制；
2. 步骤 2「五维点评」：五个维度做成横向小分条（n/5），每维只展示 comment 一句 + action 一句；缺失要点用 alert 色列出；
3. 步骤 3「重写」：点评侧滑收起为可唤出的侧签，重写编辑器占主体，顶部钉住 rewriteInstruction 一句话；
4. 步骤 4「对比」：v1/v2 双栏（compact 下上下）对比 + 字数变化 + "已生成申论复盘，明日计划将调整"的落点。

顶部用 `读题 → 初稿 → 点评 → 重写 → 对比` 分段步骤条，强化"这是搭子带着走的流程"。

### 方案三：iPad 工作台（NotebookLM 垂直工作台）

三栏职责彻底分离，杜绝"放大版 iPhone"：

```
┌──────────┬────────────────────┬──────────────┐
│ 左栏 260-300 │ 中栏 flexible（执行画布）│ 右栏 340-400（搭子） │
│              │                        │                    │
│ 目标条        │ 只放"当前正在做的事"：    │ ① 搭子判断          │
│ 差距 -14 分   │ · 当前题目/申论编辑器     │   为什么是这个任务、  │
│              │ · 或选中的学习对象内容    │   错因、掌握度变化    │
│ 今日路径      │   （错因复盘/考点卡/     │ ② 来源             │
│  ●1 判断推理  │    岗位简报的正文）      │   可点条目列表：题源、 │
│  ○2 资料分析  │                        │   知识片段、岗位公告   │
│  ○3 申论重写  │ 无嵌套卡片，像一张       │ ③ 下一步动作        │
│              │ 纸/画布：白底、大留白、   │   [做 4 题同类]      │
│ 学习对象库    │ 顶部仅一条上下文标头     │   [加入明日计划]     │
│  行测训练 ▾   │                        │ ④ 点评质量反馈       │
│  申论写作 ▾   │                        │   有用 / 不准 打点    │
│  岗位策略 ▾   │                        │ ⑤ 配额状态（低调）    │
│  周计划 ▾     │                        │                    │
└──────────┴────────────────────┴──────────────┘
```

#### 关键改动（相对现状）

- **中栏不再复刻 TodayHero + TrackMixPanel + 任务列表**（这些归左栏和右栏），中栏只有"正在执行的一件事"，这是工作台感的来源；
- **右栏由真实数据驱动**：rationale、feedback.errorType、sourceGrounding、nextAction、quota 全部已有后端字段，替换掉现在的占位文案；来源做成可点条目列表而不是一个计数；
- 左栏今日路径与 iPhone 步骤流同构（组件复用 `TaskPathView` 的紧凑变体），学习对象库按 行测训练/申论写作/岗位策略/周计划 分组（复用现有 sections 数据）；
- 竖屏（<1180pt）保持两栏：左栏不变，中+右合并时**右栏内容以"搭子"抽屉/浮层形式常驻可唤出**，而不是像现在一样把反馈内容顺序拼接在任务下面；
- 减少卡片墙：右栏用分组标题 + 分隔线组织高密度信息，只有"下一步动作"按钮区用强底色。

#### iPhone 与 iPad 的差异总结

| 维度 | iPhone | iPad |
|---|---|---|
| 隐喻 | 教练驾驶舱：一次一屏、一次一事 | 学习书桌：对象/执行/判断三者共存 |
| 今日路径 | 首页主体（步骤流） | 左栏常驻导航 |
| 任务执行 | 全屏推入 | 中栏画布就地切换 |
| AI 判断 | 首屏主卡 + 提交后就地展开 | 右栏常驻面板，随中栏内容联动 |
| 来源 | 角标，点开浮层 | 右栏可点列表 |
| 导航 | 底部三 tab | 无底部 tab，三栏 + 左栏顶部入口切「我的」 |
