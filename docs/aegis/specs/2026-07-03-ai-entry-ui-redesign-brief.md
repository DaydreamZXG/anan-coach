# 考公搭子 AI 入口 UI 重设计任务包

Date: 2026-07-03
Status: Draft for v0/Fable 5 design pass

## 1. 任务目标

重设计 `考公搭子` iPhone/iPad 首版界面，使它从“刷题软件外观”转为“AI 驱动的公考学习入口”。

用户打开 App 后，第一感受必须是：

> 搭子已经根据我的目标、差距、题库表现和申论情况，安排好了今天该怎么提分。

这不是题库首页，不是功能 dashboard，不是 AI 聊天壳。它是一个把题库、申论、岗位、错因、知识片段和计划打包后的 AI 学习工作台。

## 2. 产品判断

### 2.1 护城河

护城河不是“接入大模型”，而是把 AI 变成普通考公用户能直接使用的行业入口。

普通用户不会写 prompt、不会规划任务、不会判断应该练行测还是申论。产品要把 AI 能力包装成下一步动作：

- 今天先做什么；
- 为什么现在做这个；
- 做完后错因是什么；
- 申论答案怎么改成得分表达；
- 明天计划怎么变；
- 岗位风险如何影响备考策略。

### 2.2 产品身份

考公搭子不是“AI + 刷题”，而是“公考学习的 AI 运行环境”。

题库是燃料，不是入口。聊天是交互形式，不是产品主体。

真正入口是：

1. 打开 App：搭子已经排好了今天；
2. 做错题：搭子判断能力错因；
3. 写申论：搭子把答案改成可得分表达；
4. 看岗位：搭子结合分数和限制解释风险；
5. 模考后：搭子重排下一周提分路径。

## 3. 当前 UI 问题

当前 SwiftUI 初版已经能跑通后端闭环，但视觉和信息架构仍有问题：

1. 首页像卡片 dashboard，缺少“AI 正在带你学”的主导感。
2. 今日任务、配比、执行顺序的层级太像普通计划列表。
3. iPad 虽然从三栏硬塞改成了工作台，但仍偏卡片堆叠，不够 NotebookLM 式学习桌面。
4. 行测和申论虽同屏出现，但体验上还没有体现“两个一等学习轨道由 AI 统一调度”。
5. 底部 tab 仍让用户感到自己在选功能，而不是跟随 AI 下一步。

## 4. 必须保留的产品原则

1. 主导航保持 `今日 / 工作台 / 我的`，不要新增行测、申论、题库、选岗等顶层 tab。
2. 行测和申论同等级，但作为 AI 计划中的学习轨道出现，不作为顶层功能入口。
3. 首页第一主张是“今天该干什么”，不是功能选择。
4. 每个 AI 判断必须带来源或证据感，并落到下一步动作。
5. iPad 要像学习工作台：左侧学习对象，中间执行画布，右侧 AI 判断/来源/反馈。
6. 不做假生产用户、不做假 AI fallback、不做假付费状态。
7. 不改变后端权威边界：AI 可生成反馈，不可修改 canonical qbank/payment 权威数据。

## 5. 设计方向

请先产出 3 个 UI 方向，但最后只选择一个落地到 SwiftUI。

### 方向 A：AI 教练驾驶舱

适合商业化、可信、提分导向。

视觉关键词：

- 冷静、清晰、专业；
- 大主任务卡；
- 分数差距/今日提分路径是第一视觉；
- 少装饰，多决策；
- 不要花哨渐变，不要营销 hero。

首页结构：

1. 顶部目标条：广东省考 / 珠三角综合管理岗 / 差距 14 分。
2. 主任务：搭子给你排好了今天 42 分钟。
3. AI 判断：为什么今天先补这个。
4. 行测/申论轨道配比：用时间轴或双轨进度，而不是普通列表卡。
5. 当前 CTA：开始第 1 项。
6. 后面露出今日队列。

### 方向 B：NotebookLM 垂直工作台

适合突出“知识库 + AI 生成学习对象”。

视觉关键词：

- 来源库、学习对象、AI 解释三者并列；
- iPad 强工作台；
- iPhone 上以当前对象为中心；
- 让用户感觉题库/申论/岗位都被 AI 整理成可用对象。

iPad 结构：

- 左：今日队列 + 学习对象库；
- 中：当前任务画布；
- 右：搭子判断、来源、错因、下一步。

### 方向 C：搭子陪练流

适合年轻用户、陪伴感更强。

视觉关键词：

- 像一个有主见的学习搭子；
- 但不要变成聊天软件；
- 用短句、状态、下一步引导；
- 行动感强。

首页结构：

1. 搭子一句话判断；
2. 今天只做 3 件事；
3. 第一件事直接开始；
4. 完成后立即反馈和改计划。

## 6. 推荐落地方向

推荐合并 A + B：

- iPhone 用 A：AI 教练驾驶舱，打开就知道今天怎么提分。
- iPad 用 B：NotebookLM 式垂直工作台，左中右分别承载对象、任务、判断。

不要以 C 为主，因为“搭子陪练”容易变成聊天壳，商业可信度也会弱一点。C 的语气可以保留，但不要主导结构。

## 8. SwiftUI 落地目标

### iPhone 今日

首屏必须由一个明确的 AI 主任务控制：

- “搭子给你排好了今天 42 分钟”
- “先补省联考判断推理 3 题，再做申论概括重写”
- “原因：联考题重复率高，且你昨天错在论证关系”

不要把今日配比和任务顺序做成普通卡片堆叠。可以考虑：

- 顶部目标条；
- 主任务面板；
- 双轨时间条；
- 当前步骤条；
- 底部 CTA。

### iPhone 任务执行

做题页也要体现 AI 带练：

- 题目是执行画布；
- 提交后出现错因判断；
- 解析不是长文章，而是“为什么错 + 同类题怎么识别 + 下一步”；
- 申论是“初稿 -> AI 维度点评 -> 重写 -> 对比”。

### iPad 工作台

iPad 不是放大版 iPhone。

建议：

- 左栏：目标、今日队列、学习对象；
- 中栏：当前任务/对象画布；
- 右栏：AI 判断、来源、错因、下一步动作；
- 减少卡片墙；
- 右栏信息密度要高，但不能乱。
