# 规格：Onboarding（目标锚定）+ 执行页修正 + 时间预算模型

- 日期：2026-07-03
- 作者：fable（规格）；决策：产品负责人
- 执行者：codex（后端 + 数据）、fable（iOS UI，UI 规范见同目录 ui-standards 文档）
- 关联：method-cards 规格（planner 依赖本文件的时间预算与能力基线）
- 前置：positions 岗位明细表（专业要求/往年进面分/招录数）codex 在建，岗位筛选部分等表就绪后实施

## 1. Onboarding 流程（闭环第 1 条"目标锚定"的真正实现）

登录后首次进入（learner.profiles.onboarding_complete = false）走以下步骤，除步骤 1 外均可跳过、可事后在"我的"补：

1. 硬条件：学历、专业（选自专业目录）、应届身份、政治面貌、基层年限。存 profiles。
2. 时间预算（见第 3 节）：全职备考 / 在职碎片。存 profiles.study_mode 与 daily_minutes。
3. 目标岗位：基于硬条件筛选可报岗位（依赖岗位明细表），选定 1 个存 profiles.target_position_id。跳过则为"国考裸分目标"。
4. 能力基线（见第 2 节）。
5. 目标分生成：有岗位 = 岗位近三年进面最低分均值 + 3 分安全边际；无岗位 = 用户自填或默认 130。存 profiles.target_score。
6. 完成后 planner 生成第一天任务流，进今日页。

## 2. 能力基线：自报优先，摸底可选

决策背景：考公用户大量是二战三战，逼所有人做 35 分钟摸底卷是重复劳动；且无法导入粉笔等外部刷题记录，自报是唯一低摩擦方案。

三选一（onboarding 第 4 步）：

- A 自报分数（二战考生主路径）：填最近一次行测分、申论分（可只填一门），可多选自评弱项模块。profiles.baseline_source = self_report。
- B 摸底测验（首考考生推荐）：30 题缩编卷（资料 8 / 判断 8 / 言语 8 / 数量 4 / 常识 2，35 分钟），按模块正确率加权外推预估行测分，出五模块强弱画像。baseline_source = placement_test。
- C 跳过：baseline_source = none，planner 走 R3 诚实冷启动文案。

纪律：自报也是真数据，planner reason 可引用（"你自报行测 58，目标 68，差 10 分"）；摸底画像入工作台成为学习对象；三种来源在 UI 上如实标注（"基于你的自报"/"基于摸底"），禁止把自报包装成"AI 测评结果"。

## 3. 时间预算模型（planner 的硬约束）

决策背景：在职考生时间碎片化，单日塞 90 分钟任务流是自欺；全职考生 30 分钟又太少。时间预算是排程的第一约束。

- profiles 新增：study_mode（fulltime / parttime）、daily_minutes（全职默认 480，在职默认 120，用户可调，上限 720）。修订记录：产品负责人 2026-07-03 指出原默认（240/45）严重低估真实备考强度——上班族日均可投入约 2 小时，全职考生 8-10 小时是常态。
- planner 新增 R0（最高优先级）：当日任务总时长不超过 daily_minutes；在职模式单任务不超过 25 分钟（拆成可在通勤/午休完成的段），全职模式可排 40-120 分钟成块任务、套题与整卷模考。
- 任务粒度：在职 = 10-15 题练习、方法卡学习、单道申论小题，一天 4-6 个任务；全职 = 整模块限时训练、完整申论大题、错题清算、每周模考，上下午晚三个时段分配。
- 今日页文案随模式变化：在职显示"今天 2 小时，5 个任务"；全职按时段给出安排建议。

## 4. 申论材料完整性修正（产品负责人判定为不合理，必须修）

现状：申论执行页只展示简略材料。申论的本质是从材料中提炼，不给全材料等于把练习变成默写。

- 后端：essay 任务响应必须返回完整给定材料全文（materials 数组：每则含序号与全文）。若库中该题材料不全，标记 incomplete 并在任务生成时降权，不准截断后当完整下发。
- iOS：材料区默认展开完整材料，支持逐则折叠、字号调节；作答时材料与答题区可上下分屏对照（iPad 左右分栏）。
- 验收：任一申论任务的材料字数与题库原文一致（查库对比），禁止 summary 字段替代全文。

## 5. 行测草稿改为透明蒙版（替代弹层方案）

现状：草稿纸是独立 sheet，看不到题目，资料分析没法对着数字演算。

- 改为：点击草稿按钮后在做题页上覆盖一层透明画布蒙版（背景 alpha 约 0.05，笔迹不透明），可直接在题干与选项上圈画。
- 蒙版态：底层禁止交互，顶部小工具条（撤销 / 清空 / 关闭蒙版）；笔迹在本题内保留（切题清空），提交答案自动退出蒙版。
- Apple Pencil 与手指均可书写；iPad 上蒙版覆盖中栏画布区域。
- 实施：fable 在现有 ScratchPadView 基础上改造为 overlay 形态。

## 7. 目标分基准 v2：同类岗位组（cohort）+ 数据驱动趋势修正

决策背景（产品负责人 2026-07-03）：国考岗位代码年年变、新设岗位无历史分数，单岗位近三年均分样本太薄。改用同域相似岗位组做基准。

取数层级（逐级回退，取样本足够的最细层级，样本量阈值 n >= 3 条年度分数）：

- L1 该岗位自身近三年进面分（>= 2 年才用）。
- L2 同区县或相邻区县 + 同系统（system_code，如税务）+ 相近报考条件（学历档、专业大类、应届要求）的岗位进面分。示例：报赣州兴国县税务局（工商管理），L2 = 于都/宁都/瑞金等县税务局中工商管理大类可报岗位。
- L3 同地市全部同系统岗位。
- L4 同省同系统。

趋势修正（"越来越卷"）：对命中 cohort 的历年分数做线性趋势拟合，得到年均漂移（可能为正、零或负），目标分 = cohort 最近年均分 + 漂移 x 距考年数 + 3 分安全边际。禁止硬编码"每年 +2"之类常数——扩招年份分数会降，必须由数据说话。

API 与 UI：目标分响应需返回 basisLevel（L1-L4）、样本岗位数、cohort 年度分数列表与漂移值；UI 如实展示依据（"参考赣州税务系统 7 个相似岗位，近三年 126.8-131.2，年均 +1.4"）。样本不足 L4 也凑不齐时返回 null，走用户自填，禁止编造。

实施：codex（positions 域扩展 cohort 查询 + 目标分算法与测试）；测试须构造跨县同系统夹具并断言回退层级正确。

## 8. 近 5 年命题基准（planner 与选题的时效权重)

决策：复习内容以近 5 年国考真题分布为基准，加权而非截断。

- planner 模块/tag 权重按近 5 年国考真题的 tag 频次计算，历史绝迹题型权重归零；
- 练习抽题近 5 年优先（如 70/30 加权），稳定 tag 的老题仍可作为练习材料补充；
- 方法卡产出优先级同步按知识点地图里的近 5 年 tag 权重排（对齐 method-cards 规格 2.2 的排序依据）；
- 数据前提：questions 表需有可靠的年份与考试来源字段；国考卷面 tag 频次统计脚本由 codex 产出，结果落 product 层供 planner 查询。

### 8.5 知识点地图（tag registry / learning map）

补充决策（产品负责人 2026-07-03）：第 8 节的 `product.exam_tag_weights` 只是"近 5 年国考热力图"，回答"优先学什么"；但第 9 节外部错题录入、方法卡匹配、错题复盘还需要一张稳定的"路网图"，回答"这道题属于什么"。两者必须分层：权重不能替代地图，AI 也不能自由创造 tag。

Canonical owner：`product.knowledge_map_nodes`，由 codex 从现有 `product.questions`、`product.question_tags`、`product.exam_tag_weights` 派生并人工治理。它是 product 层资产，客户端只读，运行时不得由 AI 直接写入。

建议表结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| node_id | text PK | 稳定 id，如 `km_xingce_ziliao_xianqibiliang` |
| exam_scope | text | 首期固定 `guokao` |
| track | text | `xingce` / `shenlun` |
| module_name | text | 如资料分析、判断推理、言语理解与表达 |
| node_type | text | `module` / `question_type` / `knowledge_family` / `knowledge_point` / `micro_skill` |
| tag_type | text | 对应 `product.question_tags.tag_type`，可空（模块节点可由 questions.module_name 派生） |
| tag_value | text | 对应 `product.question_tags.tag_value` 或模块名 |
| display_path | text | 给 UI/教研看的完整路径，如 `行测/资料分析/比重/现期比重` |
| parent_node_id | text | 树形主父级；多父级以后再加 edge 表，不在首期复杂化 |
| aliases | jsonb | 近义词、OCR/AI 可能识别出的同义表达，如 `["当前比重", "现期占比"]` |
| support_status | text | `text_supported` / `image_unsupported` / `draft` / `retired` |
| near5_weight | numeric | 从 `product.exam_tag_weights` 同步的近 5 年权重，可空 |
| near5_occurrence_count | int | 近 5 年国考出现次数，可空 |
| stable_for_old_questions | boolean | 老题是否可作为 70/30 补充材料 |
| method_card_ids | jsonb | 已发布/候选方法卡 id 列表 |
| evidence | jsonb | 生成依据：来源 tag、样本题数、是否人工确认 |
| status | text | `draft` / `published` |
| created_at / updated_at | timestamptz | |

建图规则：

- 初始节点只来自已有题库字段：`questions.module_name/display_level*/knowledge_family/teaching_point/micro_skill` 与 `question_tags`，不得由 AI 直接发明新节点；
- `aliases` 可以由 AI 辅助生成，但必须落在已有 `tag_value` 节点上，且低置信别名先为 draft；
- `support_status=image_unsupported` 用于图形推理、图片资料题、视觉识别不稳定的节点；这些节点可统计权重，但不参与方法卡闭环和外部错题自动入库；
- `near5_weight` 只从 `product.exam_tag_weights` 同步，不手填、不硬编码；
- 历史绝迹节点保留为 `published` 或 `retired` 由教研决定，但 planner 权重为 0；retired 节点不再接收新错题；
- 地图变更要有幂等导入/刷新脚本与测试，禁止在 API 请求过程中临时修图。

消费边界：

- planner、模考组卷、方法卡产出优先级用 `knowledge_map_nodes.near5_weight` 排序，而不是散落查询 `question_tags`；
- practice 判分反馈与方法卡匹配以 `node_id`/`display_path` 为主，`tag_value` 只是底层来源；
- 第 9 节外部错题录入只能在 `knowledge_map_nodes` 的候选节点里选择，不能把模型输出的自由文本直接写入 learner 记忆；
- 若候选节点 `support_status != text_supported`、置信度不足、或命中多个相近节点无法区分，返回待用户确认/暂不支持，不写 learner 记忆；
- 申论地图另行扩展为能力维度/题型/材料主题，不与行测知识点强行共用一套 node_type。

验收：

- 每个 published 方法卡的 `tag_path` 必须能映射到一个 `published` 的 `knowledge_map_nodes`；
- 外部错题入库记录必须保存 `node_id`、匹配置信度、候选节点列表和用户是否确认；
- API/测试必须断言：模型返回不存在的 tag 时拒绝入库，不能自动创建节点；
- UI/文案如实标注"基于知识点地图匹配"，禁止写成"AI 已精准识别"。

## 9. "问搭子"入口 + 外部错题录入

决策背景（产品负责人 2026-07-03）：没有课程是产品薄弱项，补法不是做课，而是按需应答 + 收录用户在外部（其他 app 截图、纸质材料拍照）的错题。

问答入口：

- 首页入口，形态为场景化提问而非通用聊天框：预设"这道题为什么错 / 这个知识点怎么学 / 该不该放弃某模块"等场景；
- 回答必须引用用户真实数据（错题史、基线、目标岗位差距）与命中的方法卡，禁止百科式空谈；无相关数据时如实说明；
- 纯 AI 成本项：走 quota + audit，免费档限次。

外部错题录入：

- 拍照/截图 → 多模态模型提取题干选项 → 匹配第 8.5 节 `product.knowledge_map_nodes` 候选节点 → 给出解答与错因 → 用户确认后存入 learner 记忆（source=external），参与 planner 聚合与工作台错题对象；
- 图形推理等图片题面直接拒收并如实告知"暂不支持"；
- 提取失败（模糊/残缺）返回失败原因；匹配不到地图节点、命中 unsupported 节点、或置信度不足时不得入库，禁止硬编 tag 或编造解析；OCR 结果与候选知识点均需用户可校对后再入库。

## 10. 每周模考：智能组卷（不出新题）+ 强制复盘

决策：我们没有出题能力，模考用题库真题按国考蓝图组卷——价值在蓝图、限时与换算，不在新题。周期每周一次（产品负责人 2026-07-03 定），planner 固定排入；在职考生（parttime）默认亦为每周，允许在设置中降为两周一次。

- 组卷：135 题国考结构、五模块配比、tag 按近 5 年频次加权（对齐第 8 节）；排除该用户近 60 天做过的题防记忆污染；
- 执行：严格 120 分钟限时、中途无反馈、不可暂停（贴近真实考试）；交卷后按模块换算预估行测分；
- 复盘（模考价值的一半，不可跳过）：交卷后自动生成复盘对象入工作台——分数与上次对比、模块增减、错题按 tag 聚类、命中方法卡的修复建议；planner 下一周计划必须引用最近一次模考复盘（reason 注明"上周模考资料分析 62.5%，本周加练基期量"）；复盘未查看时今日页顶部持续提示，查看复盘计入模考任务完成条件；
- 诚实纪律：早期无全国分布数据，不给"击败 xx% 考生"排位，只给自身分数趋势与模块对比；自有样本量足够后另评估分位功能；
- 申论整卷模考依赖 AI 判分成本高，首期只做单题限时训练，另出规格。

## 11. 能力估计的持续校准（回应"摸底把握不准"的担心）

架构决定：入职摸底/自报只是低置信度先验，不承诺准确。三层持续校准：

- 先验：摸底 30 题或自报分（低置信度，仅保证第一周计划不离谱）；
- 日常：每日练习按 tag 逐步修正各模块估计（量大，中置信度）；
- 校准器：每周模考全卷校准（高置信度，最接近真实考试）。

UI 纪律：预估分永远标注数据来源与"校准中"状态（如"基于 1 次摸底 + 214 题练习 + 2 次模考"）。每周模考制下，用户入职两周后的能力估计必然优于任何一次性入职测试，产品不必在入职环节追求测准。

| 组卷算法 + 模考 API + 复盘对象生成 | codex |
