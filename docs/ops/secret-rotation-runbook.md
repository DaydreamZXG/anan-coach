# Secret Rotation Runbook

本文只记录密钥轮换流程，不记录任何密钥明文。

## 为什么要换

小程序 `AppSecret` 之前已经出现在对话里。它等价于服务端调用微信接口的密码，一旦进入聊天记录、截图、日志或仓库，就不能再当作只被服务端知道。

轮换不是让负责人学习安全工程，而是做一次“换锁”：

1. 在微信小程序后台重置/生成新的 `AppSecret`。
2. 把新值只放到服务端受控环境变量或密钥管理里。
3. 重启后端服务。
4. 用真实登录/换取 session 的流程验证新密钥可用。
5. 确认旧密钥不可用。
6. 扫描仓库、配置样例、构建日志和服务日志，确认没有新的明文泄露。

## 谁负责

- 账号持有人：在微信后台完成重置动作。
- 后端部署负责人：把新 secret 写入服务端环境，不写入仓库、不粘贴到聊天。
- Codex/工程侧：更新配置引用、测试、扫描脚本和治理证据，但不接收明文 secret。

## 微信小程序 AppSecret 轮换检查单

- [ ] 微信后台已重置 AppSecret。
- [ ] 新值只存放在服务端环境变量 `WECHAT_MINI_APP_SECRET` 或受控密钥存储。
- [ ] `ops/env.example` 仍只保留空占位，不包含明文。
- [ ] 后端服务已重启。
- [ ] 微信登录或 code 换 session 的集成检查通过。
- [ ] 旧 AppSecret 调用已失败或确认失效。
- [ ] 仓库当前文件不包含明文 secret。
- [ ] 构建日志、服务日志、终端输出没有打印 secret。

## TOS / AI / 支付等其他密钥

同一原则适用于 TOS AccessKey、AI provider key、支付证书和未来短信/语音/OCR key：

- 密钥不进仓库。
- 密钥不进聊天。
- 密钥不出现在日志。
- 每个密钥只登记“存放位置类别、负责人、轮换状态、验证命令和时间”，不登记值。

## 完成证据

完成后只保存这些证据：

- 验证命令名称与时间。
- 通过/失败状态。
- 不含密钥的 HTTP 状态、错误码或测试报告。
- 操作人和环境。
- 旧值已失效的证明。

不要保存密钥本身、截图中的密钥、复制过的密钥或能反推出密钥的片段。
