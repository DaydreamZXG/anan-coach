## 1. 先读这一页

### 1.1 岸岸是什么

岸岸是一位面向国考备考者的 AI 学习教练。它把岗位目标、可用时间、行测表现、申论训练和复盘证据放进同一条学习闭环，帮助用户每天知道：

- 我离目标还有多远；
- 今天有限的时间应该先做什么；
- 做完以后暴露了什么问题；
- 下一次计划应该怎样调整。

产品不是把题库、课程、聊天机器人和日历简单放在一起，而是让它们围绕同一份学习事实协同工作。用户看到的是一位持续了解自己的教练“岸岸”；内部的岗位、教学与规划能力共享同一套学习档案和证据。

### 1.2 一句话定位

**以目标岗位为方向、以真实学习证据为依据，为国考备考者持续生成并调整每日行动的 AI 教练。**

### 1.3 它不是什么

- 不是承诺上岸结果的“押题神器”；
- 不是只看刷题数量的题库；
- 不是用一句 AI 建议替代岗位资格核验或学习证据；
- 不是只会聊天、无法落到行动的陪伴机器人；
- 不是用精确概率制造虚假确定性的报考决策工具。

### 1.4 文档中的状态含义

为了避免把目标写成现状，本文使用四类状态：

| 状态       | 含义                                       |
| ---------- | ------------------------------------------ |
| 当前       | 已能从现有产品、代码或已接受决策中确认     |
| 已确认边界 | 产品必须遵守，但不代表每处实现都已完成验收 |
| 目标       | 产品希望形成的完整体验，需要按版本持续交付 |
| 未知或阻断 | 仍缺生产证据、真实用户数据或明确数值门槛   |

本文不以“页面存在”推导“功能已经达到生产可用”，也不以“AI 测试通过”替代确定性回归和真实用户验证。

## 2. 用户与核心问题

### 2.1 主要用户

岸岸服务正在准备国考、愿意投入学习但缺少持续反馈闭环的人，重点包括：

1. **第一次备考者**：不了解岗位筛选、行测模块和申论训练如何组织，需要从建档开始被带上手。
2. **已有外部学习经历者**：已经在纸质资料、其他题库或线下课程中学习，希望把分数、错题和报告带回来统一管理。
3. **二战或多次备考者**：有大量历史经验，但容易重复旧方法，需要重新识别稳定短板和无效努力。
4. **在职备考者**：每天时间波动明显，需要根据真实可用时间自动缩放任务，而不是承受计划债务。
5. **高强度冲刺者**：可投入时间较长，需要足量、透明且结构合理的训练，而不是被人为限制成少数大任务。

### 2.2 用户真正难的不是“没有内容”

国考学习内容很多，但用户更常遇到的是：

- 岗位目标与学习计划脱节；
- 行测和申论各自训练，无法形成统一进度判断；
- 学了很多，却说不清哪种错误在反复出现；
- 每日计划过少、过多或粒度不透明；
- 临时中断后，旧任务不断累积成心理负担；
- 外部练习无法进入自己的能力画像；
- AI 给出结论，却没有展示依据或不确定性；
- 做对一次就被当作掌握，造成虚假进步。

岸岸的核心价值，是把这些分散问题接成一条可持续更新的学习闭环。

## 3. 产品原则

### 3.1 目标岗位决定方向，但不制造录取承诺

岗位要求、招录条件、目标分差和竞争信息用于确定学习方向。资格条件必须以可核验来源为准；对竞争和结果只能表达区间、条件与不确定性，不给出伪精确“上岸概率”。

### 3.2 证据先于结论

能力判断、错因归类、计划调整和 AI 建议都应尽量回到原始作答、成绩、训练记录、用户确认或可追溯规则。没有证据时，应明确标注为候选判断或信息不足。

### 3.3 行测与申论是平行的一等学习轨道

两条轨道可以采用不同训练方式，但共同进入今日计划、时间预算、复盘、能力更新与目标差距判断。不能因为行测数据更容易量化，就让申论退化成附属入口。

### 3.4 计划必须能执行，也必须解释得清

任务保留真实的原子训练单位。相同类型的重复训练可以折叠成一个透明队列，但必须告诉用户剩余组数与总预计时间。

计划数量不设任意的“每天 3—5 个任务”上限。用户可学 8 小时，就应按有效时间和训练结构提供相称的学习量，而不是用几个超大任务掩盖实际工作。

### 3.5 周偏好提供默认值，用户只在需要时调整

用户已经设置的每周学习时间，应形成当天有效的默认可学时长。没有变化时不要求每天重复确认；“调整今天”作为显式覆盖入口保留给临时加班、休息或冲刺。

### 3.6 AI 可以提出候选，不能悄悄改写事实

AI 可以解释、归纳、生成建议和提出错因候选，但不能直接覆盖原始成绩、资格事实、已确认标签或已发布内容。关键更新应经过规则校验、用户确认或明确发布流程。

### 3.7 做完、做对与掌握是三件事

一次完成只能证明发生过学习，一次做对只能证明当时答对。稳定掌握需要变式题、延时复测或连续证据，避免用即时正确率制造能力幻觉。

### 3.8 重新计划不是惩罚

没有完成的任务不应无限滚动成债务。系统应结合剩余时间、任务价值和最新证据重新编排，清楚说明哪些保留、推迟、替换或取消。

### 3.9 用户数据权利不应被会员状态锁住

用户应能查看和管理自己的核心学习数据、授权与隐私选择。未来即使开放付费，也不能用会员到期阻断基本的数据访问、撤回授权或注销权利。

## 4. 核心学习闭环

岸岸的主循环是：

**建档与定岗 → 初始诊断 → 时间预算 → 今日计划 → 行测、申论或模考执行 → 作答复盘与错因 → 变式或延时复测 → 能力与目标分差更新 → 下一轮计划**

每天结束形成日结算，每周形成周回顾；当用户时间、目标岗位、考试阶段或能力证据发生明显变化时，触发重新计划。

### 4.1 闭环中的关键产物

| 阶段       | 关键输入                     | 用户获得               | 沉淀的证据                 |
| ---------- | ---------------------------- | ---------------------- | -------------------------- |
| 建档与定岗 | 基本情况、考试目标、岗位偏好 | 清晰的目标范围         | 用户档案、岗位条件         |
| 初始诊断   | 历史成绩、诊断训练、自我情况 | 当前起点               | 模块表现、申论样本、置信度 |
| 时间预算   | 周偏好、当天覆盖、考试日期   | 可执行容量             | 有效学习时长               |
| 今日计划   | 目标分差、能力状态、复习节奏 | 今天先做什么           | 计划版本、任务来源         |
| 学习执行   | 作答、材料、外部成绩         | 训练与即时反馈         | 原始答案、耗时、得分       |
| 复盘复测   | 错题、错因候选、变式题       | 为什么错、是否稳定掌握 | 确认错因、复测结果         |
| 能力更新   | 多次训练与复测               | 能力变化和目标差距     | 可追溯的能力证据           |
| 计划调整   | 新证据、剩余时间、用户覆盖   | 下一步行动             | 调整原因、任务变更         |

## 5. 信息架构

### 5.1 四个主导航

当前小程序采用四栏主导航：

| 主导航 | 用户问题               | 核心职责                                               |
| ------ | ---------------------- | ------------------------------------------------------ |
| 今日   | 我今天做什么？         | 今日计划、首要任务、学习队列、日结算、周计划与模考入口 |
| 能力   | 我现在学得怎么样？     | 行测与申论能力、错题与错因、报告、复测状态、目标差距   |
| 岸岸   | 我该怎么理解和调整？   | 基于学习上下文的 AI 教练、解释、建议与追问             |
| 我的   | 我的目标和资料在哪里？ | 档案、岗位、资料库、方法卡、账号、隐私、通知与服务设置 |

四栏职责在手机、竖屏平板和横屏平板上保持一致。横屏可以改变布局密度和信息并列方式，不能改变业务含义。

### 5.2 支撑业务域

主导航背后包含：

- 登录、授权与新手建档；
- 岗位筛选、资格核验与目标管理；
- 今日计划、周偏好与重新规划；
- 行测训练、错题、错因与变式复测；
- 申论材料、作答、批改、报告与复练；
- 模考、外部成绩与能力报告；
- 拍照识别、内容导入与私人资料库；
- 方法卡与受约束的学习社区；
- 账号、通知、隐私、数据与服务管理。

### 5.3 当前代码可观察规模

截至本文版本，当前小程序有 60 条注册页面路由：主包保留登录页与四个主导航页，共 5 页；其余 55 页分布在 15 个分包中。这个数字只说明当前代码覆盖范围，不等同于所有场景均已完成生产验收。

## 6. 完整用户旅程

### 6.1 登录与新手建档

目标是以最少但必要的信息，让用户第一次进入“今日”时已经得到可理解的行动，而不是面对空白首页。

建议旅程：

1. 阅读并主动同意隐私政策和用户协议；
2. 完成微信登录与账号建立；
3. 说明报考阶段、考试时间与基础情况；
4. 选择或建立目标岗位范围；
5. 设置每周可学习时间和常见日程；
6. 导入历史成绩，或完成轻量初始诊断；
7. 生成第一份今日计划；
8. 用一句话解释计划依据，并提供“调整今天”。

对已经学习过的账号，不应强制重走新手教学；应允许导入历史数据、补做诊断或直接进入现有学习状态。

### 6.2 第一次今日计划

首屏优先回答三件事：

- 今天可投入多少有效时间；
- 为什么先做这一项；
- 完成以后接下来是什么。

用户点击“开始第一项任务”进入具体训练。重复的同类训练应展示为清晰队列，例如“言语理解：共 13 组，预计 390 分钟”，而不是突然生成 13 张几乎相同的卡片，也不能把 13 组合并成一个不可理解的大任务。

### 6.3 行测训练闭环

1. 从今日任务、能力页、错题或专项入口开始；
2. 进入题组并记录作答、耗时和答案；
3. 展示正确答案、解析和必要的知识点；
4. 用户查看或确认错因，AI 可提供候选解释；
5. 错题进入待复习状态；
6. 系统安排变式题或延时复测；
7. 复测证据进入模块能力更新；
8. 后续计划根据薄弱点、遗忘节奏和目标分差调整。

### 6.4 申论训练闭环

1. 从今日任务、申论模块、模考或历史报告开始；
2. 阅读材料与题目，完成分段或整题作答；
3. 保存原始答案与版本，避免 AI 反馈覆盖用户原文；
4. 根据明确量表提供结构、要点、表达与证据反馈；
5. AI 建议必须说明依据，无法确定时标注不确定；
6. 用户修订或进行同类复练；
7. 前后版本、量表变化和复练结果进入申论能力记录；
8. 申论与行测共同参与今日时间分配和整体目标差距判断。

### 6.5 日结算、周回顾与重新计划

日结算回答“今天发生了什么”，周回顾回答“这一周是否向目标靠近”。至少应区分：

- 计划了但未开始；
- 已开始但未完成；
- 已完成但尚未复测；
- 复测后仍不稳定；
- 已形成较稳定掌握证据。

重新计划时，系统应说明调整原因。用户临时减少时间时，优先保留高价值任务；时间增加时，可以补充合理训练，而不是要求重新确认整套学习偏好。

## 7. 十个核心产品域

### 7.1 岗位与资格

**产品目标：** 让用户知道自己能报什么、想报什么，以及当前学习目标由何而来。

当前产品包含岗位搜索、职位详情、收藏或目标、资格核验和岗位相关入口。资格判断必须保留来源、条件和不确定信息；AI 可以帮助解释条件，不能凭空补齐政策事实。

岗位模块最终向计划系统提供考试时间、目标范围、分数参照和优先级，而不是成为一座独立信息孤岛。

### 7.2 今日计划与时间预算

**产品目标：** 把长期目标变成当天可执行的学习队列。

计划输入包括目标分差、能力证据、复习节奏、周学习偏好、当天覆盖与考试阶段。输出不仅是任务列表，还应有预计时间、优先顺序、来源理由和调整入口。

相同专项的重复训练允许折叠展示；任务内部仍保留原子单位，便于暂停、结算、复测和重排。

### 7.3 行测

**产品目标：** 形成“训练—错因—复测—能力更新”的证据链。

产品覆盖专项训练、题组作答、解析、错题、错因、复习队列、变式与报告。判断能力时不能只看题量或单次正确率，还要结合题型、难度、耗时和复测稳定性。

### 7.4 申论

**产品目标：** 让用户的原始作答、反馈、修订和复练能够被持续比较。

申论不是一条普通聊天记录。系统应保留材料、题目、答案版本、评价量表、反馈依据和复练结果。AI 批改属于辅助判断，应与明确规则、参考要点和人工可理解的解释共同呈现。

### 7.5 能力、报告与目标差距

**产品目标：** 用可追溯证据回答“我变好了没有”和“下一步补哪里”。

能力页同时承载行测与申论状态、错题错因、复测结果、模考报告和目标差距。能力变化应能回到具体训练证据；证据不足时显示置信度或“待验证”，不画出虚假的精密曲线。

### 7.6 岸岸 AI 教练

**产品目标：** 让用户在关键时刻得到与自己当前学习状态相关的解释和下一步建议。

岸岸不是万能问答框。它应优先使用用户已授权的岗位、计划、作答、错题和报告上下文，回答“为什么这样安排”“这次问题在哪里”“今天如何调整”等学习问题。

表达风格是站在用户身边、克制而具体：不羞辱、不制造焦虑、不空泛夸奖、不承诺结果。重要建议尽量给出依据和可执行动作。

### 7.7 拍照识别、外部导入与私人资料库

**产品目标：** 让纸质资料、其他平台和线下学习产生的有效证据回到岸岸。

内容识别后应区分四种结果：

1. 找到精确匹配；
2. 找到若干相似候选；
3. 只有 AI 生成的未核验候选；
4. 无法可靠识别。

上传、查看、搜索或保存资料不等于完成训练，更不等于掌握。只有符合学习事件定义的作答、评分、复盘或复测，才能进入能力证据。

### 7.8 模考、外部成绩与报告

**产品目标：** 把阶段性测量接入长期学习闭环。

用户可以从完整模考、分模块测试或外部成绩进入报告。报告应区分原始分数、规则计算和 AI 解释，并把结论落到下一阶段任务。一次模考只能作为一个时间点的证据，不直接代表稳定水平。

### 7.9 方法卡与学习社区

**产品目标：** 让有效学习方法可以被复用，但避免社区热度替代证据。

官方方法卡与用户社区卡分开管理。社区当前边界不包含自由评论、楼中楼或私信，降低骚扰与内容治理风险。

“有用”不应只是随手点赞；理想情况下，用户需要实际接触方法并在新的独立问题中获得帮助后再形成反馈。产品不以裸热度榜作为学习方法有效性的证据。

### 7.10 我的、通知与数据权利

**产品目标：** 集中管理用户档案、目标、资料、授权、通知、隐私与服务状态。

“我的”不是杂项仓库。它应清楚区分学习资产、账号设置、消息提醒、隐私授权、数据导出或删除以及服务说明。敏感操作需要明确后果、二次确认和可追溯记录。

## 8. AI 与学习事实模型

### 8.1 四层信息

| 层级               | 示例                               | 产品处理               |
| ------------------ | ---------------------------------- | ---------------------- |
| 原始事实           | 用户答案、耗时、原始成绩、岗位公告 | 原样保存，可追溯来源   |
| 确定性计算         | 正确率、时间汇总、规则资格结果     | 保存规则版本和输入     |
| AI 候选            | 错因推测、申论要点建议、计划解释   | 标注为候选或辅助判断   |
| 用户确认或正式发布 | 用户确认的错因、已发布的方法卡     | 记录确认者、时间与版本 |

### 8.2 AI 不能越过的边界

- 不能伪造题目来源、岗位政策或成绩；
- 不能直接把推测写成已确认错因；
- 不能覆盖用户申论原文；
- 不能给出无依据的精确录取概率；
- 不能把自然语言“看起来完成了”当作学习完成事件；
- 不能在缺少授权时调用私人资料；
- 不能用 AI 云测结果替代确定性自动化测试；
- 不能用励志话术掩盖证据不足。

### 8.3 认知科学表述边界

产品可以说“用间隔复习、提取练习、变式复测等认知科学方法进行设计”，但目前不能宣称这些机制已经在岸岸真实用户群体中证明了提分效果。机制映射已经存在，结果有效性仍需要真实队列与长期数据验证。

## 9. 页面、网络与业务状态

完整产品不能只设计“成功页面”，还要覆盖：

### 9.1 账号状态

- 未登录；
- 已登录但未完成建档；
- 建档完成但缺少诊断证据；
- 已有完整学习状态；
- 登录过期或授权被撤回；
- 已注销或处于数据处理期。

### 9.2 内容状态

- 加载中；
- 首次空状态；
- 正在识别、评分或生成；
- 已完成；
- 结果部分可用；
- 内容过期或版本冲突；
- 无法识别或证据不足。

### 9.3 故障与恢复

- 弱网、断网与请求超时；
- 微信权限被拒绝；
- AI 服务或识别服务暂不可用；
- 提交结果未知，需要幂等查询或安全重试；
- 多设备同时编辑导致版本冲突；
- 页面退出后继续处理并可回到结果；
- 本地暂存恢复与服务端状态对齐。

涉及答案提交、任务完成、支付等未来高风险动作时，不能简单把超时当作失败重做，必须先判断服务端是否已经成功处理。

## 10. 手机与平板体验

### 10.1 响应式原则

| 设备形态     | 布局策略                                               |
| ------------ | ------------------------------------------------------ |
| 手机         | 单列主路径，首要任务优先，底部导航稳定                 |
| 竖屏平板     | 有最大内容宽度的舒展单列，避免卡片被无限拉宽           |
| 横屏平板     | 主任务与辅助信息形成清晰双区，控制行宽、间距和视觉层级 |
| 长材料与报告 | 条件允许时使用材料与作答、总览与明细的双栏结构         |

适配不是把卡片简单拉长。卡片之间、卡片内部模块之间以及主次操作之间都需要稳定的呼吸空间；按钮文案不能因为窄列被挤成逐字竖排。

响应式变化只改变信息排布，不改变四个主导航、任务含义、完成规则或学习证据。

### 10.2 视觉与语言

界面应安静、清晰、可信，让用户感到“有人帮我把复杂事情理顺了”。岸岸的语言应：

- 先说明事实，再给判断；
- 给出下一步，而不是只描述问题；
- 承认不确定性；
- 避免责备、恐吓和过度亲昵；
- 避免“稳赢”“稳上”“百分百提分”等承诺。

## 11. 商业模式与服务边界

### 11.1 当前状态

当前支付能力关闭，没有购买入口；用户无需开通会员即可直接使用现有服务。

这是一项当前运营状态，不构成对未来价格的承诺。未来如开放会员或付费服务，需要单独完成商品、权益、订单、支付、退款、对账、客服、隐私和消费者权益验收。

### 11.2 未来商业化必须遵守

- 免费与付费权益清晰可比较；
- 购买前展示价格、周期、自动续费情况与退款规则；
- 支付结果可查询、可对账、可安全重试；
- 已购权益不能因短暂网络问题丢失；
- 核心数据访问、隐私撤回与注销不受会员状态阻断；
- 不通过制造焦虑、虚假稀缺或上岸承诺促成购买。

在支付能力正式启用前，不应对外描述尚未验收的会员权益。

## 12. 隐私、安全与可靠性

### 12.1 已确认边界

- 只收集完成明确功能所必要的数据；
- 在收集前说明用途，并记录有效同意；
- 私人资料默认不公开，不因进入 AI 上下文而改变可见性；
- 用户能够管理授权、数据和账号；
- 敏感数据有访问控制，关键变更可审计；
- 备份、恢复与删除策略必须与对外承诺一致。

### 12.2 当前不能掩盖的缺口

| 项目           | 当前事实                                                           | 产品影响                         |
| -------------- | ------------------------------------------------------------------ | -------------------------------- |
| 服务端同意记录 | 已有同意事件数据结构，但当前登录协议勾选尚未形成完整服务端写入证据 | 正式放量前需补齐可审计的同意链路 |
| 生产备份与恢复 | 当前备份开关未启用，尚无完整恢复演练证据                           | 在真实用户数据放量前属于阻断项   |
| 商业级数值门槛 | 性能、容量、可用性、恢复、AI 质量与成本等阈值仍待确认              | 不能仅凭功能测试宣称商业生产就绪 |

## 13. 衡量产品是否真的有用

### 13.1 北极星方向

建议用“每周完成有效学习闭环、且有证据显示目标差距改善的活跃用户”作为北极星方向。

它要求用户不只是打开应用或刷题，而是至少发生计划、执行、复盘或复测、能力更新中的完整链路，并观察较长周期的趋势。

### 13.2 领先指标

- 建档后成功获得第一份计划的比例；
- 第一项任务开始率与完成率；
- 今日计划按有效时间完成的比例；
- 错题进入复测并获得新证据的比例；
- 行测与申论双轨持续学习率；
- 周回顾查看与有效调整率；
- 外部成绩成功接入闭环的比例；
- AI 建议被采纳、被修改和被拒绝的分布；
- 计划解释被打开后发生调整或执行的比例；
- 次周、四周留存与学习中断后的恢复率。

### 13.3 不能当作效果证明的数字

- 页面访问量；
- AI 对话轮数；
- 生成任务数；
- 总刷题量；
- 单次正确率；
- 方法卡点赞数；
- 一次云测或 AI 测试的“通过”结果。

这些数字可以诊断使用情况，但不能单独证明学习有效或产品已经稳定。

## 14. 当前产品状态

### 14.1 已能从当前产品与代码确认

- 微信小程序采用“今日、能力、岸岸、我的”四栏主导航；
- 登录、新手建档、岗位、计划、行测、申论、AI 教练、报告、导入识别、私人资料、社区和账号隐私等业务入口已形成代码覆盖；
- 小程序已有 60 条注册页面路由，并采用主包加 15 个分包的结构；
- 当前支付关闭，没有购买入口；
- 主包体积已压到微信 1.5 MiB 质量线以内；
- 已建立确定性 Minium 自动化方法与云测流程；
- 0.1.10 的完整云回归仍以最终报告为准，AI 探索测试只作补充。

### 14.2 仍需验证或解决

1. 生产备份、恢复演练与真实恢复时间；
2. 登录协议同意的服务端审计链路；
3. 0.1.10 全量云回归最终结论及失败项闭环；
4. 性能、容量、可用性、安全和 AI 质量的正式数值门槛；
5. 不同基础、不同可用时间用户的计划质量；
6. 行测和申论能力更新是否与真实长期表现一致；
7. 真实用户队列中的提分效果、留存与中断恢复；
8. 长材料、弱网、多设备和无障碍体验。

因此，当前适合描述为“功能面较完整、正在进行全量验证和公开内测准备”，不应描述为“已经完成商业生产验证”。

## 15. 暂不进入当前承诺的范围

- 事业单位考试等其他考试品类；
- 正式支付、会员售卖与自动续费；
- 完整客服工单系统；
- 用户可见的手工备份管理；
- 社区自由评论、楼中楼和私信；
- 精确上岸概率或结果保证；
- 把“训练”增加为第五个主导航；
- 用宠物或纯游戏化形象替代岸岸教练。

这些方向可以进入后续研究，但不能提前写进当前对外能力清单。

## 16. 对外介绍口径

### 16.1 推荐简介

> 岸岸是一款面向国考备考者的 AI 学习教练。它把目标岗位、可用时间、行测与申论训练、错题复测和能力变化放进同一条学习闭环，帮你看清差距、安排今天，并根据真实学习证据持续调整下一步。

### 16.2 可展开的卖点

- **不是固定课表：** 根据目标、能力证据和当天时间持续调整；
- **行测申论双轨：** 两类学习共同进入计划和能力判断；
- **错题不止收藏：** 从错因到变式、延时复测再到能力更新；
- **外部学习能回来：** 支持把纸质资料、外部成绩和历史报告纳入自己的学习档案；
- **AI 有边界：** 重要结论尽量展示依据，推测与事实分开；
- **手机平板都能学：** 同一学习语义，针对不同屏幕组织信息。

### 16.3 禁止或暂不使用的表述

- “保证上岸”“稳过国考”“百分百提分”；
- “精准预测录取概率”；
- “已经科学证明有效”；
- “AI 自动替你做出报考决定”；
- “永久全部免费”；
- “全平台、全机型零问题”；
- “已经达到商业生产级”，除非全部发布门槛和生产证据已完成。

## 17. 版本推进建议

### 17.1 近期：把当前闭环验证扎实

- 完成全量云回归并闭环失败项；
- 用新手账号、已有学习状态账号和多种学习时长验证计划；
- 补齐服务端同意记录；
- 启用并演练生产备份恢复；
- 验证手机、竖屏平板和横屏平板的核心路径；
- 建立关键学习事件和计划解释的可观测性。

### 17.2 中期：验证计划与能力判断质量

- 对比不同基础和不同时间预算下的任务结构；
- 验证复测是否比单次正确更能解释后续表现；
- 建立申论多版本和量表一致性评估；
- 观察用户为何调整或拒绝 AI 建议；
- 用真实队列验证四周留存和目标差距趋势。

### 17.3 后续：在证据充分后扩展

只有核心闭环稳定、生产安全边界完成且真实用户价值成立后，再评估支付、更多考试品类、更丰富的社区能力或新的主导航结构。

## 18. 术语表

| 术语           | 定义                                                 |
| -------------- | ---------------------------------------------------- |
| 学习事实       | 用户原始答案、耗时、成绩、材料、确认标签等可追溯信息 |
| 学习证据       | 能够支持某项能力或计划判断的事实及其上下文           |
| 原子任务       | 可独立开始、暂停、完成和结算的最小训练单位           |
| 透明队列       | 把多个相同原子任务折叠展示，同时保留数量与总时间     |
| 错因候选       | AI 或规则提出、尚未由用户或验证流程确认的错误原因    |
| 复测           | 在新的题目、变式或延时场景中再次检验                 |
| 能力更新       | 根据新增证据调整模块或题型状态，而非直接覆盖历史     |
| 目标分差       | 当前能力证据与目标要求之间的估计差距                 |
| 当天覆盖       | 用户对当天默认可学时长做出的临时调整                 |
| 未开放购买阶段 | 当前支付关闭、没有购买入口的运营阶段                 |
