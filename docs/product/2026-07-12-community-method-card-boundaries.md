# 社区方法卡、效果验证与贡献奖励边界

> 状态：商业发布基线
> 日期：2026-07-12
> 适用：方法卡、外部错题、解题 Agent、全局资料检索、社区与商业权益

## 1. 产品决策

允许用户上传、编辑和公开分享自己的解题方法，但不建设以点赞数为真相的内容社区。社区方法卡的核心问题不是“谁更受欢迎”，而是：

1. 这个方法适用于什么题，不适用于什么题？
2. 它是否与题目答案、题库标签和国考规则冲突？
3. 其他用户看完后，是否能在未见过的同类题上迁移？
4. 对哪类能力、速度和错误模式的用户有效？

社区不建设文字评价系统。用户实际使用后可投一张“对我有用”票，并可选择固定、非文字反馈；没有用户输入的评语、公开评论和回复。“奖励”使用**有效贡献和迁移证据的可审计奖励**，不按裸票数发放。

## 2. 两层方法库

### 2.1 正式方法库

`product.method_cards` 继续是系统正式方法的唯一 owner：

- 使用稳定知识地图节点和发布版本。
- 必须有回测题集、适用/排除范围、错误特征和发布证据。
- 可以作为解题 Agent 的默认资料、复盘依据和规划任务。
- 社区热度不能直接修改其内容、优先级和发布状态。

### 2.2 社区方法库

社区内容使用独立领域和数据表，不写入 `product.method_cards`：

| 对象 | 用途 |
|---|---|
| `community_method_cards` | 稳定卡片 ID、作者和当前状态 |
| `community_method_card_versions` | 每次编辑后的不可变内容、来源声明和结构版本 |
| `community_method_card_reviews` | 自动结构、去重、安全、版权和题库一致性检查 |
| `community_method_card_exposures` | 哪个用户在什么作答阶段看到了哪个版本 |
| `community_method_card_trials` | 看卡后的新题、用时、正确性、基线和迁移结果 |
| `community_method_card_votes` | 实际使用并完成新题后的“对我有用”票和固定信号 |
| `community_method_card_reports` | 错误、不适用、抄袭、广告、不当内容和证据 |
| `community_contribution_rewards` | 奖励原因、里程碑、数量、发放/撤回和关联证据 |

社区卡被采纳进正式方法库时，也是一次显式、可审计的派生发布，必须保留原作者和来源版本，不是直接更改社区卡状态。

## 3. 创作流程

```text
文字 / 语音 / 手写照片 / 错题复盘
  → 个人私有草稿
  → AI 结构化（识别、适用、步骤、排除、坑点、用时）
  → 作者逐字确认
  → 提交公开候选
  → 去重 + 内容安全 + 来源 + 题库一致性检查
  → 限量试用
  → 独立用户的新题迁移验证
  → 社区已验证 / 继续试用 / 限制展示 / 退役
```

个人可以长期保留私有方法卡，不必公开。AI 只是结构化工具，作者确认的版本才能提交；不得将用户的复盘自动发布为社区内容。

## 4. 状态机

```text
private_draft
  → submitted
  → automated_review
  → trial
  → community_validated
  → retired

automated_review → revision_required | rejected
trial / community_validated → restricted → automated_review
```

- 每次修改生成新版本，不覆盖旧版本。
- 内容步骤、适用范围、排除范围或关联知识节点变更后，新版本重新进入试用，不继承旧版本的效果分。
- 达到错误或风险阈值时先自动限制展示，不等待人工处理才停止传播。
- 状态转移必须写入决策版本、规则/模型版本、证据和原因。

## 5. 投票边界

用户只有在系统记录过方法卡曝光，并完成一道独立新题后，才能投一张“对我有用”票。投票记录关联用户、卡片版本、曝光、新题试用和时间，可附带 `clear`、`actionable`、`not_applicable` 等固定信号，但任何 API 和页面都不提供评价文字字段。

- 每个用户对同一卡片版本最多一票。
- 作者不能给自己的卡投票。
- 没有“没用”或“踩”；认为方法错误、误导、抄袭或不适用时使用独立举报流程并提供证据。
- 不展示用户名单，不建设用户评语、公开评论、回复和争论区。
- 投票不可转让、购买、奖励互换或用于改变题目答案。

## 6. 效果分与排序

社区卡使用类型化效果摘要，不显示星级、评分或单纯票数排行。排序输入包括：

1. 独立试用用户数和有效试用数。
2. 使用卡前的用户基线，以及新题正确率/用时的变化。
3. 延时复测是否仍有效，避免只测当时记忆。
4. 知识节点、题型、难度、用户错因和速度区间的匹配程度。
5. 有效“对我有用”票的保守下界，只作为辅助信号。
6. 效果不确定性的保守下界，而不是小样本的平均数。
7. 错误、不适用、抄袭、广告和异常互投网络的风险惩罚。
8. 卡片版本的新鲜度和当前国考适用性。

排序输出是对当前用户和当前题的个性化匹配，不是全站方法卡排行榜。社区试用卡可在提交后作为“其他考生的一种思路”选看，未达到 `community_validated` 前不能成为规划 Agent 的必做任务或解题 Agent 的默认依据。

## 7. 奖励边界

奖励不与上传数、浏览量或裸投票数直接挂钩。可奖励的里程碑包括：

- 候选通过自动一致性检查并进入试用。
- 获得足够多独立、有效的新题迁移证据。
- 在指定适用人群中达到保守效果阈值。
- 发现其他卡片的真实错误，且举报被证据确认。
- 方法卡被正式方法库派生采纳。

首批奖励使用有上限、不可转让的 AI 场景额度或会员服务时长，不发放现金、可提现代币或可交易道具。原因是需要先验证作弊、税务、退款和内容责任边界。

每一笔奖励都必须：

- 使用唯一奖励事件和幂等键。
- 记录规则版本、证据、发放前后权益和成本。
- 对同一作者、卡片、里程碑和周期封顶。
- 在抄袭、刷量或效果证据被撤销后可审计地撤回未消耗奖励。
- 不因会员身份改变方法卡效果排名。

## 8. 作弊与内容风险

- 作者、同设备/异常账户簇和异常互评网络不计入独立验证数。
- 不建设私信、群聊、用户评语、公开评论区和外链。
- 用户必须声明拥有方法文字的分享权；从第三方课程、图书或截图识别出的内容默认只能作为私有草稿。
- 公开卡只展示作者自己的方法表述和允许公开的题目引用，不公开上传的原图、其他 App 解析和第三方水印内容。
- 题目答案冲突、适用范围过宽、广告、联系方式、恶意指令或高风险举报会自动进入 `restricted`。

## 9. 与解题 Agent 和全局资料库的边界

- 正式方法卡是默认可检索证据。
- `community_validated` 可以作为“社区已验证思路”检索，引用时必须标识社区来源、卡片版本、适用范围和验证样本。
- `trial` 只在提交作答后侜用户主动试用，不进入全局 Agent 的默认检索结果。
- `private_draft`, `submitted`, `automated_review`, `restricted`, `rejected` 和 `retired` 不对其他用户检索。
- 社区卡不能作为题目答案真值、岗位硬条件或用户能力的直接证据。

## 10. 付费边界

- 创建私有方法卡、手工编辑、提交公开、参加有效试用、投有用票、举报和查看自己贡献永久不因会员到期被锁定。
- 已公开的社区方法卡不因作者或读者会员身份改变排名。
- AI 语音转写、手写识别、自动结构、个性化匹配和深度迁移分析使用透明的场景额度；贡献奖励可抵扣这些额度。
- 不允许支付提高社区卡排名、跳过验证、撤销错误举报或购买投票。

## 11. 验收门禁

- 修改社区卡会生成新版本，新版本不继承旧版本效果分。
- 未完成新题试用的用户无法投“对我有用”票，任何用户都无法提交评价文字或公开评论。
- 作者、关联账户和异常互评网络不计入独立验证。
- 卡片状态、排序和奖励都能回放至规则、模型、证据和数据版本。
- `trial` 内容不会被规划 Agent 当作必做任务，也不会被全局问答当作默认方法。
- 限制或退役不删除历史引用，但新回答不再展示其为可用建议。
- 任何支付都不能改变内容验证和排序结果。
