# 总分证据与能力估计版本契约

> 状态：执行基线
> 日期：2026-07-13
> Owner：`ability_estimation` / `learning` schema
> 消费者：岗位 Agent、规划 Agent、学习档案、报告

## 1. 解决的问题

国考岗位进面分是行测与申论笔试总分。任何只掌握行测、只掌握申论，或把不同口径的单科分直接与岗位总分相减的实现都会制造假分差。因此总分不是页面临时相加的展示字段，而是共享学习大脑中的版本化派生事实。

正式不变式：

1. 原始成绩证据不可覆盖；纠错通过 `supersedes_evidence_id` 形成单链历史。
2. 每次估计固定输入证据集合、算法版本和 SHA-256 指纹。
3. `partial` 只能包含行测或申论其中一项；同时具备两项时必须生成 `complete` 总分区间。
4. 岗位分差和冲稳保只能读取 `complete` 估计，不能读取旧档案单科字段。
5. OCR、外部报告识别和 AI 推断在用户确认前不进入 `score_evidence`。
6. 冲突不强行选一条；扩大区间、降低置信度并记录冲突科目。

## 2. 数据分层

### 2.1 `learning.score_evidence`

保存不可变成绩事实：考试范围、来源类型、场景、行测、申论、是否限时、发生时间、确认状态、幂等命令和修订关系。只有 `user_confirmed` 或 `system_verified` 证据可以进入估计。

当前小程序开放本人结构化录入；受控模考、外部模考和正式成绩后续通过各自领域写入同一表，但不得绕过确认状态。

### 2.2 `learning.ability_estimate_versions`

保存派生版本：行测区间、申论区间、总分区间、置信度、输入证据 ID、证据摘要、算法版本、输入指纹和前序版本。版本只追加，不更新。

当前版本 `ability-estimate-v1` 使用来源可靠度、限时状态和确认方式形成确定性权重；区间同时包含来源基础误差与样本离散度。申论基础误差高于行测。分差达到冲突阈值时区间至少覆盖冲突跨度，置信度降为低。

新证据必须发生在最近 365 天内。估计版本保存明确的 `valid_until`：单科估计取该科最新证据时间加 365 天，完整估计取两科有效期中的较早者。系统不做无法回放的连续时间衰减；到期后统一进入 `stale`，在新证据产生新版本前禁止岗位分差和规划决策。

## 3. 写入与并发

- 所有本人录入使用 `Idempotency-Key`；相同键和相同输入返回同一证据，不同输入被拒绝。
- 幂等命令绑定首次写入时的考试年度；即使活跃国考数据年度已经切换，原命令重放仍按原年度返回，不能被当前 release 改写。
- 写入前锁定当前 learner，保证同一用户同一考试的并发证据按顺序进入估计，最新版本不会漏掉同时提交的另一科成绩。
- 原证据只能有一个直接后继，原估计也只能有一个直接后继，数据库唯一索引禁止分叉历史。
- 修订外键同时约束用户、考试类型和考试年度，数据库本身禁止跨用户或跨考试串接历史。
- 新估计与 `ability_estimate.changed` outbox 事件在同一事务提交。
- 数据库校验单科范围、两科齐全时总分必填且等于两科之和、完整/部分状态、区间三值完整性和区间顺序，不依赖应用代码兜底。

## 4. 可用性契约

| 状态 | 行测 | 申论 | 总分 | 岗位分差/冲稳保 |
|---|---:|---:|---:|---|
| `unavailable` | 无 | 无 | 无 | 禁止 |
| `partial` | 仅一科 | 仅一科 | 无 | 禁止，明确缺少科目 |
| `complete` | 区间 | 区间 | 两区间相加 | 允许，必须引用估计版本 |
| `stale` | 保留历史区间 | 保留历史区间 | 仅供回看 | 禁止，先补充新成绩 |

本人录入默认是低置信证据。`GET /api/v2/score-evidence` 返回当前考试年度的完整证据历史；活跃证据可通过带 `supersedesEvidenceId` 的新命令修订，旧记录继续可见但不可编辑。后续证据不会静默覆盖历史，而是生成新版本。旧 `learner.profiles.baseline_*` 缺少统一的发生时间、场景和确认契约，不自动提升为 canonical evidence；用户需要在新入口重新确认，避免迁移制造伪证据。

## 5. 旧链路退休边界

旧 `/api/v1/taskstream` 已修正为只有同时具备行测、申论时才计算总分差，并按两科之和计算；它仍不是新小程序的正式规划契约。新岗位组合和 `/api/v2/plans/today` 必须直接引用 `estimateVersionId`，不得回读 `baseline_xingce_score`、`baseline_shenlun_score` 或客户端上传的 `currentScore`。
