# 行测—申论双轨规划 Agent 契约

> 状态：双轨规划、国考申论目录、AI rubric 编译、成稿与结构化复盘、grounded review 及评阅确认已实现；行测结构化复盘/验证、行测/模考 owner writer 及申论重写、迁移仍是发布门禁
> 日期：2026-07-13
> Owner：`planning`
> 消费者：小程序今日页、岗位 Agent、解题 Agent、岸岸、报告

## 1. 问题与正式结论

旧 `taskstream` 虽然固定附带一条“申论概括题重写”，但它的能力校准、弱项选择、明日焦点、模考阻塞和主要解释均来自行测；申论时长只是行测分配后的剩余时间。它不是双轨规划。

正式规划必须把行测和申论作为同等候选任务来源：二者分别产生能力证据、待处理闭环、收益、紧迫度和成本，统一进入一个受时间、恢复日和模考约束的选择器。规划 Agent 不把申论写成固定每日占位，也不把剩余时间自动分给申论。

## 2. 规划输入

每个计划版本固定以下输入版本及指纹：

- 当前主目标岗位版本、岗位目标总分区间及有效期。
- 同一考试年度的行测、申论和总分能力估计版本；缺科、冲突和过期是显式状态。
- 行测模块证据：正确率、用时、错因、待复盘、即时验证、间隔复测和模考校准。
- 申论证据：材料包、题型、采点、结构、表达、格式、原稿、评阅、重写和新材料迁移版本。
- 当日可用时间、精力、压力与确认状态；常规休息日、模考日和近七天实际投入。
- 未完成任务不形成“任务债”；它只作为新计划的一条执行证据重新参与选择。

旧 `baseline_xingce_score`、`baseline_shenlun_score` 和客户端传入的单点分不能成为新计划的 canonical 输入。

当前行测结构化复盘、掌握状态与间隔验证尚无 canonical writer；规划合同必须返回 `objectiveClosure=unavailable`、`dueReflectionCount=null`、`dueVerificationCount=null` 和明确的 capability gap。在 writer、版本化状态与归属验收同时发布前，不生成 `objective_reflection` / `objective_verification` 可执行闭环，也不用 `0` 伪装“已清空”。

## 3. 双轨候选任务

| 轨道 | 阶段 | 候选任务 | 完成条件示例 |
|---|---|---|---|
| 行测 | `objective_baseline` | 受控摸底 | 完成固定题组并形成版本化结果 |
| 行测 | `objective_practice` | 模块针对训练 | 达到题数、用时与复盘门禁 |
| 行测 | `objective_reflection` | 高价值错题复盘 | 确认思路、错因候选与修复动作 |
| 行测 | `objective_verification` | 即时/间隔验证 | 独立变式题验证，不看原答案 |
| 申论 | `essay_material_reading` | 材料阅读与标注 | 完成稳定段落引用和分类标注 |
| 申论 | `essay_point_extraction` | 找点与归类 | 提交找点、材料锚点和归类依据 |
| 申论 | `essay_outlining` | 提纲与结构 | 提纲覆盖任务要求和评分维度 |
| 申论 | `essay_drafting` | 限时作答 | 保存材料、题目、思路、原稿和用时版本 |
| 申论 | `essay_review` | 查看证据化评阅 | 逐条确认用户原句、材料原句和评分点 |
| 申论 | `essay_rewrite` | 定向重写 | 解决指定 finding，且不引入新退步 |
| 申论 | `essay_transfer` | 新材料迁移 | 在未泄露答案的新材料中验证同一能力 |
| 模考 | `weekly_mock` | 周度标准校准 | 按完整考试合同交卷并查看复盘 |
| 恢复 | `recovery_review` | 轻量到期闭环 | 只做待复盘/待验证，不开新知识 |

申论没有可靠评阅证据时，先排基线链路；容量不足放下真实限时作答时，只拆出可验收的材料阅读，不压缩时间伪造基线。题目与完整材料已发布、但可审计评分点尚未发布时，也只能安排 `essay_material_reading`，禁止把材料段落冒充得分点进入成稿或评阅。

有评阅未重写时优先重写；重写完成但尚未迁移时排新材料验证。单篇重写成功只关闭本篇 finding，不直接提高长期申论能力。

## 4. 优先级与约束

候选任务保存可回放的优先级分解：

```text
priority =
  0.30 × 岗位总分收益
  + 0.30 × 能力信息/改善收益
  + 0.25 × 复盘与验证紧迫度
  + 0.15 × 时间适配度
  - 0.15 × 负荷惩罚
  + 近七天轨道失衡修正（最高 0.12）
```

规则不是固定分配比例：

1. 普通日且可用时间不少于 40 分钟时，在预算允许的组合中至少选择一项行测和一项申论，再按收益补第三项。
2. 时间不足时只选最高证据收益任务；近七天投入不足的轨道获得可审计平衡修正，而不是轮流硬切。
3. 常规恢复日不排新知识，只允许一项不超过 20 分钟的到期复盘、验证或申论重写。
4. 周度整卷模考是强约束任务，不再把行测模考日误写成普通双轨日；周计划负责保证申论在其他日期获得足够覆盖。
5. 缺少目标、能力或申论内容版本时输出明确采集/阻断状态，不虚构分差、收益或可执行任务。

## 5. 版本、解释与事件

`learning.daily_plan_versions` 保存用户、日期、目标版本、能力版本、容量版本、周偏好版本、申论题目/材料包/评分规程版本、执行水位、算法版本、指纹、总时长、解释和前序计划。`learning.daily_plan_tasks` 保存任务轨道、阶段、稳定工作项键、来源对象、完成合同、优先级分解、证据引用和执行入口。

`learning.task_execution_versions` 只追加保存进行中、完成和主动结束版本；完成必须提交合同要求的真实学习证据。`learning.essay_learning_artifact_versions` 只追加保存材料标注、要点提取、提纲、评阅确认和反思，强绑定用户、题目、材料、rubric 与 review/answer 版本。申论页通过原子组合命令在同一事务内写入不可变答案和结构化复盘、结算成稿计划任务并生成新计划，不留半状态；AI 评阅作为独立的异步计费步骤排队，不反向撤销已经成立的学习事实。执行水位变化进入下一计划指纹，终态工作项不会被重新包装为 `ready`。

公开规划执行接口只接受 `in_progress` 与 `abandoned`；`complete` 必须由学习领域 owner 在写入 canonical 证据的同一数据库事务中提交。申论 owner 验收必须精确匹配计划任务的 attempt、current answer、task、material、rubric、review 与完成合同；客户端不能使用任意历史证据自报完成。

只有 `completed`、`essay-grounding-v2`、引用验真通过、明确 `eligibleForLearning=true` 且具有执行指纹的当前评阅版本，才能进入申论弱项提取、评阅确认和后续重写规划。旧 v1 评阅、失败结果、被替代版本和未验真的模型输出均不得进入计划或岸岸上下文。

同一输入指纹重放返回同一计划；目标、能力、容量、到期闭环或任务执行变化生成新版本，并通过 `daily_plan.changed` outbox 通知今日页、岸岸和报告。页面上的每句“为什么今天做这个”必须能回到任务的优先级分解和证据引用。

## 6. 退休边界

- 旧 `rules_v1` taskstream 不再作为微信小程序正式计划 owner。
- “固定一条申论概括题 + 行测后剩余分钟”不得迁移到 v2。
- 旧 `/api/v2/feed/today` 可在切换期做展示适配，但不能再次计算或更改任务顺序与时长。
- 微信小程序正式读取 `/api/v2/plans/today`，原型数据必须与同一合同一致，并在发布构建中禁止使用。

## 7. 当前实现证据

- 认证接口 `GET /api/v2/plans/today` 已由 `planning` 领域提供；同一用户、日期和输入指纹重放同一个计划版本。
- `20260713_17` 是当前唯一 Alembic head；`20260713_11`–`15` 建立双轨规划、申论 canonical artifact、grounded review、成本/额度账本与跨设备评阅意图，`20260713_16` 将行测闭环未知计数改为 nullable 能力门禁，并以 attempt 的 task/material/rubric 完整元组强绑评阅意图；`20260713_17` 增加岸岸付费命令账本。
- 国考申论目录发布器从唯一 `task` knowledge chunk 与完整 material chunks 编译题目/材料版本；自动 rubric 链固定执行 generator 与独立 critic/reviser，再由确定性编译器校验逐字引用、Unicode 偏移、重复计分和总分守恒，只追加发布 `system_compiled + unverified`，不伪装成官方评分标准。
- 正常日规划器在不少于 40 分钟且两轨候选均可执行时应用 `xingce` + `essay` 双轨约束；恢复日、模考日、容量不足与证据缺失不套用正常日规则。
- 计划和任务保存目标收益、能力收益、遗忘紧迫度、时间适配、负荷扣减、轨道平衡修正、证据引用和完成合同，并在新版本提交时写入 `daily_plan.changed` outbox。
- 小程序今日页直接消费生成 OpenAPI 契约，展示正式轨道、阶段、分钟、任务原因、完成条件、执行状态、实际用时及遗漏原因；用户可确认分钟、精力、压力和时间把握，极端负荷触发恢复模式。
- 申论执行页已开放材料标注、要点提取、提纲、限时成稿、结构化复盘和评阅确认。成稿使用单事务组合命令同时固定答案、复盘、任务完成证据和新计划，并在同一事务登记不消耗额度的评阅意图；grounded review 使用独立 job、额度预留、最多两次模型调用、引用验真、成本账本与显式重评版本。页面可在任意登录设备从服务端恢复 `pending / waiting_quota / queued`，客户端本地草稿不是送审真相源。重写和迁移在各自 writer 完整前保持禁用，不用占位页冒充完成。
- 岸岸的全局解答上下文已纳入申论基线、有效能力区间、grounded review 摘要、结构化复盘和当日申论任务；单题 AI 训练估分不得直接改写岗位分差或正式申论能力估计。
