## 一、总体结论

UI 基础 **中上**：设计 token 体系完整、`state-view` 状态原语渗透率高（83%）、有平板响应式适配，整体不是"裸奔"项目。但存在明显的 **"两代设计系统并存、三套按钮体系并行"** 的结构性裂缝，以及 **98% 可点击元素没有触摸反馈** 这类直接影响体验手感的问题。

| 维度 | 评分 | 说明 |
|------|------|------|
| 设计 token 体系 | ★★★★☆ | token 定义完整，但页面端绕开 token 的硬编码仍多 |
| 组件化程度 | ★★★☆☆ | state-view 是范本；按钮、弹层、卡片失控 |
| 视觉一致性 | ★★★☆☆ | 33 种字号 / 27 种圆角 / 260 处硬编码颜色 |
| 交互反馈 | ★★☆☆☆ | 触摸反馈覆盖率仅 2%，弹层无统一实现 |
| 可用性（加载/错误/空态） | ★★★★☆ | 45/53 页有重试，83% 页面用 state-view |
| 无障碍与适配 | ★★☆☆☆ | 无深色模式、aria 覆盖 7 页、图片无 lazy-load |

## 二、做得好的地方（应保留发扬）

1. **设计 token 体系完整**：`design-system/tokens/index.wxss` 覆盖颜色/渐变/阴影/圆角/间距/字号/字体/布局断点，且通过 `app.wxss` 全局注入。
2. **state-view 原语是成功范本**：44/53 页（83%）、109 处使用，空态/加载态/错误态基本收敛。
3. **features 共享 page-shell 模式健康**：6 个领域 page-shell.wxss 被 29 个页面 @import，避免了跨页复制。
4. **错误重试覆盖率不错**：45/53 页面的 wxml 中有重试/重新加载入口；全部 53 页都配置了有意义的 `navigationBarTitleText`。
5. **有真正的响应式适配**：`design-system/responsive/index.wxss` 用 768px 断点 + px 单位覆盖平板，并注释明确了"一套产品，不是第二个平板 UI"的策略。
6. **主题资产规范**：安安形象资产（packages/anan-*）统一 webp + @2x + 版本目录管理，无超大图片打包。

## 三、问题清单（按严重程度）

### P0 — 直接影响用户体验

#### 1. 可点击元素几乎全无触摸反馈（覆盖率 2%）
- 全项目 103 处 `<view bindtap>`，仅 **2 处** 声明了 `hover-class`。
- 设计系统其实已提供 `.card--hover/.item--hover/.option--hover`（primitives/index.wxss:139-158），但页面没有接。
- **后果**：列表、卡片点击无按压态，用户得不到"点到了"的确认，手感发"死"。
- **建议**：给所有 bindtap 的卡片/列表项统一补 `hover-class`，工作量小、收益立竿见影。

#### 2. 三套按钮体系并行，视觉规格互相打架
| 体系 | 规格 | 使用 |
|------|------|------|
| `ui-button` 组件 | 组件级封装 | 16 页 / 36 处 |
| 全局 `.primary-button`（primitives） | 高 88rpx、渐变底、28rpx 字、700 粗 | 15 页 / 57 处 |
| 全局 `.s9-primary-button`（stage9） | 高 104rpx、纯色底、29rpx 字、800 粗 | 10 页 |
| 各页自创按钮类 | 约 30 种 | 15 个 wxss |
| 原生 `<button>` 直写 | — | 184 处 / 34 页 |

- 同一个主按钮，在 A 页是 88rpx 渐变、在 B 页是 104rpx 纯色 —— 用户能感知到"不是一个产品"。
- **建议**：以 `ui-button` 为唯一出口，把 `.primary-button` 和 `.s9-primary-button` 的样式收编为组件的 variant，全局类标记废弃。

#### 3. 弹层/浮层零共享，同一模式重复手写
- design-system 中**不存在任何** modal/popup/sheet 组件。
- `pages/practice/index.wxml`：手写 `.answer-sheet-mask` ×2 + `.pause-mask` + `.task-overlay` ×3。
- `pages/mock-exam/index.wxml`：手写 `.overlay-mask` ×5，与 practice 的五个场景（答题卡/草稿/暂停/工具/争议）一一对应、结构雷同。
- `pages/positions/index.wxml`、`pages/answer-ingestion/index.wxml`：又各自写了 `.sheet-mask`。
- 另有 51 次 `wx.showToast/showModal/showLoading/showActionSheet` 命令式调用散布在 19 个页面。
- **建议**：抽一个 `ui-sheet`/`ui-overlay` 原语（遮罩 + 圆角容器 + 关闭手势），practice 与 mock-exam 五个场景是第一批迁移对象。

### P1 — 设计系统裂缝

#### 4. 两代设计系统（stage9 vs primitives）并存且都全局生效
- `app.wxss` 同时引入 `primitives/index.wxss` 和 `stage9/screen.wxss`。
- s9 体系：21 页用 `s9-page/s9-card`，10 页用 s9 按钮；primitives 体系：15 页用 `.card/.primary-button`。
- 部分页面两套混用，页面骨架 padding 都不一致（`.page` 32rpx/28rpx vs `.s9-page` 28rpx/32rpx）。
- **建议**：明确一代为终态，另一代出迁移清单；短期至少停止新页面使用旧体系。

#### 5. 字号失控：33 种硬编码 rpx 字号
- token 只定义 4 档（48/30/28/22），页面实际用了 **33 种**（16–86rpx），重灾区是 18–25rpx 的小字（合计约 340 处）。
- **根因**：token 缺少 caption/small 档位的梯度，页面被迫各自发明。
- **建议**：token 补齐 18/20/21/22/24/25 小字阶梯（或直接收敛为 3 档），然后页面批量替换。

#### 6. 圆角失控：27 种硬编码值
- token 定义 4 档（40/32/26/14），实际用了 27 种；卡片圆角 32rpx 只有 3 处硬编码，更多的是 16/18/20/24 各自为政。
- **建议**：同字号，先扩/收敛 token 阶梯再批量归一。

#### 7. 主色 rgba 硬编码 8 种透明度
- `rgba(0,151,139, α)` 出现 40+ 次，α 取值 0.1/0.12/0.14/0.16/0.18/0.2/0.24/0.28 共 **8 档**，本质是"主色软背景"没有 token。
- **建议**：新增 `--color-primary-a10/a16/a24` 之类透明度 token（或 color-mix），替换全部硬编码。

#### 8. 硬编码颜色 260 处，其中直接重复 token 值的约 44 处
- `#ffffff` 37 处（= `--color-surface`）、`#00978b` 5 处（= `--color-primary`）、`#e7f7f3` 2 处（= `--color-primary-soft`）。
- 重灾区：`capture-import`（39 处）、`practice`（27 处）、`external-report`（20 处）、`features/positions/page-shell.wxss`（20 处）。
- 另有一条长尾的一次性"近色"（#eef2f0/#f0f3f2/#eef0f5…），是视觉噪声的来源。

#### 9. capture-import 自成一派的暗色主题
- `pages/capture-import/index.wxss` 使用 `#13211f` 深底 + `#5ed6c1/#78e4d1/#f0c36e/#16a88f` 等**全部不在 token 内**的颜色。
- 相机/扫描场景做暗色有其合理性，但颜色应作为 token 的语义化扩展（如 `--color-camera-*`），而不是游离值。

### P2 — 一致性与工程卫生

#### 10. 卡片类大爆炸：98 个根级 `*card*` 类 / 24 页
- 全局 `.card` 与 `.s9-card` 已存在，各页仍定义 98 个卡片类；`essay-task` 18 个、`practice` 13 个、`capture-import` 9 个。
- **建议**：卡片收敛为"容器用全局类 + 差异用修饰类"，essay-task/practice 优先治理。

#### 11. 巨型样式文件
- `features/positions/page-shell.wxss` 1250 行、`essay-task` 1208 行、`practice` 1083 行、`capture-import` 901 行、`today` 888 行。
- 超过千行的样式文件通常意味着页面该拆组件了。

#### 12. usingComponents 死声明 7 处
- 声明了 ui-button 但 wxml 没用：membership、login、privacy、capture-import、profile。
- 声明了 state-view 但没用：companion、profile/qualification。
- **建议**：清理，避免误导后续维护者。

#### 13. 空态仍有个别手写复制粘贴
- `onboarding/index.wxml` 与 `profile/qualification/index.wxml` 的 `.loading-state` 结构几乎逐行雷同；
- `retake`、`positions`（`.empty-inline` ×5）、`learning-profile`、`plan-history`、`report-center` 各自手写空态。
- **建议**：迁移到 state-view，把渗透率从 83% 推到 100%。

#### 14. 无障碍与平台能力缺失
- `aria-*/role` 仅 7 页出现；`lazy-load` 图片 0 页使用；无 darkmode 配置；tabBar 三个文本 tab 无图标（微信规范允许纯文本，但图标可显著提升辨识度）。
- 触控目标未发现小于 64rpx 的硬伤（主按钮 88–104rpx，健康）。
